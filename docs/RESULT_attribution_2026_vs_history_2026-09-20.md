## §5 块 C · 事前风险分解(**已更正**; 旧的「市场 β = 0」作废, E-0920-B)

### 5.0 更正: 美元中性不等于 β 中性

旧 §5 计算 `市场_i = W_i · ȳ(E)`, 因为执行器的 reshape 使 ΣW = 0, 于是每个时段都得到「市场 = 0.000」, 并据此写了「2026 一分钱都不是靠踩对大盘」「价格全部是截面选股」。**这只证明了美元中性, 没有证明 β 中性。** 一本严格美元中性的书, 只要做多的名字与做空的名字系统性地 β 不同, 仍然带着市场风险。作废该结论, 按事前 β 重算。

### 5.1 定义(先于本节任何数字, 写在 `at_beta.py` 文件头)

- **市场代理** m(E) = ȳ(E), 该锚成员表 ∩ 在世名字的等权 4h 收益(主口径, 也正是书被去均值所对的那个截面中心); 敏感性: BTCUSDT 的 4h 收益。

G0 的冻结标签里 **RG-ALT 与 RG-TREND 只到 2026-08-31**(它们要 BTC 30 天收益), **书的换手在认证窗之外不存在**。所以「当前档位组合」有两个口径, 两个都报, 都不是挑出来的:

- **JOINT8(预注册的八个条件量)**, 最后一个八项齐全的锚 = **2026-08-31T00:00Z**: DISP=高, FDISP=高, FLEVEL=中, BREADTH=中, VOL=中, ALT=低, UBAR=高, TURN=低。该八元组全轴 27 个锚 / 21 段, 中位 1 锚, 最长 2 锚, 完整配方窗 g −8.538 [−26.169, +6.711]。**这个 g 被同窗量 UBAR 污染(§6.1), 不可作状态读数。**
- **五个因果状态量(冻结后追加, 探索性; 就是能打档到轴末的那几个, 不是按结果挑的)**, 锚 = **2026-09-18T20:00Z**: **DISP=高, FDISP=中, FLEVEL=中, BREADTH=高, VOL=低**。
  - 该五元组全轴 158 锚 / 83 段, 游程中位 0.17 天、p90 0.67 天; 完整配方窗 g −0.19。
  - 同一五元组在 +7 / +30 / +90 天后仍成立: **4.0% / 5.4% / 3.7%** —— **精确的联合档位组合几乎不重现, 不承载信息**。
  - 按「与当前状态相同的档位个数」: 0 个 g −1.21(170 锚), 1 个 +0.04(1,230), 2 个 **+0.96**(2,442), 3 个 **+0.93**(2,072), 4 个 +0.75(876), 5 个全同 −0.19(158)。**没有单调关系**; 绝大多数历史锚落在 2–3 个相同的区间里, 那里的 g 就是全窗平均水平。

### 9.3 「2023 那种组合」在历史上多常见

八元口径下 2023H2 的众数组合(DISP=中, FDISP=高, FLEVEL=中, BREADTH=中, VOL=低, ALT=高, UBAR=中, TURN=中)只占 2023H2 已打档锚的 **1.1%**(六元口径 2.6%), 全轴 14 锚 / 12 段。**换句话说: 「2023 的状态」不是一个可以指认的状态量组合。** 那半年在七个 G0 状态量上并不特别; 特别的是**书自己的构成**(单腿 king、fund 席位被关)、**宇宙的大小**(196 名)与**成本基数**(换手 0.1158)。这三件事都不是 G0 状态量, 所以 G0 那七个标不出 2023, 正如它们标不出 2026-08(G0 原文结论)。

## §12 为什么原来的门没有抓到这个错, 以及装置 / 收据 / 复跑

### 12.1 为什么门没有抓到(逐字, 因为这是本次最该记住的东西)

**原来的门验的是「算术对不对」和「能不能复现」, 没有验「被拆解的那个量, 是不是它被假设成的那个东西」。**

具体地, 旧 §A 身上挂着这些绿灯, 而它们**每一个在错误模型下都照样是绿的**:

- `B4.A2_additive` / `B5.A2b_additive`(4e-11 / 2.8e-14): 只说「我定义的几项加起来等于我定义的总和」。**我用任何一组系数去拆任何一个向量, 这个门都过。**
- `additivity`、`group.sums_add_up`(1.7e-13): 同上, 恒等式自洽。
- `AT_CONTROL` 逐格复现已发表表(最差相对 3.4e-14): 验的是 **L1 已实现层**, 而腿层拆解**根本不进 L1**。控制复现再完美也碰不到这个错。
- `B7.paper_tracks_realised`(Pearson 0.963 / 0.923): 验的是纸面**总量**跟得上已实现总量。**总量是对的** —— 错的是把总量分成几份的那一刀。
- `B3.king_file_anchors_write_the_king_file`: 验了 kind-1 锚写的是 king 文件, 但**从没验过 kind-2 锚写的是什么**。
- 电池 20/20(基线绿 + 变异红): 变异检查用的是**我自己的**代数夹具(`legsplit.A2_is_exactly_additive` 等), 它们检验我的算术实现符合我的公式, **不检验我的公式符合生产者的代码**。

**共同的形状**: 每一个门的参照系都是**我自己的定义**, 没有一个门的参照系是**生产者的源码**。装置越自洽, 错得越稳。这与记忆里「用文本仪器去测行为性质」同族 —— 判别法是同一句: **「有没有一种输入, 使被测对象根本不是我以为的那个东西, 而我的断言仍然全绿?」** 这里答案是「有, 而且就是实际情况」。

**这次加的门是不同种类的**: `A0a` / `A0b` 把书**从分解式重建出来, 与生产者写出的目标逐位比对**(6,702 + 2,437 个锚, 0 例外)。它的参照系在装置之外。它先跑, 不过就 REFUSED、不产生输出文件。**一句可推广的验收线**: 凡是「把 X 拆成若干部分」的装置, 必须有一个门是「把部分装回去, 与 X 的**原始来源**逐位比对」, 而不是与装置自己算出的 X 比对。

**还有一条**: 生产者源码的行号与代码应当**抄进装置的 docstring**(本次 `at_legs2.py` 已照做)。旧版从 `P3.vec` 的键名 `kc` / `fc` 和 `combo_meta.w3_masked` **推断**了语义 —— 这正是错题集里「按文件名 / 目录名推断语义」(E-0825-H/G)的同一形状, 只不过这次推断的是**字段名**。
