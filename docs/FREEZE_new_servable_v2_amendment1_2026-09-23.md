# 冻结修订 1:§A3 收益通道状态由 float64 累积对数价改为稀疏界值表(数值等价,实现简化)

## 1. 依据(集成代理 pod2 只读实测,x0918r 全轴 4.1 亿格;收据须入库)

- 研究员收益 R(`corrected_combo_v1d/market/returns.npz`)在**非界值格**上等于 `float32(缓存 f16 ret5)`:两边都有值的 1.70 亿格,**0 格不同**。
- **界值格**(f16 裁剪到 ±0.30)共 960 个,R 取官方复原的原始收益。
- 单列两类:
  - R 有值而 f16 为 NaN:21,313 格。研究员用官方证据补了缺口。
  - R 为 NaN 而 f16 有值:约 119 万格。补洞格及其后一格、上市边界、不可得区间。

⇒ 冻结稿 §A3 的 `state/prices.npz`(float64 lp,约 50 MB)在数值上不必要。`rr = f32(ch0)`,界值格用 raw,ch0 为 NaN 的格保持 NaN,算出的 rr 与 lp 方案逐位相同。

## 2. 改动(取代 DESIGN §A3 生产改法第 2、3 条中的 lp 状态与迟到 bar 重算)

1. 新状态 `state/boundary_raw.npz`:稀疏表 (ts, 名, raw_f32),进 STATE_FILES 与 generation 签名,随 40 天窗滚动删旧。
2. **服务端**:
   - 摄入 bar 时若 `f16(clip(raw)) == BOUND16`(裁剪生效),把 raw = c/pc − 1 写入稀疏表,pc 为紧邻前一行收盘;
   - ch0 仍按"不跨缺口"规则摄入;
   - 消费者一律用 `rr = raw`(若在稀疏表中)否则 `f32(ch0)`;ch0 为 NaN ⇒ NaN。
3. **部署时历史行(≤ 09-19T00Z,40 天窗内)**:
   - ch0 取 x0918r,补洞格七通道 NaN;
   - 稀疏表写入窗内的界值格 raw;
   - **并写入窗内研究员用官方证据补的缺口格**(R 有值而 f16 为 NaN 的那 21,313 格中落在窗内者),使窗内历史与训练逐位一致。
4. **具名残差**:部署之后新出现的缺口,实盘拿不到补缺口的官方证据,与训练约定不同。按事件计数,写进首锚验收与月度报告;历史频率约 0.0125% 的格。
5. 迟到 bar:只影响该行本身的 ch0 与是否入稀疏表,不再有顺序重算。
