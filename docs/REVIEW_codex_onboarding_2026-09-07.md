### §5.2 控制组公平性 —— **OLD_MATCH 是我见过最扎实的匹配控制**
不看文档, 直接比训练收据: **3 折 25 个 epoch 的 `order_sha256` 两臂逐 epoch 完全相同**(202501 K=7 / 202601 K=13 / 202608 K=5, 全同)。这是**机器可验证**的逐步匹配证据, 而非声明。K = CONST42 best_epoch+1 ⇒ FULL 末轮 epoch 索引 = CONST 的 best 索引, epoch 数受控; 归一化沿用原 85% 切片不重估, 避免了一个明显混淆。
**★ 一处被低估的混淆(我的加注)**: OLD_MATCH 末轮 `train_loss` **系统性低于** FULL(2.073 vs 2.334 / **0.606 vs 1.631** / 2.756 vs 3.489)而样本外更差 —— 典型的重复训练过拟合签名。⇒ **`FULL − OLD_MATCH` 不是"新标签信息"的纯度量, 而是"新标签 vs 同预算重复旧数据"**, 其中含"避免重复退化"的价值。审查方在 RESULT 里写了这一句, 但未量化; 202601(K=13, loss 差 1.03)正是差值最大的折之一。**建议下一版加第三臂: OLD 窗但降步数至不过拟合。**

### §5.3 指标计算 —— **实现正确; 门的设计与本书形态不匹配**
实现侧无可挑剔: 拒绝覆盖冻结产物、借用函数前先钉源码 sha(`analyse_parity.py` sha 白名单)、逐个 `pred.npy` 对训练收据 sha、`assert m.sum()>=50`、门的布尔逻辑与预注册逐条对应。裁决算术我复核: FULL−CONST 三折均值 ΔP=+0.005477 ≥ +0.003 ✓、ΔS=+0.010828 ≥ 0 ✓、**但 202501 ΔP=−0.004512 < 0 违反每折非负** ⇒ STOP_PILOT **判得对**。
**★ 门的设计问题(归下一版, 不是本次执行的错)**: 本书是**截面**书(锚内排序+去均值), **CS rank-IC 才映射到书**; per-asset 时序 Pearson/Spearman 度量的是"分数能否预测该币自身的时序收益", 对去均值截面书不直接变现。**门却在 CS 全绿的情况下被一个不映射到书的指标否掉。** 更关键: **per-asset 项没有任何 CI**, 而 CS 项有自举 —— 一个点估计与一个区间估计放在同一个硬门里。

### §5.4 时间块推断 —— **这是全submission最脆弱的一环**
