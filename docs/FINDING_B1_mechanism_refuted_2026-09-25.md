# 发现:B1「先各自归一再混合」的机制**在组合层被否** —— 它实际上是一个**发布**臂,不是混合臂

**在跑任何引擎格之前用 CPU 侧控制抓到的。** 判据文件未动,本文**不出任何判词**。

## 1. 我原来的立论(设计 `891ebc7da` §2 B1)

**这条被实测否掉。**

## 2. 实测(NC 两个成员,基准组合,`scaled_diagnostic`)

| 量 | s42 | s2027 |
|---|---|---|
| `‖kc‖₁ / ‖fc‖₁` 中位数 | **1.0025** [q10 0.9210, q90 1.1405] | **1.0074** [q10 0.9418, q90 1.1716] |
| 混合后 L1 质量里 King 的**有效份额**中位数 | **0.5506** | **0.5518** |
| **名义份额** | 0.5500 | 0.5500 |

⇒ **有效混合比与名义混合比只差 0.06–0.18 个百分点。** 「名义 0.55/0.45 不是有效混合比」这句话是错的。

**我的推断错在哪(可定位):**

| 量 | 实测 |
|---|---|
| `kc` 每锚非零格数(中位数) | **256.0** |
| `fc` 每锚非零格数(中位数) | **256.0**(比值 1.000) |
| `kc` 每个非零格的平均 \|值\| | 0.002604 |
| `fc` 每个非零格的平均 \|值\| | 0.002567 |

两条腿在**格数**与**每格量级**上都几乎对称。
⇒ dlarch 的「保留率 King 34.8% / F10 58.1%」**分母不是 `kc`/`fc` 的格数, 也不是 L1 质量**,它量的是别的层的别的东西。
**我把另一层的一个百分数, 直接推成了 `‖kc‖₁` 的性质, 而没有去量 `‖kc‖₁`。**
这与在案的 `name_of_the_quantity_is_not_the_quantity_2026_09_24` 同族:**按名字取量, 不读消费它的那一行。**

## 3. B1 实际做了什么:删掉预检下限的咬合

B1 变体组合(装置 `fa_fuscombo.py --kernel combo_target_b1`)的实测:

| | 基准 | B1 |
|---|---|---|
| `raw gross` 中位数 | 0.5524 | **0.8491** |
| `gross < 0.4` 占比 | **0.1992**(s2027: 0.2323) | **0.0000** |
| `gross > 1.2` 占比 | 0.0000 | 0.0000 |
| 发布锚数(窗内 8,142 锚) | 6,520 | **8,142(全部)** |

**机制上这是必然的**:两个单位 L1 向量按 0.55/0.45 相加,L1 范数被夹在 `(0, 1]` 内,所以
**下限 0.4 几乎不可能再被触发,上限 1.2 也永远触不到**。

⇒ **B1 的书层效应几乎全部来自「预检门不再咬」, 而不是来自混合比的改变(后者只有 0.06 pp)。**
**若按「混合臂」去读它的结果, 就是把一个发布效应贴上混合的标签。**
