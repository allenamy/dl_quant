## §A 聚合合同(五条, 承重)

**类的陈述(E-0920-C)**: *任何聚合量都不得把「本窗不适用 / 无测量」编码成一个良性数值再与真实测量一起平均。* 与「未知不是零」「零测量也算通过」同族 —— 这是它们的**聚合版**。

下列五条是**合同**, 由 `bt_agg.py` 实现并强制, 适用于基线表装置持久化的**每一个**聚合块, 不是一张受影响量的清单。

- **A1 闭合人口**: 每个聚合块必须声明 `population.n` 与成员标识 `population.members`。**禁止在传入聚合器之前用推导式静默过滤成员** —— `agg([... for p in PP if f(p)])` 这种写法本身即违约, 因为被丢掉的成员不会出现在任何输出里。人口由调用点显式给出, 聚合器核对 `len(members) == population.n`。
- **A2 具名无测量子集**: 每个成员由调用点声明的 `applicability(member)` 分类器判定: 返回 `None` = 有测量; 返回**字符串** = 无测量, 该字符串即**原因名**。无测量成员进入 `no_measurement.by_reason[<原因名>]`(含成员 id 列表), **永不进入任何 mean / percentile**。
- **A3 两个数缺一即 REFUSE**: 每个块必须同时给出
  - `whole_population`: 全人口读数。无测量子集为空时它 `equals_measured = true` 并复制统计量; 非空时 `mean = null` + `refused_because` + `coverage = n_measured / n`。**全人口的均值在有成员无测量时不存在**, 装置必须说「不存在」而不是给一个数。
  - `measured`: 有测量子集的 `n_eff / mean / median / p05 / p95 / min / max`。
  任一侧缺失 ⇒ 抛 `AggRefusal`, 装置退出码非 0, 不落盘。
- **A4 每个落盘均值旁必须有它的有效样本数 —— 由结构扫描强制**: 落盘前对**整份输出文档**做一次递归扫描, 任何含 `mean` 键的 dict 必须同时含 `n_eff` 与 `population_n`; 违者 REFUSE 且不写文件。
  **这一条是本修订的类形状核心**: 它不认识 `never`, 不认识任何具体量; **明天任何人往输出里新加一个聚合块, 只要它没走合同就会被拦下。** 验收线就是这句话。
- **A5 禁止良性替换**: 分类为「有测量」的成员其值为 `None` ⇒ REFUSE(无解释的缺值不是一个类, 必须先具名); 分类为「无测量」的成员其值不是 `None` ⇒ REFUSE(分类器与数据互相矛盾, 先对账)。

### A-0 为什么不保留「旧口径」那个数作为对照
不保留。把 `0.0` 与真实亏损一起平均得到的 −21.97% 不是另一种口径, 它是**把无测量编码成良性数值**的产物; 在结果件里并列它会让读者以为那是一个可选的读法。它只出现在错题集 E-0920-C 与本文这两处, 作为**缺陷的量级**, 不作为读数。

## §B 窗口切片语义(显式裁定)

### B-1 问题
旧装置 `bt_p2_reading.py` 的 `withheld_mask(H="never")` 取 `t0 = min(t for t, _ in p["flatten"])` —— **整条路径**的首次日止损, 不限于报告窗。于是一次发生在**报告窗之前**的停机会被带进窗内: 对 seed 3/5/12/17, `t0` 早于 FULL_RECIPE 窗起点 ⇒ 窗内 6,948 个锚全部被扣住。这把**「报告窗」与「入场时点」混为一谈**。

### B-2 两种读法(各自具名, 都要报)
- **W-ENTRY(入场时点)**: 基准锚 = 入场时点。只有**发生在基准锚当时或之后**的日止损参与扣锚; 窗前的停机**不继承**。
- **W-CARRY(路径连续)**: 报告窗只是一条连续路径上的观察切片; 窗前开始且未恢复的停机**带入**窗内。旧装置实际算的就是这个(但没有声明过)。

### B-3 裁定: **主读数 = W-ENTRY**; W-CARRY 并列具名报出
理由**全部是结构性的**, 不引用任何待算的数字:

1. **两条停机规则必须用同一个时钟。** §4-4 的累计线在已发布的读数 P 里就是**入场指数化**的: `cum_k = navm1_k / navm0_base − 1`, 即 −25% 的计数器在基准处**归零**, 窗前的回撤不带入。若 §4-4 不带入而 §4-2 带入, 同一个读数里两条规则用了两个不同的起点 —— 这是装置内部的不一致, 是**关于现有装置的事实**, 不是偏好。
2. **配置里每一个基准的标签本身就是「起点」**: `run window start`、`FULL_RECIPE window start`、以及 17 个 `p_reading.starts` 季度**起点**。整张季度表问的就是「如果你从这天开始」; R6-03 的反例原话也是「2024-01-01 **起点**」。
3. **W-CARRY 会让季度起点表在 H = "never" 档退化**: 越晚的起点越可能继承一次很早的停机, 于是整窗无测量、读数恒为 0 —— 那不是关于「从该起点开始」的任何事实, 只是关于「这条路径更早以前发生过什么」的事实。
4. **W-CARRY 仍然有意义, 但只在 base = 路径起点时**: 那时它回答「一个从头跑到尾、一次也没被人工恢复的操作者」的下界。在该基准上两种读法**必须逐位相同** —— 装置对此下**断言**, 不同即 REFUSE(§B-4)。

### B-4 随裁定而来的断言(装置强制)
- **B4-a 同一性断言**: 在 `base_index == 0` 的基准上, W-ENTRY 与 W-CARRY 的每条路径 `end_return_P2` 必须逐位相同; 任一不同 ⇒ REFUSE。
- **B4-b** H = `sim`(不额外扣锚)下两种读法必须逐位相同(两者都不扣锚) ⇒ 同样断言。
- **B4-c** 在 W-ENTRY 下「无测量」仍可能发生(日止损恰好落在基准锚时刻 ⇒ H="never" 扣住整窗)。该类**不因主读数改变而取消**: 合同 §A 照常运行, 并在收据里给出该类为空/非空的普查。

### B-5 顺带纠正的口径(同族, 一并入合同)
- **平仓成本聚合的窗口**: 旧装置 `flatten_costs_per_path` 遍历**整条路径**, 而结果件 §0-1 把它当作「**在完整配方窗里**每条路径中位 8 次」引用 —— 又一次「报告窗 vs 路径」的混淆(这次不改变数值, 因为两窗恰好同中位, 但**巧合不使口径正确**)。新装置按**基准窗**报, 并同时给出整路径口径, 各自具名。
- **平仓成本的静默过滤**: 旧写法 `agg([... for p in PP if flatten_costs(p)], "v")` 把「本路径没有任何日止损」的成员**静默丢掉**(当前 32/32 都有事件, 所以它是**潜伏的**, 不是已发作的)。按 A1/A2 改为具名子集 `no_day_stop_event_in_this_path`。
