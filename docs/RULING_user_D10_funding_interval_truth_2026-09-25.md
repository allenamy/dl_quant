# 用户裁定:资金费结算间隔(D10)按真实情况取,训练与实盘一致

## 1. 用户原话(2026-09-25)

> 「资金费应该尽可能严格按照真实情况吧,这个有你设计模型,抓去数据来确定最佳方式,离线训练和线上推理最一致,最真实的。」

## 2. 裁定内容

1. **原则**:资金费特征(fund_ema 等)使用的每一次结算的**费率与结算间隔**,都以**交易所的真实记录**为准,不以本地账本推断为准。
2. **一致性**:离线训练与线上推理必须用**同一条规则、同一种数据表示**;任何一侧单独改动都不允许。
3. **授权范围**:由 lead 设计方案、抓取数据、实测确定最佳做法。这取代「D10 = snap_interval 间隔推断」这一冻结选择(冻结件 D10 条款)。
4. **不变**:新规则会改变特征 ⇒ King 与 F10 需按新特征重训;重训后的模型替换在役版本仍是书行为改动,**部署前照例交用户最后确认**;验证判据先于数字冻结。

## 3. 背景(lead 转述给用户的材料)

- 现行 NC:`iv = snap_interval(本地账本相邻结算的时间差)`,吸附到 1/2/4/8h、平局取大。账本漏记一次结算,或交易所改周期时出现 3h 这类间隔,都会把 iv 认错 2–4 倍(`RESULT_live_d10_known_error_2026-09-24.md`:生产账本 41 次可疑事件,2026 年 40 次;最大 TUSDT 09-06)。
- 研究员:官方间隔(拼接账本的归档间隔 + latest + 2026-08 官方归档),历史上与 NC 在约 0.23% 的事件上不同;经 3 天半衰期累积,2026 年格层差 21.8%。
- 书层影响在测:news2 第 2 步 arm (b)(只换资金费两列为研究员值,全链到书层),约 04:35Z。**本裁定不依赖该读数**;该读数只决定排期的紧迫程度。
