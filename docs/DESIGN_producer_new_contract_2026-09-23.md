### A3. D3 — 收益通道: float32 不裁剪; 历史部分用认证原始价格表, 09-19 之后实时取数回填

**研究员定义**(先写清楚它到底是什么, 设计由此而来)

1. 研究员的「原始价格表」`price_full_raw_x0918r.npy` 不是 K 线收盘价取对数, 而是由 f16 缓存收益重建的累积对数价格:
   - 构建装置 `baseline_tables_2026-09-19/devices_v3/bt_prices_full_x0918r.py`: 对缓存 ret5(`rp_lib.base_logs`, NaN ⇒ 0)取 log1p;
   - 对**裁剪到 ±0.30 的 bar**, 用官方收盘价比 `c_now/c_prev − 1` 复原(`rp_lib.apply_patch`、`classify`), 再加缺口补值, 然后逐行累加。
2. `build_combo_inputs.py` 的计算步骤:
   - L85–88: `rr = expm1(lp[t] − lp[t−1])`, 仅当两个端点都 seen, 结果为 float32;
   - L96–98: `close_observability` 与 `repair_intervals` 使补洞格及其后一格为 NaN, 并恢复官方证明的区间;
   - L102: 通道 0 换成 rr, 其余 6 个 f16 通道原样, 补洞格七通道置 NaN。
3. 研究员缓存的约定(rp_lib 文档串): 「ret5[ts] = close(ts)/close(ts−300) − 1, 然后裁剪、存 f16; **任一收盘缺失则 NaN**」。
4. 结论: 研究员的收益在未裁剪 bar 上就是 f16 精度的值。收据中与旧 f16 收益相差超过 1e-5 的只有 960 格(`BUILD_RECEIPT.json` `raw_feature_returns_changed_gt_1e5`), 即被复原的裁剪 bar。

**生产现状(两处不同)**
- (a) 通道 0 裁剪 ±0.30 存 f16, 所有消费者直接用它(L422–426, L173);
- (b) L413–427 的 `pc` 跨过缺失 bar 延续, 缺口后的第一根 bar 存的是跨两个区间的收益; 研究员此处为 NaN。

**生产改法(让研究员构建器在实时数据上跑出的数与服务端逐位相同)**
1. 摄入: ret5 只用紧邻的前一行收盘(前一行缺失 ⇒ NaN, 不跨缺口)。其余通道公式不变(`bars_to_channels` / `clipch`, 已证与 x0918r 逐位相同: `P5_DATA_PARITY.json` 450 名 36,288,000 格 0 差)。
2. 新状态(`state/prices.npz`, 进 generation 签名), 限取数名单列:
   - `lp` float64[T, N]: 逐行累积对数价, lp[t] = lp[t−1] + L_t;
     - L_t = log1p(raw_t) 若 f16(clip(raw_t)) 等于界值 BOUND16, 否则 log1p(float64(r16_t));
     - r16 NaN ⇒ L_t = 0;
     - raw_t = c_t / c_{t−1} − 1(float64, 同一对收盘)。这就是 `rp_lib.classify` 的 RESTORED 语义, 服务时每根 K 线都带收盘价, 所以不需要额外请求。
   - `seen` bool[T, N]: 该行有 K 线(与 log_qv 有限等价)。
   - 迟到补进的 bar(生产者只填 NaN 行): 从该行起对该列重算 lp。研究员的 cumsum 是逐次加法(np.cumsum 对 float64 是顺序累加), 所以重算方式是: 从 lp[t−1] 起顺序累加, 与研究员逐位同序。
3. 消费者一律改用 rr = where(seen[t] ∧ seen[t−1], float32(expm1(lp[t] − lp[t−1])), NaN), 不再用 f16 通道 0。消费者包括:
   - King 窗口统计与成员 n7 / v7;
   - F10 迷你管线(研究员 `patched_market.py` 的做法: 通道 0 换成 rr, 属 B 部分调用点);
   - rev24 腿(`combo_legs.py` L36 用 values40 通道 0 的 288 窗和);
   - 席位腿收益(研究员 `combo_legs.py` L60–63: 48 行 rr 和, ≥ 46 有限; 生产 L556–572 现用 f16);
   - btcv(研究员 L156: v7[BTC], 计数 ≥ 95%)。
4. 精度说明(**需要 lead 知悉的取舍**): 按上式, 服务端在未裁剪 bar 上保留 f16 精度, 与训练历史同一分布、同一实现。
   - 另一种做法是改用真实 float32 收益 c_t/c_{t−1} − 1。它更「干净」, 但训练历史只有 f16 精度, 两者在未裁剪 bar 上相对差最多约 2^-12(f16 半个 ulp), 逐位平价不可能。
   - 要让训练也用真实精度, 就得从 data.binance.vision 重拉 2022 年以来 829 名的 5m K 线收盘价, 这是另一个数据项目。
   - **本设计取前者**(与训练逐位同)。

### E4. 超预算预案(按 lead 定的优先级; 每项写明对训练 / 服务一致性的影响)
