# 1. 这个项目在做什么

每 4 小时，对 110 个加密永续合约打一次分，买分高的、卖空分低的，多空金额相等。赚的不是"市场涨跌"，而是"**这 110 个里谁相对跑赢谁相对跑输**"这个排序做得对不对。

三个数量级上的事实决定了全部设计：

| 事实 | 数值 | 后果 |
|---|---|---|
| 单次预测的信息量极低 | 横截面 rank-IC ≈ 0.03–0.06 | 单个锚点的判断几乎等于抛硬币（t≈0.5）；必须靠"下注次数"把优势累积出来 |
| 下注次数极多 | 110 币 × 6 次/天 × 365 天 ≈ 24 万次/年 | 微弱优势 × 巨大广度 = 可观的年化 t 值（≈23） |
| 每次下注的毛利很薄 | 单边毛 edge ~个位数 bps | 成本决定生死：taker 5bps 直接吃光，maker ≈0 才活 |

所以整套系统的目标函数不是"预测得多准"，而是 **max(毛 alpha − 换手 × 有效成本)**，且必须在**非平稳**（月度概念漂移）下保持稳定。

# 2. 数据与宇宙

## 2.1 面板

- **时间网格：** 小时级。当前面板 T ≈ 48,700 小时（约 5.5 年）。
- **横截面：** N = 140 个候选 symbol，其中 **110 个**在任意时刻是"成员"。
- **成员资格（point-in-time，无前视）：** 每个自然月月初，取过去 30 天滚动美元成交额 `DVOL30` 最大的 110 个币，该月内固定。
  `TOPN = 110`；`DVOL30 = rolling(QVOL, 24*30, min_periods=24*5).mean()`。
  **为什么按月固定：** 若每小时重排成员，成员进出本身会制造虚假的横截面收益（新进来的币往往刚涨过）。按月初的滚动均值定成员，且只用 ≤t 的数据，切断这条污染路径。

## 2.2 通道（DL 的输入特征）

`wide_dl_live.npz` 的 `CH` 张量，形状 `(T, N, C)`，**C = 32**：

```
funding_ema  mom_4h  mom_8h  mom_24h  mom_72h  mom_168h  rev_1h  rev_3h
rvol_24h  dvol_24h  rvol_72h  dvol_72h  beta_24h  beta_72h  lturnover_24h
illiq_72h  size_dvol  max_ret_24h  gtja_046  a101_044  ret_1h  ret_4h
ret_12h  ret_24h  rvol_6h  logqvol  xsr_rvol  xsr_ret24  xsr_fund
xsr_turn  xsr_mom72  betaadj_ret24
```

前 20 个是 wide_factory 的输出（第 4 节逐条讲）；后 12 个是补充的价量描述子与它们的横截面 rank 版本（`xsr_*` 前缀 = cross-sectional rank）。

**全部通道严格因果**：任一通道在时刻 t 的取值只用到 ≤t 的数据。这条是硬约束，不是习惯 —— 违反它会让所有回测数字失去意义。

# 3. 预测目标：Y 与 YR

这一节回答"残差到底是什么"。

## 3.1 原始目标 Y

```python
Y[t, i] = log(close[t+H, i]) - log(close[t, i])     # 前向 H 小时对数收益
HORIZONS = (1, 4, 24)                                # 主目标 H = 4
```

这是"币 i 从 t 到 t+4h 涨了多少"，**绝对**收益。

## 3.2 残差目标 YR（DL 真正的训练目标）

```python
BASELINE = ["funding_ema", "mom_24h", "mom_72h", "rev_1h",
            "rvol_24h", "size_dvol", "max_ret_24h", "beta_24h"]
YR = _xsec_residualize(Y, X_baseline, MEMBER)
```

`_xsec_residualize` 逐时间戳做三件事（只在该时刻的成员上）：

1. **横截面去均值**：`y = Y[t] − mean(Y[t])`
   去掉的是"整个市场这 4 小时涨了多少"。加密市场的共同因子极强（alt 对 BTC 的同期 beta 平均约 0.7），不去掉的话模型会把 80% 的容量花在预测大盘，而大盘方向我们既不赌也预测不了。
2. **基线因子也去均值并标准化**：`Xt = (X[t] − mean) / std`
   标准化这一步有具体原因（代码注释里写明）：ridge 会对所有列施加同样的收缩，若某列（`funding_ema`）尺度大、尾巴重，它会被**欠收缩**，于是残差里留下对它的载荷 —— 审计实测残留载荷 0.042。标准化是逐列可逆变换，所以"对标准化列正交"等价于"对原始列正交"。
3. **岭回归取残差**：`beta = (XtᵀXt + 1e-6·I)⁻¹ Xtᵀy`，`YR[t] = y − Xt·beta`

**所以 YR 的含义是：在时刻 t，把这 110 个币未来 4 小时的收益，扣掉市场平均、再扣掉这 8 个已知因子能线性解释的部分，剩下的那部分。**

## 3.3 为什么要这么做（关键设计意图）

DL 的成本远高于因子。如果让 DL 去拟合原始 Y，它大概率会重新发现"动量"、"低波溢价"这些已经被 8 个基线因子免费拿到的东西 —— 那不叫 alpha，那叫用 GPU 重新实现一个 rolling mean。

把目标换成 YR 之后，**DL 数学上不可能靠复述基线因子得分**：它的输出与那 8 个因子在训练集上正交。它拿到分数的唯一途径是找到基线因子之外的结构（条件化、非线性、跨资产关系）。这就是"incremental over [funding + zoo]"这个判据的由来 —— **我们只为增量付钱**。

## 3.4 非重叠标签集 CL

```python
CL[t] = True  every H hours    # H=4 时: t = 0, 4, 8, ...
CL = CL & MEMBER & isfinite(Y)
```

前向 4 小时收益在相邻小时上是重叠的（t 和 t+1 的标签共享 3 小时）。重叠标签会让评估的有效样本量虚高、显著性被高估。**评估一律在 CL 上做**（非重叠），训练可以用密集样本（更多梯度信号），但报数必须用 CL。

# 4. 因子腿逐条讲透

每个因子返回 `(值, 符号)`，符号 +1 表示"值越大预期未来收益越高"，−1 表示反向。

**读法说明：** 这些因子**不拟合任何东西**。它们是直接可计算的量（价格、成交额、资金费的某种变换），用法是**每个时刻在 110 个币之间排序**。"拟合残差"是第 3 节 DL 目标的构造方式，与因子本身的定义无关 —— 这两件事经常被混淆，第 6 节专门澄清。

## 4.1 funding_ema —— 拥挤反转（压舱石）

**原料：** 永续合约的资金费率。交易所每个结算周期（本宇宙 110 个币在 testnet 全部是 8 小时；live 上有 8h 与 4h 两种）让多空一方付钱给另一方，用来把合约价钉住现货价。多头拥挤 → 费率为正 → 多头付钱。

**构造：**
```python
span = max(2, round(24.0 / interval_h))          # 8h 币 → span=3, 4h 币 → span=6
ema  = ewm(rate * (8.0 / interval_h), span=span, adjust=False).mean()
```
两步都关键：
- **`rate × (8.0 / interval_h)`：单位归一。** 同样年化 55% 的拥挤度，8h 结算的币每期费率 0.05%，4h 的币每期只有 0.025%。不归一到 8 小时等效，4h 币会被系统性判成"不拥挤"。这条曾经是个真实 bug：错口径下这条腿七年回放呈假性亏损（rank-IC −0.008, t=−6.2），修正后 −0.0019（t=−1.49，不显著），配对差 +0.0062（t=+7.79）。
- **`span = 24 / interval_h`：所有币都是 24 小时等效 EMA。** 8h 币取 3 期、4h 币取 6 期，跨度都是一天。EMA 而非简单均值，是为了让最近的结算权重更高，同时保持平滑。

**符号 −1：** 做空高 funding、做多低（或负）funding。

**机制：** 高正 funding 意味着一群人加着杠杆做多、且**每 8 小时还在为此付费**。这个群体结构脆弱：价格稍回落 → 杠杆多头被强平 → 强平即市价卖出 → 更跌 → 更多强平。所以高 funding 不是看涨信号，是"多头结构已经不稳"的读数。负 funding 对称（空头拥挤 → 做多）。

**为什么它是压舱石：** 资金费 8 小时才变一次，再经 24 小时 EMA 平滑，**排名变化极慢** → 换手低 → 成本余量大（实测盈亏平衡有效成本 18.8 bps/side，是全部因子里最高的）。它不是赚最多的腿，是最扛成本的腿。

**风险控制的一个细节：** 用 z-score 加权时，极端行情会把仓位吸到单个币上（FTX 崩盘日某币 −18σ，单名权重冲到 0.49，等于半本书压一个名字）。改成 **rank 加权**后单名权重上界自然落到 0.049（见第 7 节）。

## 4.2 动量族 mom_{4,8,24,72,168}h

```python
mom_nh = log(close[t]) − log(close[t−n])          # 符号 +1
```
过去 n 小时的对数收益。符号 +1 = 买涨得多的（横截面动量）。5 个跨度从 4 小时到 1 周，让模型/合成层自己决定哪个尺度有效。

**机制：** 资金流入有惯性；指数纳入、叙事轮动等事件的影响持续数天。横截面动量是跨资产类别最稳健的经典因子之一。

## 4.3 短期反转 rev_1h / rev_3h

```python
rev_1h = −(log(close[t]) − log(close[t−1]))       # 符号 +1
rev_3h = −(log(close[t]) − log(close[t−3]))
```
注意负号已经在定义里：**买过去 1/3 小时跌得多的**。

**机制：** 与动量相反的时间尺度。小时级的独立暴跌通常不是基本面，而是一次性流动性事件（大额市价单、强平链），价格被打过头（接盘方要求折价），冲击结束后做市商把它拉回公允值。这是"短期均值回归"，与动量在不同尺度上共存不矛盾。

## 4.4 波动率族 rvol / dvol

```python
rvol_nh = rolling_std(ret, n)                      # n ∈ {24, 72}, 符号 −1
dvol_nh = rolling_std(min(ret, 0), n)              # 下行半波动, 符号 −1
```
**符号 −1 = 做多低波动的币**（低波异象 / low-vol premium）。

**机制：** 高波动资产吸引赌性资金（追求彩票式回报），被系统性高估；低波资产被冷落，风险调整后收益反而更好。`dvol` 只统计下跌方向的波动，区分"上涨造成的波动"（无害）与"下跌造成的波动"（恐慌）。

## 4.5 市场 beta 族 beta_{24,72}h

```python
market = nanmean(ret, axis=1)                      # 等权市场收益（110 币平均）
beta_nh = rolling_cov(ret_i, market, n) / rolling_var(market, n)     # 符号 −1
```
**符号 −1 = 做多低 beta 的币**（"betting against beta"，BAB）。

**机制：** 受杠杆限制的投资者用高 beta 资产替代杠杆，把高 beta 买贵了。做多低 beta、做空高 beta 能收割这个溢价。注意 `market` 用**等权平均**而非 BTC —— 因为 symbol 是按字母序排的，代码里明确注释了不能假设 BTC 在第 0 位。

## 4.6 流动性族 lturnover_24h / illiq_72h

```python
lturnover_24h = log(rolling_mean(QVOL, 24))                          # 符号 −1
illiq_72h     = rolling_mean(|ret| / QVOL, 72)                       # Amihud, 符号 +1
```
- **换手（−1）：** 做多低换手的。高换手往往是投机狂热的信号，随后回落。
- **非流动性（+1）：** Amihud 指标衡量"单位成交额能推动多少价格"。**做多流动性差的币** —— 因为持有它们要承担无法快速退出的风险，市场为此支付溢价。

**注意这条腿与执行的张力：** 非流动性溢价是真的，但我们自己也要在这些币上成交。这就是为什么合成层要做单名封顶（第 7 节），以及为什么执行侧的滑点测量必须分层。

## 4.7 规模 size_dvol

```python
size_dvol = −log(DVOL30)                           # 符号 +1
```
`DVOL30` 是 30 天滚动美元成交额，用它做"市值"的代理（加密市场的流通市值口径混乱，成交额更可靠）。取负号后符号 +1，实际含义是**做多小盘**（small-size premium）。

**机制：** 经典规模因子。小盘的信息覆盖少、定价效率低，且承担更高的流动性与生存风险，长期有正的风险补偿。

## 4.8 彩票 max_ret_24h

```python
max_ret_24h = rolling_max(ret, 24)                 # 符号 −1
```
**做空过去 24 小时内出现过极端单小时涨幅的币。**

**机制：** MAX 效应。散户偏好"可能一夜翻倍"的资产（彩票偏好），把刚刚暴涨过的币买到溢价，随后回落。这是行为金融里最稳健的异象之一。

## 4.9 alpha 库幸存者 gtja_046 / a101_044

```python
gtja_046 = (MA3 + MA6 + MA12 + MA24) / (4 × close)                   # 符号 +1
a101_044 = −rolling_corr(high, rank_xsec(volume), 5)                 # 符号 +1
```
这两条来自公开 alpha 库（国泰君安 191 因子、WorldQuant 101 因子）的批量扫描，是通过我们的显著性与持久性筛选后的幸存者。

- **gtja_046：** 多个均线的平均相对当前价的位置。价格低于自身多尺度均线 → 值大 → 买。本质是多尺度均值回归。
- **a101_044：** 当日最高价与"成交量横截面排名"的 5 日滚动相关，取负。捕捉"放量冲高"的形态并反向操作。

**为什么保留它们：** 它们不像前面的因子那样有教科书级的机制叙事，但通过了同一套门槛（增量 IC、跨年持久性、成本后为正）。**保留但标注机制较弱**，在权重上不给它们独立席位（它们只作为 DL 的输入通道，不单独成腿）。

# 5. DL（king）：输入、架构、损失、训练、评估


## 5.1 输入

**张量形状：`x = (B, N, W, C)`**
- `B` = batch 内的预测小时数（默认 `batch_hours=16`）
- `N` = 110（成员）
- **`W` = 168** —— 回看窗口 168 小时 = **7 天** - `C` = 32 通道（第 2.2 节）

即：每次预测，模型看到 110 个币各自过去 7 天、每小时 32 个特征的完整序列。

**掩码：** `mask = (B, N)`，标记该小时该币是否为成员且数据有效。非成员在注意力与损失中都被屏蔽。

**标准化：** 逐通道的 `mu`/`sd` 在**训练集的成员小时**上计算，验证/测试沿用训练集的统计量。`sd` 下限 clip 到 1e-6。这一点很重要：用全样本统计量标准化会泄漏未来分布信息。

## 5.2 架构

```
x (B,N,W,C)
  └─ reshape → (B·N, W, C)                     每个币独立、权重共享
      └─ 输入投影 C → d
      └─ Conformer × 2 blocks                  d=64, n_heads=2, kernel=15, dropout=0.2
          （每 block = 自注意力 + 深度可分离因果卷积 + 前馈）
      └─ 取最后一个时间步 → (B·N, d)
  └─ reshape → (B, N, d)                       每币一个 embedding
  └─ [可选] Cross-Asset Attention × n_xattn     4 头, 成员掩码, 同一时刻的 110 个币互相看
  └─ 输出头（二选一）
       ├─ K 个正交因子头: 6 × [Linear(d,d) → GELU → Dropout → Linear(d,1)] → (B,N,6)
       └─ QIM 头: 25 分位单调分位函数 → (B,N,25) → [隐含均值, q50] → (B,N,2)
```

**设计要点：**

- **权重共享的时序主干。** 110 个币共用同一套 Conformer 参数。这是把 params:sample 从单资产时代的 18:1 压到 ~1:1000 的核心杠杆 —— 在 R² < 1% 的信噪比下，容量必须匹配信号，pooling 是唯一能同时提高容量利用率和降低过拟合的手段。币的身份不进主干（主干是 asset-agnostic），需要区分时通过下游的 asset-id embedding 注入。
- **因果性。** Conformer 的卷积是因果的（只看过去），注意力在时间轴上加因果掩码。取最后一个 token 而非 pooling，是因为预测时刻的状态最相关（历史实验中 mean-pooling 会稀释近端信息）。
- **跨资产注意力（可选）。** 在同一预测时刻，让 110 个币的 embedding 互相看。机制上它能表达"BTC 刚跳水 → 高 beta 的 alt 会跟随"这类关系。实测在宽宇宙（N=110）上贡献显著（+0.031 增量 IC），在窄宇宙（14 币）上曾经是负贡献 —— 宽度是它生效的前提。
- **K=6 正交因子头。** 一个主干输出 6 个候选因子分数，训练时加正交惩罚（`lam_orth=1.0`）让它们互不重复。这是"一次训练挖多个因子"的设计，而非集成。
- **QIM 头（另一条臂）。** 输出 25 个单调分位数（通过累积 softplus 保证单调），交易时用**分位隐含均值**（对 τ 做梯形积分）而非中位数 —— 在肥尾分布下，隐含均值是比 q50 更稳健的中心估计。实测这条臂领先约 2 倍。

## 5.3 损失函数

主损失的设计

```
L = 0.30 × Huber(q50, r)  +  0.70 × LambdaRankIC(q50, r)  +  0.10 × Pinball(quantiles, r)
    (+ lam_orth × 正交惩罚,  lam_orth=1.0)
    (+ pred_smooth_lambda × 预测平滑惩罚,  默认 0)
```
其中 `r` 就是第 3 节的横截面残差目标。三项各司其职：

- **LambdaRankIC（权重 0.70，主项）**
  逐横截面，对所有满足 `target_i > target_j` 的有序对：
  ```
  w_ij = 12·|rank_j − rank_i|·|target_i − target_j| / (n·(n²−1))     ← detached
  l_ij = w_ij · log₂(1 + exp(−σ·(s_i − s_j)))
  ```
  **为什么用它：** 它是 `(1 − Spearman rank-IC)` 的**上界** —— 最小化它就是在直接最小化我们的 headline 交易指标。而且它是**秩不变**的：加密的肥尾会让 Pearson-IC 的梯度被少数极端样本主导，秩形式对此免疫。权重项用 detached 的秩（LambdaLoss 惯例），梯度只从 pairwise logistic 流回，避免秩计算的不可导问题。
- **Huber（权重 0.30）**
  对残差幅度做校准。**它的第二个作用更重要：提供稠密的梯度以对抗 σ 塌缩** —— 纯排序损失对预测的整体尺度不敏感，模型可以把所有预测压到接近 0 仍然排序正确，那样输出就没有可用的幅度信息了。用 Huber 而非 L2 是有血泪教训的：L2 类主损失在这个信噪比下会直接把 σ 压塌。
- **Pinball（权重 0.10）**
  多分位（q10/q50/q90 或 QIM 的 25 分位）的分位损失，给出肥尾稳健的"信心 σ"，供仓位加权参考。
- **一个关键的协同性质：** Huber 与排序项看的是**同一个残差目标**，所以它们的梯度共线 —— 不存在"排序与幅度互相拉扯"的问题，不需要梯度手术。

**训练配置：** `lr=6e-4`、`wd=0.01`、`max_epochs=20`、`patience=4`、`seed=42`、`batch_hours=16`。

## 5.4 训练与验证切分

```
walk-forward year folds:
  expanding train  →  val (30 天，从 train 尾部切出)  →  embargo 8 天  →  test
  test_frac = 0.45, n_folds = 3
```
**embargo 8 天**的长度不是随手取的：它必须 ≥ 回看窗口天数（168h = 7 天）+ 预测跨度（4h），否则测试集的输入窗口会与训练集的标签在时间上重叠。

**σ-gate（保存 checkpoint 的硬条件）：** 只有当 `σ_pred / σ_target ≥ 0.02` 时才允许保存 best checkpoint。这条来自一个真实事故：某通道的初始化噪声曾产生"高 IC 但已塌缩"的假冠军 —— IC 看着漂亮，但预测方差接近 0，实际不可交易。

**kill gate（可选，预注册）：** fold-0 在第 8 个 epoch 若增量 IC < 0.003 则直接终止，节省算力。这是预注册的，不能事后调。

## 5.5 评估指标

| 指标 | 定义 | 角色 |
|---|---|---|
| **横截面 rank-IC** | 每个锚点，110 个币的预测分与实现残差的 Spearman 相关，再对锚点取均值 | **headline**。long-short 组合的直接对应量 |
| **增量 IC (inc_ic)** | 在 [funding + zoo] 基线之上的增量 —— 由于目标已是残差，模型的 IC 天然就是增量 | 因子录用的主判据 |
| **IC-IR** | mean(IC) / std(IC)，按锚点 | 稳定性 |
| **per-asset Pearson** | 每个币各算时序 Pearson 再平均 | 诊断用。**注意它衡量的是"市场择时"能力，不是横截面能力** —— long-short 策略的门必须用 rank-IC，两者不可混用 |
| **σ_pred / σ_target** | 预测标准差 / 目标标准差 | 塌缩守卫，硬门 ≥0.02 |
| **持久性** | 逐年、逐 regime 的 IC 符号一致性 | 防止"某一年的特例" |
| **净成本 Sharpe** | 扣掉换手 × 有效成本后的组合 Sharpe | 最终判据 |

**评估纪律：**
- 一律在 **CL（非重叠标签集）** 上报数。
- **同时报 Pearson 与 Spearman**，两者背离是危险信号，必须诊断。
- **β 的绝对水平不是质量指标。** 代数上 `β = IC × (σ_y/σ_ŷ)` —— 把预测乘以常数 c，IC 完全不变而 β 变成 β/c。所以 β=3 和 β=1 常常是同一个模型差一个标量。β 的合法用途只有两个：(a) 塌缩监视（但真守卫是 σ 比值），(b) **跨 regime 的稳定性**（β 逐月乱摆说明分布在漂，一次全局 rescale 修不了）。**看 β 的方差，不看它的均值。** 部署需要真实 bps 时，用事后校准层（在验证窗上做 isotonic 或线性 rescale，IC 不变），不要把 β 训进模型。

# 6. "拟合残差"这件事的完整链条

这是最容易混淆的一点，单独讲清楚。

## 6.1 因子腿不拟合任何东西

`funding_ema` 是一个**直接计算**出来的数：拿资金费率、做单位归一、做 24 小时等效 EMA。它不是回归的产物，没有拟合目标，没有训练过程。它的用法是：**在每个时刻把 110 个币按这个数排序，做空排名高的、做多排名低的**（符号 −1）。

同理，`size_dvol` 就是 `−log(成交额)`，`mom_24h` 就是 24 小时收益。**这些量本身与"拟合"无关。**

## 6.2 "残差"只出现在 DL 的目标构造里

真正涉及残差的只有一处：**DL 的训练目标 YR**。

```
Y   = 未来 4 小时的原始对数收益
      ↓  逐时刻横截面去均值（扣掉市场）
      ↓  对 8 个基线因子做岭回归取残差
YR  = 扣掉市场、扣掉 8 个已知因子之后，剩下的那部分未来收益
```

**DL 拟合的是 YR，不是 Y。** 8 个基线因子里包含 `funding_ema`，所以 DL 的输出在训练集上与 funding 因子正交 —— 这正是我们想要的：**DL 拿到的每一分 IC 都是 funding 和 zoo 因子给不了的那部分。**

## 6.3 三者的关系

| | 拟合什么 | 目标是什么 | 与其他因子的关系 |
|---|---|---|---|
| **funding 腿** | 不拟合 | 无 | 独立成腿，直接拿 0.30 权重 |
| **size 腿** | 不拟合 | 无 | 独立成腿，直接拿 0.30 权重 |
| **DL (king)** | 拟合 | **YR4** = 扣掉市场 + 8 基线因子后的 4h 残差 | 训练集上与基线因子正交 |
| **s2** | 拟合 | 同为残差目标的另一模型/另一代 | 与 king 相关但不同，作为分散化的小权重腿 |

**一句话：因子是"直接算出来的排序信号"；DL 是"学出来的、且被强制只学基线之外那部分的排序信号"。合成时它们是四个并列的信号源，不是层级关系。**

## 6.4 一个已知的口径注意事项

`funding_ema` 的单位归一修复（`rate × 8/interval_h`）发生在 2026-07-25，而当前冻结的 DL 权重训练于 2026-07-11 的面板 —— **即训练时用的是未归一口径**。因此系统里**刻意维持两套口径**：

- **因子腿**（funding 直接作为一条腿）：用**已修正**口径；
- **DL 输入通道**（`funding_ema` / `xsr_fund` 作为 32 通道之一）：保持 **as-trained 未归一**口径。

理由：给冻结模型换输入分布，等同于给它换权重。要切到修正口径必须重训。这两套口径都有守卫断言保护（每份面板断言它"应有"的口径，两条带之间是禁区），且期望值绑定在冻结权重的哈希上 —— 重训会让断言变红，强制显式重新确认。

# 7. 从预测分数到仓位：权重是怎么定的

这一节回答"position 权重如何确定"和"为什么不能直接用 DL 分数"。

## 7.1 四条腿与它们的权重

```python
DEFAULT_WEIGHTS = {"king": 0.30, "s2": 0.10, "funding": 0.30, "size": 0.30}
DEFAULT_SIGNS   = {"king": +1,   "s2": +1,   "funding": -1,   "size": +1}
```

| 腿 | 是什么 | 权重 | 节奏 |
|---|---|---|---|
| **king** | 主 DL 模型对 **YR4**（4 小时残差）的预测 | 0.30 | 4 小时 |
| **s2** | 另一个 DL 臂（`wideA_s2_y24_c1`）：目标 **YR24**（24 小时残差）、39 通道（比 king 多 7 个 funding/OI/positioning 指标通道）、`lam_orth=0` + xattn | 0.10 | 24 小时 |
| **funding** | funding_ema 因子 | 0.30 | 8 小时 |
| **size** | size_dvol 因子 | 0.30 | 24 小时 |

**关于 s2 的权重为什么只有 0.10（有明确的验收史）：** 它的五门验收判词是 **CONDITIONAL REJECT（不以原样进书）** —— 过了 4 门但 FAIL 决定性的"书级边际"门。
- **过的门：** 对 king 正交的增量 IC **+0.0277**（CI [0.020, 0.035]，逐 fold 2024/2025/2026 全正）；与 king 的预测相关仅 **0.24**（24h vs 4h 是实质不同的下注）；动态占比 0.944（增量来自择时而非静态倾斜）；净成本 Sharpe 3.45@5bps、盈亏平衡 16.8bps（24h 慢腿，日换手约 king 的 1/6）。
- **FAIL 的门：** 权重扫描显示**任何权重都不显著抬高整本书**（w=0.1 时 −0.01，w=0.3 时 −0.84）。原因是 king 太强（paper Sharpe 12–20）而 s2 单独只有 3.4–4.9，**一条弱 4 倍的低相关腿也抬不动书** —— 这是"弱因子进书 = 负贡献"的又一次验证。
- **它仍拿 0.10 的理由：** 判词同时写明，若走**多 sleeve 部署**（而非信号混合），s2 有窄价值 —— 低相关（0.20）、换手慢、成本便宜、增加容量。所以它以**小权重慢 sleeve** 的身份进书，取的是分散化与容量，不是 alpha 强度。**这也是为什么绝不能把 s2 混进 king 的信号里**（那是稀释），只能作为独立腿。
- **两个前置条件已登记：** 那 7 个 metrics 通道有结算/发布延迟，+0.0277 的增量只在这些通道使用 ≤t 已发布值时才成立（泄漏审计已做，判定 LEAKAGE-CLEAN，残余是未文档化的 5 分钟内发布延迟，对 YR24 可忽略）；以及 32 通道消融。

**权重是怎么定的：** 不是优化出来的，是**按分散化与稳健性设定并经全历史回放验证的**。理由：
- 在 IC ≈ 0.03–0.06 的信噪比下，权重优化（如均值-方差）会把估计误差放大成配置误差 —— 用噪声估出来的协方差去优化，得到的是过拟合的权重。
- 四条腿的相关性低（DL 抓 4 小时流动性事件，funding 抓天级仓位结构，size 抓月级风格），近似等权本身就是稳健解。
- king 拿 0.30 而不是更多，是因为它换手最高、衰减最快；funding/size 慢腿的成本余量大，多给它们权重能提高净收益。
- s2 只有 0.10：它与 king 相关度高，边际分散化有限，小权重取其残余分散。
- **有独立证据支持 king 的份额**：挑战者轨实测，把权重从其他腿挪向 king 会提高样本外 IC（+61%，132 锚点配对，t=6.83）—— 但那是 IC 口径，净成本口径下慢腿的价值不体现在 IC 上。当前配置是两者的折中。

## 7.2 合成流程（逐步）

```python
# 第 1 步：每条腿各自做横截面归一化
funding → _rank_centered(x)      # 秩映射到 [−1, +1]，零均值，天然有界
其他腿  → _z(x)                  # z-score
再乘以各自的符号 sign

# 第 2 步：每条腿各自 L1 归一化 → 每条腿都是"单位总敞口"的子组合
leg_k = leg_k / sum(|leg_k|)

# 第 3 步：加权求和
combo = Σ_k  w_k × leg_k

# 第 4 步：整形（shape_position）
mag = [可选] isotonic 校准(combo)          # 把分数映射到实际 bps 量级
mag = clip(mag, 1%分位, 99%分位)           # 单名尾部截断
pos = mag − mean(mag)                      # 市场中性：最后一步减均值
```

**每一步的必要性：**

- **rank vs z-score（第 1 步）。** 生产口径（CANONICAL）对 funding 用 **rank**。原因前面提过：z-score 在极端行情下会把单名权重推到 0.49，rank 天然把它限制在 ~1/N。代价是丢掉了"这个币比第二名极端多少"的信息 —— 但在这个信噪比下，那点额外信息不值得承担集中度风险。全历史回放：rank + cap 口径平均净 Sharpe 12.21。
- **逐腿 L1 归一（第 2 步）。** 保证"权重 0.30"真的意味着"30% 的资金份额"。如果不先归一，某条腿的原始尺度大，它的实际份额会远超名义权重。
- **99 百分位截断（第 4 步）。** 组合后仍可能有单名偏大，硬截断作为最后一道集中度保险。
- **demean 放在最后（第 4 步末）。** 顺序很关键：先截断再去均值，能保证最终 intent 的净敞口精确为 0（实测 −0.000%）。反过来做，截断会重新引入净敞口。

## 7.3 为什么不能直接用 DL 的预测分数当仓位

这是本节的核心问题，有四个独立的理由：

**理由 1：分数的尺度没有意义。**
代数上 `β = IC × (σ_y / σ_ŷ)`。把所有预测乘以常数 c：IC 完全不变，β 变成 β/c。**也就是说预测分数的绝对大小是可以被任意缩放的，它不携带"该下多大注"的信息** —— 除非专门做过校准。直接拿分数当仓位，等于让一个任意的标量决定杠杆。

**理由 2：分数的分布是肥尾的，直接用会导致致命集中。**
模型偶尔会对某个币给出极端分数。若仓位正比于分数，一次极端输出就是一次巨额单名押注。而在 IC=0.05 的世界里，**任何单笔押注的期望收益都不足以补偿集中度风险**。rank 化 + 封顶把这个风险从结构上消除。

**理由 3：分数在不同 regime 下的尺度会漂移。**
预测的 σ 逐月变化（这正是 β 逐月乱摆的原因）。用分数直接定仓位，等于让杠杆随模型的"自信程度"漂移 —— 而模型的自信程度与它的实际准确度并不同步。rank 化使每个锚点的总敞口恒定，把"信号强度"与"仓位大小"解耦。

**理由 4：多腿合成需要可比的尺度。**
king 的分数是残差收益量纲，funding_ema 是费率量纲，size_dvol 是对数成交额量纲。**它们的原始尺度完全不可比**，不做同一化就没法加权求和。rank / z-score 提供了这个共同尺度。

**那么"最佳的仓位定义思路"是什么？** 按证据，是这条链：

```
预测分数（只信它的【序】，不信它的【值】）
  → 横截面 rank 化（有界、尺度无关、regime 稳定）
  → 按腿加权合成（权重表达先验的分散化，不表达对某腿的信心大小）
  → 尾部封顶（集中度硬保险）
  → 去均值（市场中性）
  → [部署时] 事后校准层把无量纲分数映射到真实 bps，用于净成本门与 Kelly 式规模
```

**关键分工：** 模型负责**排序**（信息），合成层负责**风险**（集中度、中性、尺度），校准层负责**量纲**（bps）。三件事分开做，任何一件出问题都不污染另外两件。把它们混在一起（"让模型直接输出仓位"）会导致模型的一个尺度问题同时变成风险问题。

## 7.4 换手与 netting

四条腿的自然节奏不同（king 4h / funding 8h / s2 24h / size 24h）。执行时统一到 king 的 4 小时网格上，每个锚点计算**净目标仓位**，只交易差额：

```
gross_turn  = 各腿独立交易的换手（反事实基准）
net_turn    = 合成后实际净书的换手
hedge_rate  = 1 − net/gross ≈ 11.9%     # 白送的对冲节省
```
慢腿延迟到 4 小时网格上执行，对 8h/24h/日级信号的损失可忽略；反过来**绝不降低 king 的频率** —— 那是把 alpha 损失伪装成成本节省。

**当前换手水平：** 绝对口径约 1,457×/年（净）。曾经做过完整的换手-成本前沿研究（三根轴：no-trade band、成本加权 band、持仓惯性），结论是：
- **band 无效**：band 开到均值仓位的 0.5 倍，换手只掉 9.6% —— **这本书的换手不是由小额调仓构成的，band 没有可抑制的对象**；
- **惯性有效但要付费**：换手降 30% 要付 12.6% 的 Sharpe，降 55% 付 33%；
- **在真实费率（4.5bps）下现状最优**，惯性变体要到有效成本 6.93bps 才反超；
- **但在盈亏平衡成本（11.8bps）下，现状的净 Sharpe 是 −0.21，而惯性变体是 +1.79** —— 所以低换手变体是**保险**（成本比预期更糟时唯一还活着的配置），不是改进。相应的激活规则已经预注册：实测有效成本持续 >6.93bps 启动惯性挑战者评估，>8.49bps 直接上影子轨。

# 8. 执行：maker 与 taker

## 8.1 成本结构

| 执行方式 | 费率 | 其他成本 | 有效成本合计 |
|---|---|---|---|
| **taker**（吃单，立即成交） | ~4.5–5 bps/side（零售档）| 无价差成本（直接吃对手价，价差已含在成交价里）| ~4.5–5 bps |
| **maker**（挂单，等成交） | ~0–1.8 bps/side（高等级近 0）| 半个价差 + 逆选择 | ~2–4.5 bps |

**逆选择**是 maker 的隐性成本：你的挂单被成交，往往是因为对方掌握了更新的信息（价格正要往对你不利的方向走）。它无法通过费率优化消除，只能测量。当前 markout 校准值：BTC tick 数据实测正常态 −1.71bps / 压力态 −3.24bps / 崩盘态 −5.30bps，alt 币尚未直接测量（**这是 pilot 唯一离线不可测、且最可能是坏消息的量**）。

## 8.2 为什么必须是 maker

本策略单边毛 edge 是个位数 bps。全 taker（如果4.5–5bps/side、双边 9–10bps）会直接超过毛 edge —— 策略亏。这不是"优化空间"，是**可行性前提**。全部可部署结论都建立在 maker 执行上。

盈亏平衡线：**11.79bps/side**（全历史口径）/ 9.59bps（2026 年）。当前测量到的清洁日有效成本 8.629bps（testnet 口径，仅供机械验证，不代表真实成本）。

## 8.3 maker + taker 的混合结构

实际执行是两段：

```
第 1 段（maker）：在 mid 附近挂 post-only 限价单，等 k 分钟（当前 k=15 分钟）
第 2 段（taker）：k 窗口结束后，对未成交的残差用市价单补足（top-up）
```

**为什么要有 taker 补单：** 纯 maker 会导致仓位偏离目标（挂单不成交），而组合的**中性性**依赖于多空两侧都建到位。若只有一侧成交，就出现了非预期的方向暴露 —— 那个风险比补单的成本更贵。

**这一段的经济学：** 强制 taker 补单实测让年换手增加约 27 个百分点。当前 pilot 的实测：一个健康锚点上 maker 腿成交后，补单只需补 1.66% 的残差（E1 判据 <20%，实测 0.0166）—— 也就是说 **maker 在 15 分钟窗口内成交了绝大部分**，taker 只是收尾。

**一个已量化的取舍：** 当成交读不到时（交易所接口退化），系统**拒绝补单**（不能在"假定为零成交"的基础上补，那会导致双倍建仓）。这条保护的代价实测：92 个名字被保护免于翻倍 vs 9 个名字欠配（名义比 1:13.2）。

## 8.4 关于"先用 taker 测 alpha"这个思路

**这个思路部分正确，但在本策略的信噪比下会误杀 —— 它的正确用法有严格边界。**

**它对的地方：** taker 执行没有"是否成交"的不确定性，所以用 taker 回测能得到一个**干净的信号存在性检验** —— 排除了成交率、挂单位置、逆选择这些执行侧变量的干扰，测的是纯粹的预测能力。作为**第一道存在性筛**（"这个信号到底有没有方向性"），它是合理的。

**它错的地方，以及为什么在这里会误杀：**

1. **taker 成本可能超过本策略的单笔毛 edge。** 用 taker 的净成本口径去筛因子，结论可能是"全部无效" —— 而这个"无效"是被成本口径判死的，不是被信号判死的。
2. **taker 与 maker 的 alpha 剖面不同。** maker 承担逆选择，所以它实际捕获的收益分布与 taker 不同（同一个信号，maker 拿到的是"没有被信息交易者挑走的那部分成交"）。用 taker 测出来的 alpha 幅度不能直接换算成 maker 的。
3. **成交率是策略的一部分，不是执行细节。** maker 的成交率 φ 直接决定了实际建仓覆盖率，而覆盖率影响中性性与实际 IC 兑现。把它抽象掉，测的就不是将要部署的那个系统。

**建议正确的做法（本项目采用的）：**

```
第 1 层  毛 IC / rank-IC（无成本）        —— 信号存在性。用它筛掉真正没方向的东西
第 2 层  净成本 IC（假设 maker 成本档）   —— 经济可行性。用它排序候选
第 3 层  执行仿真（maker 成交率 + 逆选择） —— 部署判定。用它做最终录用
第 4 层  实盘小规模（P0）测量真实 φ 与 markout —— 唯一能给出真数的一层
```

**核心原则：用哪种执行方式测，就用哪种执行方式的成本口径判 —— 且必须明确标注口径。** 用 taker 测信号、用 taker 成本判经济性，会误杀；用 taker 测信号、用 maker 成本判经济性，是口径混用（更危险，因为它给出的是乐观的错误结论）。

# 10. 术语表

| 术语 | 含义 |
|---|---|
| **bps** | 基点，1bps = 0.01% |
| **perp** | 永续合约，无到期日的衍生品，靠资金费率锚定现货 |
| **funding rate** | 资金费率，perp 多空之间的周期性支付，读出市场拥挤方向 |
| **maker / taker** | 挂单方 / 吃单方。maker 费率低但可能不成交，taker 立即成交但费率高 |
| **逆选择 (adverse selection)** | maker 的隐性成本：挂单被成交往往因为对方信息更新 |
| **markout** | 成交后 D 秒的价格位移 × 方向，用于测量逆选择 |
| **横截面 (cross-sectional)** | 同一时刻在多个资产之间比较，而非同一资产的时间序列 |
| **rank-IC** | 每个时刻预测与实现值的 Spearman 秩相关，横截面策略的 headline 指标 |
| **IC-IR** | IC 的均值除以标准差，衡量稳定性 |
| **残差 (YR)** | 扣掉市场均值与基线因子解释力之后剩余的未来收益 |
| **增量 IC (inc_ic)** | 在既有因子基线之上的额外预测力 |
| **CL** | 非重叠标签集，避免前向收益重叠导致的显著性虚高 |
| **embargo** | 训练集与测试集之间的时间隔离带，防止窗口/标签重叠 |
| **σ-gate** | σ_pred/σ_target ≥ 0.02 的硬条件，防止预测塌缩 |
| **L1 归一** | 除以绝对值之和，使总敞口为 1 |
| **demean** | 减去横截面均值，实现美元中性 |
| **netting** | 多腿合成后只交易净差额，省下的换手 |
| **hedge rate** | 1 − 净换手/毛换手，netting 白送的节省比例 |
| **BAB** | betting against beta，做多低 beta 做空高 beta |
| **Amihud** | 非流动性指标，单位成交额造成的价格冲击 |
| **point-in-time** | 只用当时可得的数据构造，无前视 |
