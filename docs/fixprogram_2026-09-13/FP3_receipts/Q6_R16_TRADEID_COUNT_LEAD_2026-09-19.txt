Q6 R16 修正版: 「只走 trade-id」路径的触发计数 —— 主研究员独立测量, 非推理
================================================================================
问题(我向修复线提的): 有多少【携带的未归属成交】, 其 trade_id 真的出现在
【合并后请求】的 trade_ids 集合里? 我要的是计数本身, 不是平价结果 ——
平价跑分不清「零因为确实没有符合的」与「零因为那条路径根本到不了」。

方法: 直接读 checkpoint 产物, 不改装置, 不采信任何一方自述。
  携带侧 = 上半 checkpoint (0808..0913) 每名 hard.unattributed_fills
  合并侧 = 续跑 checkpoint 每名 hard.requests[*].trade_ids
  接缝 0913/0914, 真实 41 天账本。

结果
  带有携带未归属成交的名 : 256
  携带未归属成交总数     : 3,725
  trade_id 命中合并后请求 : 0
  命中的名               : 无

判读(两句必须分开写)
  (1) 恢复的平价 = 【无回归】的证据。trade-id-only 归属零条, 所以续跑与单跑
      回到一致 —— 这是它不破坏东西的证据。
  (2) 这条路径在这 41 天真实数据上【一次也没有触发】。所以「修法会正确触发」
      此刻【只有合成夹具】支撑, 没有任何真实数据证据。
  把 (1) 说成 (2) 就是把「已验证」说大了。

为什么这个计数比「计数为零」强
  候选人口是 3,725 条, 不是零。所以「零命中」排除了「零是因为根本没东西可数」。
  坏版本(9da6a8a9)正是从这 3,725 条里用【推断路径】错认了 87 条,
  产出 2,496 条虚假 UNMEASURABLE。修正版把路径收窄到确定性判据后归属零条。

根因坐实
  checkpoint 的 unattributed_fills 是四元组 [ts, lots, ?, trade_id] ——
  【确实不带 rebalance_id / attempt_idx】。而同一份 checkpoint 的 requests
  是带 rebalance_id / attempt_idx 的。所以丢失是【只丢在未归属成交这一侧】,
  重建时填 None, 于是它们获得了「唯一存活同向」这条路径的资格 ——
  而完整重算里它们仍带标识符, 在第一个窗口就被 rid-attempt 解析掉, 从不走那条路。
  这就是【有损重建陷阱】: 在 checkpoint 已丢弃的证据上重跑一遍推断。

方法论(本轮两次教训)
  一条【失败过】的推理结构, 不会因为换一个更窄的主张就变可靠。
  分支旧论证: 平价曾成立 => 无可认领 => 重新提供不变。被实测推翻。
  分支新论证: 平价曾成立 => 完整重算归属零条 => trade-id-only 也零条。结构相同。
  ⇒ 必须用【同一种测量】替换掉, 即本表。
  「它必定是零, 因为平价曾成立」不能代替「我数了, 是零, 候选 3,725」。
