## 3. 两个机制, 不是一个
### 3.1 SCRT / STORJ = **场所下市结算**(`DELIVERED_SETTELMENT`)
同窗 `GET /fapi/v1/income` 里, 这两笔的收入类型是 **`DELIVERED_SETTELMENT`**(SCRT −41.25 USDT / STORJ +10.60 USDT), 不是 `REALIZED_PNL`。也就是说: **是交易所在合约下市时把仓位结算掉的, 不是我们下的单。**
这正是判活规则要挡的情形 —— 书在持有**已经下市的合约**。与 09 月普查里 ICX / SCRT / STORJ 同一批, 也与 [[a0_reference_flattered_by_dead_contracts_2026_09_16]] 同源。**这一条完全闭合。**

### 3.2 ATOM / SNX 08-21 16:23:09 = **本地账本完全没有记录的平仓**
收入类型是正常的 `REALIZED_PNL` + `COMMISSION`, 价格正常, 两个名都被**平到零**。但是:
- 这两个 orderId(24719601930 / 11122351098)在本地 `orders.jsonl` 里**根本不存在**;
- 本地在 **16:20–16:25 之间一行订单都没有提交**(当天 ATOM / SNX 各 10 行本地订单, 最近的一次提交是 16:01);
- 该时刻**仍在 16Z 锚自己的工作窗内**(锚日志 16:24:09 才写 `lock released (anchor work complete)`, 16:24:10 `anchor done rc=0`);
- 当锚的 phase_C(16:19:40)写的是 `stopped: []`, `held_exit` 与 `meta_excluded` 都为空, `known_gaps` 只点名 SKL / MEME 两个。

**结论**: 存在**订单与成交都没有任何本地记录**的平仓动作。我不对它的来源下结论 —— 这需要执行器侧按 orderId 反查是哪条代码路径发的单, 属生产侧排查, 本件只报不修。
