# 验收门重做: 从「内部自洽」到「外部可复算」

## §0 一页结论(白话)

1. **复审指出的缺陷成立**: 旧门的每一项都是**内部自洽** —— 电池从路径文件重算 32 路径均值、比对**收据自报**的 sha; 钉哈希比对的是**运行配置自己声明**的值。因此「改初始现金 / 改基价并重签配置 / 改路径经济量并重算收据」都能通过。旧门的 PASS 证明的是**自洽**, 不是「这些数字来自指定输入上的指定模拟执行」。
2. **已修**(装置 `bt_gate_external.py`): 输入**从各自的路径重新哈希**并与仓库里 committed 的批准表比对(不读配置/收据里的任何 sha); 经济常数(初始现金 / gross 倍数 / 追单权重 / 路径数)**整块哈希**; 运行配置自己的钉必须与批准表一致; 每条路径的初始状态必须等于批准的初始现金与空书; 最关键的一项 —— **按批准表的输入路径重跑并与存档逐位比较**。
3. **篡改用例已实测**(见 §2): 复审给的三类篡改, 加上两类同族篡改, 在**旧门全绿**的情况下**新门全红**; 基线(未改)在两个门上都是绿。
4. **本装置的篡改测试还抓到了我自己修法里的洞**: 第一版新门只重算一条抽样种子, 于是一个 seed 01 被改过的目录照样 PASS(抽 1/32 的命中率)。因此**覆盖度进入判词**: `--reproduce all` 才是 **PASS**, 否则判词是 **PASS-SPOTCHECK** 并列出未认证的种子, **不得当发布门引用**。
5. **没有任何已发布数字发生变化**: 在役 A0、A0 延长窗、v4 三条**主读数**运行, 各 **32/32 条路径**从外部输入重算, 与存档**逐位相同**(见 §3)。门现在能说出这句话 —— 这正是旧门做不到的。

## §1 门的内容(每一项都有具名判据)

| 检查 | 内容 | 它防住什么 |
|---|---|---|
| **E1** | 每个输入**从它自己的路径**重新哈希, 与 `APPROVED_INPUTS_2026-09-20.json`(仓库 committed, 由三份已冻结运行配置交叉核对并逐个重哈希生成)比对 | 换掉价格表 / 资金费账本 / 目标 / 标定, 并把配置里的 sha 一起改掉 |
| **E2** | 经济常数块(`current_production_config` + `nav0_usdt` + `paths_R`)的规范化 JSON 哈希 == 批准值 | 改初始现金、gross 倍数、追单权重、路径数 —— 即使所有收据都与之自洽 |
| **E3** | 运行配置自己的钉(路径 + sha)必须与批准表逐项一致; 运行所引的目标文件必须在批准表里 | 本机上被改过的配置副本 |
| **E4** | 每条存档路径的 `nav0[0]` / `navm0[0]` == 批准的初始现金, `gross0[0]` == 0 | 直接改路径里的初始现金 |
| **E5** | **从外部输入独立重算**: 按批准表的输入路径重跑该目录的每条路径(`--workers` 并行, 价格面板 COW 共享), 与存档**逐位**比较窗账本(价格损益 / 资金费 / 手续费 / 换手 / NAV)与 5 分钟 NAV | 任何「自洽但不是那次执行产生」的数字 |
| **E6** | 旧的内部自洽检查(AGG == 逐路径均值; 每个 npz 与其 json 的 sha 一致)—— **保留**, 因为它们必要, 只是不充分 | 目录内部被部分改动 |
| **覆盖度** | `--reproduce all` ⇒ PASS; 否则 PASS-SPOTCHECK 并列出**未认证**的种子; `--reproduce 0` 直接拒绝(零测量的绿) | 「PASS 听起来覆盖了全部, 其实只抽了一条」 |

## §4 局限(具名)

1. **门证明的是「这些数字由这套代码在这些输入上产生」**, 不证明这套代码的经济假设正确 —— 模拟器的标定、UNAVAILABLE 规则、停机语义仍由各自的预注册与读数(P / P2)约束。
2. **批准表本身**是由三份已冻结的运行配置交叉核对后生成并入库的; 它的权威来自 git 历史, 不来自 pod 上的任何文件。若三份配置在某个钉上不一致, 生成器**拒绝**而不是取其一。
3. **E5 重跑用的是同一份驱动代码**: 它证明输入与存档的对应关系, 不能发现「代码本身自始至终就错」的问题 —— 那由电池(53 项, 基线绿 / 变异红)与独立复审覆盖。
4. **覆盖度必须和判词一起引用**: `PASS-SPOTCHECK` 的收据不得当作发布门。
