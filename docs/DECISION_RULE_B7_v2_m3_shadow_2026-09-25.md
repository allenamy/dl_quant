# 判据:M3 v2 影子锚的 B7 控制(取代 v1 的「逐名相对差 1%」)

## 0. 为什么要换

v1 的 B7 第 (i) 层是逐名相对差 `|β_prod − β_res| / |β_res| ≤ 1%`。β 接近 0 的名,相对差会被分母放大,与真实误差无关。诊断 `bb076fa2c`(08Z/12Z 两锚,898 个名×锚)在改读 RR 之后:
- 绝对差中位 4.6e-5、p90 1.4e-4、p99 5.4e-4;
- 仍超 1% 的名几乎都是 |β| < 0.035 的近零 β(BTR、TAC、STORJ、SOLV、AIN、UB);
- 两个例外是有数据异常的名:STGUSDT(下架结算中,|Δβ| 0.039)、SCRTUSDT(已掉出取数集,推断非 TRADING,|Δβ| 0.003)。

用这批**已有**诊断数据标定容差,判据适用于**之后的** v2 影子锚(不是在同一批数据上既标定又判定)。

## 1. 判据(每个 v2 影子锚)

| 层 | 内容 | 角色 |
|---|---|---|
| **(0) 版本与自检** | 字段 `version == m3_beta_v2`;执行器记录的 `betas_sha256` 与生产字段重算一致;生产公式逐位复现(方法 b)`M3_SELFCHECK OK n=0` | **门** |
| **(i) 逐名** | 超限名 = `|β_prod − β_res| > max(0.01·|β_res|, 0.002)`;逐个列出名、β 两侧、n_obs 两侧、该名在锚时刻的场所状态(TRADING / 非 TRADING / 结算中) | **必报,不作门** |
| **(ii) 执行层** | `|β_exec_prod − β_exec_res| ≤ max(0.01·|β_exec_prod|, 0.001·NAV)`(USDT;β_exec = Σ 目标名义 × β,BTC 取 1;合池量) | **门** |

- **放行 on 的前置**:连续 **2 个** v2 影子锚 (0) 与 (ii) 全过。
- (i) 的每个超限名必须在报告里有具名原因(状态异常 / n_obs 不同 / 其它);**出现无法解释的超限名 ⇒ 该锚记为「待查」,不计入 2 个干净锚**(不是判红,是不计数)。
- 任何一锚 (0) 或 (ii) 不过 ⇒ 停,查因,不切 on。
