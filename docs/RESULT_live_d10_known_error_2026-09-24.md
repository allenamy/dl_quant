# 实盘 D10 的已知误差

## 0. D10 是什么,以及这份材料回答什么

**D10 是一个已冻结的有意选择**:结算间隔 `iv` 的来源。

| | `iv` 从哪来 |
|---|---|
| **NC(在役)** | `snap_interval(ft − 上一条账本事件的 ft)`(`nc_contract.py` L32–44) |
| 研究员 | 装配:拼接账本 + `latest` + 2026-08 官方归档(`build_combo_inputs.py` L140) |

`iv` 经 `rn = rate × 8 / iv` 进入 fund_ema,再进 King 的 78 列输入与资金费腿。**所以 `iv` 推错 k 倍,`rn` 就偏 1/k 倍。**

本文只回答:**在役这条路径上,这个误差实际发生过几次、每次多大、持续多久。不回答哪边对。**

## 1. 一个必须先说的限制

**生产账本自己存的 `iv` 就是 NC 推出来的那个值**(`ingest_settlements` L77:`iv = snap_interval(gap) if led else None`)。所以**生产数据里没有独立的"真值"可以对照**——它无法区分「交易所真的改了周期」和「账本漏了一次结算」。

⇒ 下面的幅度都是**条件反事实**:**假如**那一次是漏结算(即真实间隔仍是前一档节奏),NC 算出的 fund_ema 与本应有的值差多少。**本文不主张那 41 次确实是漏结算。**

## 4. 最该单列的一类:k 不是 2 的幂时,`snap_interval` 平局取大

`snap_interval` 把间隔吸附到 `IV_GRID = (1, 2, 4, 8)`,**平局取较大的那个**(`nc_contract.py` L42:`d == bd and g > best`)。

⇒ **3 小时的间隔落在 2 与 4 正中间,被吸附成 4。**

所以 `SOPHUSDT`(2026-09-11)与 `1000XECUSDT`(2026-07-23)这两例:前一档节奏 1h、实际间隔 3h,NC 推成 **4h**,**比值 4.0 而不是 3.0** —— 即 `rn` 只剩应有值的 **1/4**,而不是 1/3。

**k=3 共 8 例**,都属于这一类。这是 D10 在实盘上偏得最多的情形,建议在裁定时单列。

## 5. 量级的读法

fund_ema 本身的量级在 1e-4 … 1e-2 之间(见 `FUND_EMA_WALK.json` 的实例:−0.0218、+0.0001)。所以:

- **中位一次事件 1.1e-05 的偏差,相对多数名的 fund_ema 是小的**;
- **最大一次 1.5e-03(`TUSDT`)不小**,且要 10 天才衰减到峰值的 10%;
- 但**一次只影响一个名**,而书是 400 名的横截面,且 fund_ema 之后还要过秩变换(`xz_in_base`),**单名的绝对偏差不等于书层影响**。**书层影响本文未测。**
