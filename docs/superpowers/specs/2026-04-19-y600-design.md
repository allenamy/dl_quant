# Y_600 Robust Prediction Pipeline — Design Spec (V5-LH)

**Date:** 2026-04-19
**Objective:** Build a long-horizon (y_600 = 10-minute) prediction model reaching clean Pearson IC ≥ 0.07 on 3-fold pooled walk-forward, WITHOUT regressing y_180 performance.
**Trading-cost constraint:** Ignored. This is a pure signal-quality problem.
**Independence:** V4 code (DualPathLOBModelV3, existing NPZ) remains untouched. New code under `src/model_v5_lh/`, `src/features_v5_lh/`, `data/npz_v5_lh/`.

---

## 1. Problem Statement

### 1.1 Current baseline (to beat)

| Model | y_600 Clean Pearson (stride=600 subsample) | Notes |
|---|---:|---|
| Ridge on orig_64 features | **0.045** | from Phase D Stage 1 |
| Ridge on orig+ms+session (87 feat) | 0.039 | multi-scale hurts (collinear) |
| V4 y_180 model on y_600 (not retrained) | 0.019 (subsample) | current floor |
| **Target (V5-LH)** | **≥ 0.07** | primary criterion |

### 1.2 Root-cause analysis (Phase A-D evidence)

Why y_600 prediction is harder than y_180:

1. **Input window / horizon ratio mismatch.** y_180 has 600s/180s = 3.3× lookback. y_600 has 600s/600s = 1.0×. No context.
2. **TCN receptive field 15s** irrelevant to 600s horizon (coverage 2.5%).
3. **Stride=60 NPZ** creates 90% label overlap for y_600 → training sees near-duplicate targets; clean IC halves.
4. **Features engineered for 1-second to 5-minute scale** — max scale feature is `realized_vol_300s`.
5. **V4 bin-plot diagnosis (y_180)** shows systematic tail shrinkage — extreme negative y predicted near zero. This pattern likely worsens at longer horizons.
6. **No multi-horizon joint training** — V4 y_180 encoder may have focused on sub-minute patterns.

### 1.3 Success criteria (hard gates)

- **Primary:** clean y_600 pooled Pearson ≥ 0.07, Spearman ≥ 0.08
- **Secondary:** y_180 pooled Pearson ≥ 0.08 on same NPZ (no regression from V4 0.094)
- **Tail behavior:** bin-plot E[ŷ | y bin 1] ≥ 0.5× OLS-expected (improve from current 36%)
- **Calibration:** q10/q50/q90 actual coverage within ±3% of nominal
- **Monotonicity:** decile Spearman ≥ 0.95
- **Daily IC-IR:** ≥ 1.0 (health check)

If primary not met after 4 weeks, stop and document failure. This is Phase E's honest cut-off.

## 2. Architecture (V5-LH)

### 2.1 Overview

```
Inputs: X (N, 1800, 64), X_raw (N, 1800, 20, 4), regime_prior (N, 6)
 |
 ├── Path A: Handcrafted Features (56 after redundancy filter)
 |    └── GDCN (2 gated cross layers) → Linear → h_A (N, 1800, d_model=32)
 |
 ├── Path B: Side-Aware Raw LOB
 |    ├── Bid: (N, 1800, 20, 2)  → BidEncoder (Conv2d)  → h_bid (N, 1800, 8)
 |    ├── Ask: (N, 1800, 20, 2)  → AskEncoder (Conv2d)  → h_ask (N, 1800, 8)
 |    ├── Cross-Side Attention:
 |    |     h_bid' = Attn(Q=h_bid, K=h_ask, V=h_ask)
 |    |     h_ask' = Attn(Q=h_ask, K=h_bid, V=h_bid)
 |    └── Concat [h_bid'; h_ask'; h_bid' − h_ask'] → Linear → h_B (N, 1800, d_raw=24)
 |
 ├── Cross-Path Fusion (bidirectional):
 |    h_A_enh = CrossAttn(Q=h_A, K=h_B, V=h_B)
 |    h_B_enh = CrossAttn(Q=h_B, K=h_A, V=h_A)
 |    h_fused = h_A_enh + Linear(h_B_enh − Proj(h_A_enh))  # residual decomposition
 |                       (N, 1800, d_model=32)
 |
 ├── Temporal Backbone: Mamba-2 (3 layers, ~3K params, causal, O(n))
 |    └── h_temporal (N, 1800, 32)
 |
 ├── Pooling: AttentionPool1D (causal) over last 300 tokens
 |    └── h_pool (N, 32)
 |
 ├── PPNet Gate: condition on regime_prior (6-dim)
 |    └── h_gated (N, 32)
 |
 └── Dual Quantile Heads (y_180 + y_600, soft shared):
       MonotonicQuantileHead_180 → (q10, q50, q90) for y_180
       MonotonicQuantileHead_600 → (q10, q50, q90) for y_600
```

### 2.2 Parameter budget

| Module | Params | Justification |
|---|---:|---|
| GDCN × 2 (on 52-56 feat) | ~4,000 | proven; no MaskNet (GDCN covers crossing) |
| Bid / Ask Encoders (Conv2d small) | ~4,000 | side-aware, small channels |
| Cross-Side Attention | ~2,500 | 1 layer, nhead=2, d=8 |
| Cross-Path Fusion | ~3,000 | bidirectional attention + residual proj |
| **Mamba-2 (2 layers, d=32, d_state=16, expand=1)** | **~12,000** | linear SSM, conservative config |
| AttentionPool1D | ~2,000 | causal token pool |
| PPNet Gate × 2 | ~3,000 | per-horizon regime conditioning |
| Dual Quantile Heads (soft shared) | ~4,000 | 2× MonotonicQuantileHead |
| **Total active forward** | **~34,500** | ~60% of V4 (59K), much tighter |

Parameter-to-sample ratio: 34.5K / ~1M train windows per fold = **1:29** (safer than V4's 1:17).

**Note:** Mamba-2 parameter count was initially under-estimated. Accurate count above uses realistic `d_state=16, expand=1, nheads=4` config. Can shrink further to ~8K if overfit observed (use `d_state=8`).

### 2.3 Why this architecture (not others)

| Alternative | Rejected because |
|---|---|
| V4 + patch attention (add back) | 22K attention params overfit at SNR<1% (proven in V4 smoke) |
| Pure Transformer (PatchTST) | O(n²) over 1800 steps = 3.2M attention ops × batch; expensive; data-hungry |
| Pure Mamba (no conv/cross-attention) | Sacrifices handcrafted-feature inductive bias |
| Adding macro hour-level features | Phase D Stage 1 proved collinearity with existing features HURTS |

Mamba-2 is the **safest long-context choice** on our data scale (15M samples): small parameter count, linear complexity, strong inductive bias for time series.

## 3. Data Pipeline (V5-LH NPZ)

### 3.1 New NPZ schema

Location: `data/npz_v5_lh/YYYY-MM-DD.npz` (separate from `data/npz_v4/`).

| Key | Shape | Notes |
|---|---|---|
| `X` | (N, 1800, F_filtered) | F ≈ 52-56 after redundancy filter |
| `X_raw` | (N, 1800, 20, 4) | same bid/ask price/amt as V4 |
| `features` | (F_filtered,) | filtered feature names |
| `regime_prior` | (N, 6) | same as V4 |
| `timestamps` | (N,) int64 (microseconds) | |
| `y_180` | (N,) | 180s forward return (kept for multi-task) |
| `y_600` | (N,) | 600s forward return (primary target) |
| `y_mask_180` / `y_mask_600` | (N,) uint8 | validity mask |
| `norm_stats_y_180` / `y_600` | (2,) | median + MAD sigma for target scale |

### 3.2 Stride — training vs evaluation decoupled

**Key realization:** stride controls two orthogonal things:
1. **Training density** — more stride=60 samples means more gradient signal
2. **Evaluation purity** — stride=60 pooled IC is autocorrelation-inflated

These can and should be decoupled:

- **NPZ stride = 60 (same as V4)** → 700 × 1440 = ~1M samples per fold
- **During training:** all overlapping samples used (same as V4, proven to work)
- **During evaluation:** subsample to stride=600 for **clean** y_600 IC reporting on test set (post-hoc, simple indexing)

**Parameter-to-sample ratio check:**
- Model params (Section 2.2): ~24K
- Train samples per fold: ~1M
- Ratio: **1:42** (safer than V4's 1:17)
- → Low overfit risk.

**Why this is rigorous:**
- V4 y_180 training with stride=60 (67% overlap) works well; no known overfit from overlap.
- The only legitimate concern with overlap is **inflated in-sample metrics**. This is addressed by evaluating on a stride=600 subsample (true out-of-sample sample independence).
- Training loss is just a proxy; as long as val/test metrics are honest, overlap during training is fine.

### 3.3 Evaluation subsampling protocol

For clean y_600 reporting (primary target):
1. For each test fold's predictions, sort by timestamp.
2. Take every 10th sample (stride_effective = 600s).
3. Compute Pearson/Spearman on this subsample.
4. Report both "raw" (all samples) and "clean" (subsampled) metrics; **primary = clean**.

This matches what we already did in Phase D to get Ridge y_600 clean IC = 0.045.

### 3.4 Feature redundancy filter

**Rationale:** Current 64 features have known collinearity (OBI L1/L5/L10/L25, realized_vol_60s/300s, return_1s/5s/30s).

**Procedure (executed once per fold, on training days only):**
1. Compute pairwise Pearson correlation matrix of last-timestep features.
2. For each pair with |r| > 0.95:
   - Keep the feature with higher |IC| against train y_600.
   - Drop the other.
3. Save `kept_indices` in NPZ metadata for reproducibility.
4. Expected to drop 8-12 features → final 52-56 features.

**Verification:** verify multi-collinearity VIF < 10 for all kept features post-filter.

## 4. Loss Function (V5-LH DUL+)

### 4.1 Composite loss

```
L_total = Σ_h (1/(2σ_h²)) · L_h  +  Σ_h log(σ_h)  +  α · L_decorr

where L_h = tail_weight · [pinball(q10, q50, q90) + γ · CRPS(q10, q50, q90) + η · L_utility_rank]
```

| Component | Weight | Role |
|---|---:|---|
| `pinball` (quantile loss) | 1.0 | base q10/q50/q90 regression |
| `CRPS` (Continuous Ranked Probability Score) | γ=0.5 | distributional calibration, forces tail predictions to match empirical CDF |
| `L_utility_rank` | η=0.3 | pairwise rank loss on risk-adjusted score (same as V4) |
| `tail_weight` | 1 + 2·I(|y|>2σ) | focal-style upweight for extreme-y samples |
| `UNIT loss σ_h` (learnable per horizon) | — | auto-balance y_180 vs y_600 gradients, prevent task conflict |
| `L_decorr` (Barlow-Twins-style) | α=0.1 | penalize off-diagonal correlation of final embeddings; reduces redundancy |

### 4.2 Why each component

**CRPS:** Proper scoring rule. Minimizes over whole distribution shape, not just specific quantiles. Directly addresses bin-plot tail-shrinkage finding. Implementable with q10/q50/q90 via piecewise-linear CDF approximation.

**Focal weighting:** Current pinball loss gives equal weight to every sample. Since 95% of samples have |y| < 2σ, extreme tail contributes only 5% of gradient. Focal weighting 2× makes it ≈10% — enough to unshrink predictions without destabilizing.

**UNIT loss (Kendall 2018):** Per-task uncertainty σ_h is learnable. L = (1/(2σ²))·L_task + log(σ). If y_600 is noisier (which it is), σ_600 grows → effective weight on L_600 decreases → y_180 dominates when tasks conflict. Dynamic equilibrium, no manual tuning.

**Decorrelation loss:** On final 32-dim embedding, penalize `||Corr_offdiag||²`. α=0.1 is light; with α too high, model collapses to orthogonal-but-useless directions.

### 4.3 Alternatives considered and rejected

| Alternative | Rejected because |
|---|---|
| MSE / Huber only | No quantile output, no confidence gating later |
| PCGrad for multi-task | More complex than UNIT; UNIT achieves similar effect with simpler math |
| Expectile regression | CRPS is strictly better (proper scoring rule) |
| Hard gradient masking | UNIT softer and better-behaved |

## 5. Risk Control (3 layers)

### 5.1 Uncertainty quantification + calibration

- Keep V4's MonotonicQuantileHead per horizon.
- **Add post-hoc isotonic calibration** using validation set: fit monotonic spline to map predicted quantile → empirical quantile, apply at inference.
- Addresses bin-plot finding that V4 q50 under-predicts extreme negative y.
- Implementation: `sklearn.isotonic.IsotonicRegression` per quantile level, per fold.

### 5.2 OOD detection

- During training, compute Mahalanobis parameters (mean + inverse covariance) on training-set embeddings.
- At inference, compute Mahalanobis distance of input embedding to train distribution.
- Flag samples where distance > 99th percentile → downstream strategy can drop to flat.
- Simple, interpretable, detects regime shifts.

### 5.3 Seed ensemble (diversity)

- Train 3 independent V5-LH models with different seeds.
- Inference: report median(q50) and IQR across seeds as diversity-aware prediction.
- Reduces single-seed overfit risk.
- Parameter cost: 3× compute, 3× storage — acceptable.

## 6. Training Strategy

### 6.1 Walk-forward 3-fold (matched to V4 for apples-to-apples)

Same fold boundaries as V4: train 700d / val 30d / test 90d, stride=60d. Max 3 folds.

### 6.2 Joint multi-horizon training

Loss is computed for both y_180 and y_600 per sample. Encoder shared (soft sharing — both heads share backbone Mamba+fusion, each has private quantile head + per-horizon PPNet gate).

### 6.3 Optimizer + schedule

- Optimizer: AdamW (weight_decay=1e-3)
- LR: 6e-4 with linear warmup (5 epochs) + cosine anneal
- Early stopping: patience=8 epochs on **val y_600 Pearson** (primary criterion)
- Batch size: 256 (smaller due to longer input)
- Checkpoint: save top-5 by val y_600 Pearson, enable SWA ensemble at evaluation

### 6.4 Training monitoring (fail-fast)

Abort fold if at epoch 10:
- val y_600 Pearson < 0.02 → architecture/data issue, debug
- val y_180 Pearson < 0.05 → multi-task gone wrong, inspect UNIT σ values
- Gradient norm explodes (> 10) → clip aggressively, investigate

## 9. Theoretical Soundness Checklist

Each design decision grounded in theory/evidence:

| Decision | Theoretical Basis | Empirical Precedent |
|---|---|---|
| Stride = horizon | No label-overlap autocorrelation contamination | CLAUDE.md anti-pattern |
| Input window 3× horizon | Match successful V4 y_180 ratio (3.3×) | V4 y_180 works |
| Mamba-2 over Transformer | SSM stable long-range memory, linear scaling | Mamba-2 paper, Chronos-Bolt |
| Side-aware encoding | Microstructure asymmetry (buyer vs seller initiated flow) | Kyle 1985, Easley 1996 |
| Cross-path fusion | Complementary feature learning avoids redundancy | Multi-modal learning (CLIP-style) |
| UNIT loss | Bayesian uncertainty for multi-task | Kendall et al. 2018 |
| CRPS + focal | Proper distributional scoring | Gneiting & Raftery 2007; Lin 2017 (focal) |
| Decorrelation (Barlow Twins) | Redundancy reduction via cross-correlation matrix | Zbontar 2021 |
| Isotonic calibration | Distribution-free post-hoc calibration | Zadrozny 2002 |
| OOD via Mahalanobis | Gaussian mixture assumption on training embeddings | Lee 2018 |
| Seed ensemble | Model risk reduction via diverse predictions | Lakshminarayanan 2017 |
