# V4 Design Spec: Structure-Aware + Regime-Conditioned LOB Transformer

**Author**: Claude Opus 4.6 (1M context)
**Date**: 2026-04-16
**Status**: Design Approved — pending implementation plan

---

## Context

After 4 fold-level experiments (V2 single-day, V3 stride-180 fixed, V3+RevIN stride-60), we have reached a plateau. V3+RevIN's **Fold 0 test correlation of 0.082** underperforms the Ridge baseline's **0.099** on 1004-day BTCUSDT data. Ablation (Phase A2) showed MaskNet contributes only +0.004 to val_corr while GDCN contributes +0.032. Distribution shift analysis (Phase A3) showed PSI=0.35 (severe non-stationarity). Ridge feature importance (Phase A1) showed signal concentrates in trade-flow + OBI features.

This spec defines **V4**: an architecture + data pipeline + loss redesign informed by the above evidence, targeting `pooled OOS correlation > 0.12` across 4 walk-forward folds.

---

## Design Goals

1. **Beat Ridge pooled IC ≥ 0.12** (vs current 0.099 baseline).
2. **Test period ≥ 90 days** for tighter confidence intervals.
3. **Architecturally minimal**: retain only components with proven contribution.
4. **Regime-aware**: explicit external prior modulates model predictions.
5. **Multi-horizon**: 60/180/300/600s simultaneously for task diversity.
6. **Respect disk budget**: ~100GB total (currently 56GB free; delete old 45GB NPZ).

## Architecture: DualPathLOBModelV4

### Overall Dataflow

```
INPUTS
  x_feat       : (B, 600, 64)       — 58 base + 6 ridge-informed features
  x_raw        : (B, 600, 20, 4)    — bid/ask delta_bps + log_amt (20 levels)
  regime_prior : (B, 6)             — external 1-hour regime signals
        ↓
[1] RevIN        (per-instance normalization of x_feat)
        ↓
[2] Linear(64→32)  (project BEFORE crossing — avoids later compression loss)
        ↓
[3] GDCN(32-dim)   (gated crossing in compressed space)
        ↓
h_craft : (B, 600, 32)

    x_raw
        ↓
[4] 1x1 Conv(4→16) (explicit channel mixing: bid/ask/amt interaction)
        ↓
[5] Conv1d(16→32, k=3, over levels)
        ↓
[6] AttentionPool over 20 levels (replaces AdaptiveAvgPool)
        ↓
h_raw : (B, 600, 16)

FUSION
  concat(h_craft, h_raw) = (B, 600, 48)
        ↓
[7] Linear(48→32)
        ↓
h_fused : (B, 600, 32)

TEMPORAL
        ↓
[8] TCN: 3 × CausalConvBlock(d=32, k=3, dil ∈ {1,2,4})  — receptive field 15
        ↓
[9] Patch Embedding: patch_size=5 → 120 tokens (was 30 at patch_size=10)
        ↓
[10] Causal Attention: depth=1, nhead=2, d_ff=64
        ↓
[11] AttentionPool over 120 tokens (replaces last-token; reduces recency bias)
        ↓
h_pred : (B, 32)

REGIME GATE
        ↓
[12] PPNetGate(regime_prior(B,6) → scale(B,32)) — multiplicative modulation
        ↓
h_pred_gated : (B, 32)

MULTI-HORIZON HEADS
        ↓
[13] 4 × MonotonicQuantileHead(32 → 3) for horizons {60, 180, 300, 600}
        ↓
quantiles_by_horizon : (B, 4, 3)
```

### Component Changes vs V3

| Component | V3 | V4 | Rationale |
|-----------|-----|-----|----------|
| RevIN | present | **unchanged** | Handles non-stationarity at marginal level; proven in V3 |
| MaskNet | 2 blocks | **REMOVED** | A2 ablation: +0.004 contribution, not worth 20K params |
| GDCN | after input proj | **BEFORE → AFTER compression** | Preserves crossing information; GDCN now in 32-dim |
| RawLOB | Conv + AvgPool1d(1) | **+1x1 conv, AttentionPool over levels** | Explicit channel mixing; position-aware pooling |
| Temporal Conv | 3 blocks, d=32 | **unchanged** | Works fine; receptive field 15 captures microstructure |
| Patch size | 10 → 30 tokens | **5 → 120 tokens** | Finer temporal resolution |
| Patch output | last-token | **AttentionPool** | Reduces recency bias |
| PPNet Gate | `d_prior=0` (disabled) | **`d_prior=6` enabled** | External regime conditioning |
| Quantile Head | single horizon | **4 horizons** | Multi-task regularization |
| Input length | 300 (5 min) | **600 (10 min)** | More context for long-horizon predictions |

## Data Pipeline Changes

### New Features (6 ridge-informed)

Based on Phase A1 Ridge weights (top: net_trade_flow, OBI, depth):

| Feature | Formula | Rationale |
|---------|---------|-----------|
| `net_flow_x_spread` | `net_trade_flow_1s * spread_bps` | Flow impact scaled by market liquidity |
| `net_flow_x_vol` | `net_trade_flow_1s * realized_vol_30s` | Flow impact in current vol regime |
| `obi_L5_rank_1h` | Rolling percentile of `obi_L5` over past 1h | Scale-invariant, regime-robust |
| `net_flow_rank_1h` | Rolling percentile of `net_trade_flow_1s` over past 1h | Scale-invariant |
| `large_trade_arrival_60s` | 1 if any 60s trade > p95 of training distribution, else 0 | Event signal |
| `book_pressure_delta_60s` | `book_pressure_imbalance(t) - book_pressure_imbalance(t-60)` | Velocity of queue pressure |

**All features strictly causal** (no future data).

Base features remain 58 from current pipeline. Total: **64 features**.

### Multi-Horizon Labels

`build_npz_for_day` emits:
- `y_60`, `y_mask_60` — 60-second forward log-return
- `y_180`, `y_mask_180` — 180-second
- `y_300`, `y_mask_300` — 300-second
- `y_600`, `y_mask_600` — 600-second

Back-compat: `y` and `y_mask` alias to `y_60` (shortest horizon).

Already implemented in commit `f0b7291` — no code change needed, just regenerate NPZ with `horizons_sec=[60, 180, 300, 600]`.

### Regime Prior (6 features, external)

Stored as new NPZ field `regime_prior: (N_win, 6)`, loaded by `LOBDatasetV2`, passed to model:

| Feature | Formula | Window |
|---------|---------|--------|
| `vol_1h` | `std(log_return_1s over [pred_idx - 3600, pred_idx])` | 1h |
| `spread_mean_1h` | `mean(spread_bps over past 1h)` | 1h |
| `obi_trend_1h` | Linear regression slope of `obi_L5` over past 1h | 1h |
| `price_return_6h` | `log(mid[pred_idx] / mid[pred_idx - 21600])` | 6h |
| `hour_sin` | `sin(2π × hour_of_day / 24)` | deterministic |
| `hour_cos` | `cos(2π × hour_of_day / 24)` | deterministic |

All strictly causal. Fill with 0 when insufficient history.

### Input Window = 600 Seconds

Up from 300. Minimum required rows per day:
`min_rows = input_len + max(horizons_sec) = 600 + 600 = 1200 seconds` (20 min)

Median day has ~31K seconds, so virtually all days qualify. Days with < 1200s discarded silently.

Windows per day at `stride=60`: `(31620 - 1200) / 60 ≈ 507 windows` (vs 580 at input_len=300).

### Walk-Forward Fold Structure

| Param | Old (V3) | New (V4) |
|-------|---------|---------|
| `train_days` | 500 | **700** |
| `val_days` | 30 | 30 |
| `test_days` | 30 | **90** |
| `fold_stride` | 60 | 60 |
| **Folds** | 8 | **4** |
| **Samples/train fold** | ~220K | ~355K |
| **Samples/test fold** | ~13K | ~45K |

Trade-off: fewer folds but each test has ≥90 days of OOS samples, reducing test-period regime dependency.

### Disk Estimate

- Per window (X + X_raw + labels × 4 + regime_prior):
  - X: 600 × 64 × 4 = 154KB
  - X_raw: 600 × 20 × 4 × 4 = 192KB
  - Labels (4 × y + 4 × mask): ~40 bytes
  - Regime prior: 24 bytes
- Uncompressed: ~346KB/window, **compressed ~120KB/window** (~35% ratio)
- 1004 days × 507 windows × 120KB = **~61 GB**

**Plan**: Delete old `data/npz_dense/` (45GB) before regen. Net disk usage ≈ 61GB.

## Loss: Distributional Utility Loss (DUL)

Replace quantile-only loss with three components.

### L_quantile (main)

Unchanged pinball loss on q10/q50/q90. Sum across horizons for multi-horizon training.

### L_utility_rank (new)

1. Compute risk-adjusted trading score per sample:
   ```
   s = q50 - α × (q50 - q10)       # risk-aversion: penalize downside
   with α = 1.0  (tuneable)
   ```

2. Pairwise logistic rank loss within each batch:
   ```
   for random pairs (i, j):
     desired = sign(y_i - y_j)
     pred_diff = s_i - s_j
     loss_ij = log(1 + exp(-desired × pred_diff))
   ```

3. Number of pairs = batch_size (same order as quantile loss).

**Why pairwise rank**: scale-invariant, directly optimizes ordering/IC, unifies direction + magnitude from the distribution.

### L_calib (optional, stretch)

Batch-level quantile coverage penalty:
```
c_τ = fraction of (y ≤ q_τ) across batch
L_calib = (c_0.1 - 0.1)² + (c_0.5 - 0.5)² + (c_0.9 - 0.9)²
```

**Warmup**: disable L_calib for first 5 epochs (model needs to learn rough distribution first).

### Combined

```
L_total = L_quantile
        + λ_1 × L_utility_rank     (λ_1 = 0.3 default)
        + λ_2 × L_calib            (λ_2 = 0.1, after epoch 5)
```

For multi-horizon: sum each component across all 4 horizons before weighting.

## Evaluation

### Per-fold metrics (saved to `test_results.json`)

Per horizon:
- Pearson correlation
- Rank correlation
- R²
- Direction accuracy
- 95% CI for correlation

### Aggregate (via `scripts/aggregate_folds.py`, already exists)

- **Pooled OOS IC** (concat all fold test predictions)
- **Mean ± Std** across folds
- **IC-IR** = mean / std
- **t-statistic vs 0** with p-value
- **Per-horizon comparison**: is h=60 or h=600 the winning horizon?

### Backtest (per horizon, using `BacktestEngine`)

- Fee: 4 bps round-trip (Binance taker)
- Slippage: 1 bps per side
- Position sizing: confidence-based (`|q50| / (q90 - q10)`)
- Newey-West HAC correction with `overlap_ratio = horizon_sec / stride`

### Pass criteria

- **Primary**: Pooled OOS Pearson correlation ≥ 0.12 on h=180 (vs Ridge 0.099)
- **Secondary**: At least 3 of 4 folds show test_corr > Ridge's 0.099
- **Tertiary**: Weighted Sharpe > 1.0 on best horizon

If primary fails: revert to Ridge-based signal for production, document V4 as research prototype.

## Implementation Phases

### Phase 1: Data Pipeline (estimated 8-10h wall-clock)

1. Modify `compute_microstructure_features` to add 6 ridge-informed features.
2. Create new module `compute_regime_prior_features` (6 features, strictly causal).
3. Modify `build_npz_for_day` to accept `horizons_sec` AND output `regime_prior` field.
4. Regenerate all 1004 days' NPZs. ~5-6h background, requires deleting old `npz_dense/`.

### Phase 2: Model (est. 3-4h implementation + tests)

1. Delete MaskNet usage from `DualPathLOBModelV3` → rename to V4 or update in-place.
2. Reorder GDCN to after Linear(64→32).
3. Add `ChannelMixConv1x1` + `AttentionPoolLevels` to `RawLOBEncoder`.
4. Add `AttentionPoolTokens` to replace last-token extraction.
5. Enable PPNet gate (`d_prior=6`).
6. Unit tests for each component + integration smoke test.

### Phase 3: Trainer + Loss (est. 2-3h)

1. Update `LOBDatasetV2.__getitem__` to return `regime_prior`.
2. Update trainer to pass `regime_prior` to `model.forward`.
3. Implement `utility_rank_loss` and `coverage_calib_loss` in `losses.py`.
4. Update `trainer_v2` to use DUL composition.
5. Tests.

### Phase 4: Training + Evaluation (est. 30-40h wall-clock)

1. Create `configs/v4_full.json`.
2. Train 4 folds × ~7-8h each.
3. Run `aggregate_folds.py`.
4. Compare against Ridge baseline and V3 previous run.
5. Write results report in `docs/V4_RESULTS.md`.

### Total Time Estimate

Implementation: ~15h active engineering
Compute: ~40h background training
**Total: ~55h calendar time** (≈ 3 days)

## Risks and Mitigations

| Risk | Severity | Mitigation |
|------|---------|------------|
| NPZ regen takes >10h and crashes | High | Incremental writes, `skip_existing=True`, retry wrapper |
| New NPZ exceeds disk budget | Medium | Monitor; have fallback to drop some X_raw levels (25→15) |
| Multi-horizon loss gradient conflicts | Medium | Start with quantile-only, add utility_rank after basic run converges |
| PPNet gate over-fits to regime prior | Low | Dropout in gate; ReLU bound scale |
| AttentionPool over 120 tokens increases compute | Low | Single-head attention, d=32, trivial cost |
| Still underperforms Ridge after all changes | Medium | Accept Ridge as signal source; V4 is research learnings |
