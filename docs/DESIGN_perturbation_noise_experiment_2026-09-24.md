# 设计:扰动噪声实验 —— 2.835 / 0.935 bps/日里有多少只是噪声

## 0. 要回答的问题(lead 2026-09-24)

> 「更关键的问题是:这 2.83 / 0.93 bps/日有多少只是模型扰动的噪声。要回答它,需要测『扰动噪声』的分布。」

**先把这两个数字的含义钉准**(我今天在这里犯过标签错误,已更正):**2.835 与 0.935 分别是 s42 与 s2027 两个种子各自在 pre-2026 判据窗上对 NEW_S 的缺口**。**0.935 不是 2026 年的缺口。** 2026 段单独用冻结 `dbar` 实测是 **−0.367 bps/日**(242 完整日,CI [−3.72, +3.67])。

所以本实验要放进分布里读的是**两个 pre-2026 的数**:**+2.835** 与 **+0.935**。

## 1. 已经知道的,和还不知道的

**已知(`KING_REFIT_PERTURB.json`)**:把训练行改动 **0.047%**(136 行),King 的 P 就与 NC 差到「研究员那一档」(锚内秩相关中位 0.7894,参照 0.7802)。**分数层的扰动敏感性已经确立。**

**未知**:这种扰动在**书层**造成多大的 `dbar` 离散度。分数层差异不等于书层差异(在案「排序≠净额」五例)。**本实验只测这一件事。**

## 2. 臂与扰动

- **固定**:NC 特征(`NC_FEATURES.npz` `3c886a2b`)、标签、折边界、宇宙、执行配置,全部不动。
- **扰动**:King 训练的 `random_state`,K 次取 K 个不同值(`0` 已是基准,故取 `1..K`)。

**为什么用 `random_state` 而不是行扰动**:两者在分数层已被证明落在同一档(重拟合臂 (a) 是行扰动、臂 (b) 是特征扰动,都落到 0.79–0.83)。`random_state` 是**唯一变量最干净**的旋钮——它不改变任何输入数据,因此"扰动"的定义没有歧义。**行扰动可作为敏感性,但会额外引入"扰动了哪一行"的自由度,首轮不做。**

## 3. 每次必须走完整管线(lead 的耦合约束)

```
King(扰动 random_state) → 腿(nc_legs) → F10 s42 重训 → 组合 → 适配器 → 引擎 base 格 → 读数 → dbar
```

**F10 必须每次重训。** 理由(lead 原话):F10 训练时读的 `WL` 由含 King 列的 `LR` 算出。King 一变,`LR` 变,`WL` 变,F10 的训练输入就变。**不重训 F10,得到的就是管线产不出的组合**,那样测出来的离散度不是真实管线的离散度。

## 5. `/dev/shm` 策略:跑完即腾,峰值不叠加

- 当前空闲 **约 2.6 GiB**(与 `fresh` 共用同一块盘)。
- **串行跑**,每次跑完:先取出 `dbar` 与读数 JSON、**核 sha 落盘到研究仓**,再删除该次的 `runs/`、`work/f10_*`、`work/king`、`targets`。
- ⇒ **峰值 = 基线 + 一次运行的 0.475 GiB**,不随 K 增长。
- 每臂开跑前照 `shm_gate.py` 实测 df,预计写入 0.475 + 1.0 GiB 余量不够就等,**不挤、不删别人的东西**。
- GPU 按用户规则:**只在别人不用时用**,每次开跑前查占用。

## 6. 报什么(先于数字)

- 每次运行的 `dbar(perturbed_i, NC)`,口径 = 冻结 `news_stats.py` 的 `dbar`,**pre-2026 段**(与 2.835 / 0.935 同段,不跨段);
- K 个值的**中位数、SD、min/max、四分位**;
- 把 **+2.835** 与 **+0.935** 放进这个分布里,报它们的**分位位置**;
- 同时报 2026 段的同一分布与 **−0.367** 的位置(因为 2026 段的在役表现同样要判);
- 每次运行的 30 日块区间**不报**——K 次之间的离散度本身就是要测的量,再叠一层块自举会混淆两种不确定性。**这一条先写死。**

## 7. 判读规则(冻结于数字之前)

1. 若 **+2.835 落在扰动分布的常见范围内**(比如 |z| < 1.5)⇒ **该缺口无法与"一次模型扰动"区分**;不得说研究员的方案更好。
2. 若 **+2.835 明显在分布之外**(|z| > 3)⇒ 缺口**不是**扰动噪声可解释的,需要另找机制。
3. 中间区 ⇒ 写「分辨不出」,**不挑一边**。
4. **K 次是同一种扰动的 K 个样本**,只刻画 `random_state` 这一种扰动;行扰动/特征扰动的离散度**未测**,不得外推。
5. 本实验**不产生换装建议**。它回答"缺口有多少是噪声",不回答"该上哪个版本"。

## 8. 红控制

- **基线格**:K 次里包含一次 `random_state=0`,其 `dbar` 必须与在案 NC 的 `dbar` **逐位相同**(同一输入同一种子必须复现)。不同即说明管线不确定,**整个实验作废**。
- **变异格**:`random_state=1` 的 King P 必须与 `random_state=0` 的 **不同**(否则种子没接上,测的是零扰动)。
- 两格任一不过 ⇒ 不继续跑剩下的 K−1 次,**省算力并报告**。

## 9. 具名不测

- 行扰动 / 特征扰动的离散度(只测 `random_state`);
- 成本格(fee/slip/fill)与 `lit`:只跑 `base` 格;
- 种子 s2027 的管线:只跑 s42(F10 GPU 成本翻倍);**所以 0.935 只能作为"另一个种子的点"放进 s42 的分布里读,这是一处不对称,必须写在结论旁**;
- 书层机制:本实验只给离散度,不给机制。
