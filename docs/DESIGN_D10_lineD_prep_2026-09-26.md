## 1. 第 (1) 项:资金费特征重建装置

### 1.1 输出的四列(lead 指定)
`fund_now`、`fund_ema`、`rn8`、`iv`。范围 **2022-06 → 2026-08**,九月留接口(§1.4)。

**每列绑到消费它的那一行**,不按名字对齐:
- `fund_now` / `fund_ema` / `iv` ← `NEWS_FEATURES.npz` 的 `fn_v` / `fe_v` / `iv_v`,**CSR 成员条目**(2,785,754 条,由 `off`/`m` 索引),float64;

⇒ **两种表示、两种 dtype**,重建产物必须**同形同 dtype**,否则线 B 的门在形状上就对不上(这正是我在线 B 里必须写布局断言的原因)。

### 1.2 真值接口(源无关)
```
class MsLedger:                       # 毫秒键
    def events(symbol) -> [(ft_ms:int, rate:float, declared_iv:float|None)]  # 严格递增
```
实现之一由 lead 的裁定决定。装置只依赖这个接口 + **`common/funding_interval.py` 的 `interval_d10`**(import,不重实现)。

### 1.3 计算,逐步绑到冻结件
1. **as-of**:该名在锚 A 前(含)**毫秒最大**的那笔(lead 修订 1:「as-of 取毫秒更晚者」);同一秒多笔**全部保留**,`UNRESOLVED_NON_INCREASING_TIME` 逐笔具名计数;
2. **`iv`** = `interval_d10(prev_ft, ft, declared)`(线 A);层级(`SPACING_EXACT`/`CLAMPED_*`/`DECLARED_*`/`UNRESOLVED_*`)**逐笔计数进收据**;
3. **新鲜度门** = `nc_contract.py:95` 的 `FRESH_S = 43200`,超龄 ⇒ 四列全 NaN(与在役同),**不得默认 0 或 8**;
4. **`rn8`** = `rate * 8 / iv`(`nc_contract.py:98`);
5. **`fund_ema`**:**必须调用在役的 EMA 累加代码**,不得按描述重写 —— 线 B 已测出两个实现之间存在 ~1e-12 的累加差异,而按 lead 裁定那种差异**本身就是红**。取法同 `nc_legs.py` 的 `H.set_tree(TREE)`(直接重放生产者树)。

### 1.4 九月接口
`--month-source` 可分月指定来源;九月在**十月初归档发布后**填。**P2 账本本身止于 2026-09-01T02:00Z**,所以九月在任何方案下都要等归档(runbook §8b),不是装置限制。

### 1.5 必报(不作门)

## 2. 第 (2) 项:「只换资金费特征」对照格

### 2.1 构造
King 与 F10 **权重不变**(用已交付的 s42 等种子),只把喂进推理的资金费特征换成重建值,走**同一条** `combo` + 引擎(同 32 路径、同 `dbar` 冻结口径)。即独立复审 Q2 四格里的「模型旧 × 数据新」那一格。

### 2.2 它回答什么
**在模型固定的前提下,修数据本身把书层读数移动了多少。** 这是唯一能把「修数据的效果」与「重训的效果」分开的格 —— 四格里另外三格(旧×旧、新×旧、新×新)各自都做不到。

### 2.3 它**不**回答什么(必须写进结果件,否则会被误读)
1. **不回答「修数据是好事还是坏事」。** King 的 OOF 与 F10 的权重是**在旧(受污染)特征上拟合**的;把推理输入换成新特征 ⇒ 模型面对的是**与其拟合分布不同**的输入。所以这一格**可能比旧×旧和新×新都差**,而这**不能**读成"修数据有害"。**这是本格最容易被误读的一点。** 已有同向先例:干净输入上重训反而更差(pre-2026 −9%/−16%),说明这条链上"更正确"与"更好"不是一回事。
2. **不回答实盘影响。** 在役生产者仍用 `snap_interval`,要到十月重建才改用 D10 规则 ⇒ 本格是研究侧的,不是实盘反事实。
3. **不回答九月。** 九月无归档(§1.4)。
4. **不回答"哪一列贡献多少"** —— 四列一起换。若要分列,得再开四格;**不要**从合并结果里推单列贡献(三信号不可加已有在案)。

### 2.4 必报
双列(对 T0 / 对在役 NC s42)、逐段(2026 段为主、pre-2026 不得变差,按 DL 书层门修订 4)、四通道分解 + 闭合、换手、发布率、**以及 §1.5 的重建层计数** —— 让"数据移动了多少"与"读数移动了多少"能对上。

## 3. 第 (3) 项:线 B 门在重建产物上的首次正式运行

### 3.1 顺序(不可调换)
1. **基线绿**:重建产物对自身 ⇒ 每列 0 DIFFER(证明比较器不自造差异);
2. **正控**:每列注入**该列自己 dtype 的 1 个 ULP**(float64 列与 float32 `rn8` 列**各自**测)⇒ 必须检出,否则门作废;
3. **才是正式判**。

### 3.2 两侧是什么
- **训练侧** = 重建产物;
- **实盘侧** = **同一份 `interval_d10` + 同一份 EMA 累加代码**在生产者树上跑出的值(`H.set_tree(TREE)`)。
**两侧必须调同一个函数** —— 这是 lead §2 的第一条,也是为什么 ~1e-12 的累加差异**照样判红**:它是"两侧不是同一实现"的证据,不是可容忍的噪声。

### 3.3 逐列 dtype(判等在该 dtype 上)
| 列 | dtype | 依据 |
|---|---|---|
| `fund_now` / `fund_ema` / `iv` | float64 | `NEWS_FEATURES` 存 float64;与归档同源十进制,**无需容差**即可逐位相等(fresh 实测) |
| `rn8` | **float32** | `legs.npz` 的 `RN8` 是 float32;**在 float64 上用 1e-12 判会在正确数据上失败**(面板侧实测差 1.264356e-11) |

### 3.4 人口与必报
人口 = 当锚**书成员**(`members[i] = m[off[i]:off[i+1]]`,**不是** `cand = mask & crypto`)。必报:原始格数与**成员触及数**、三类拆分(`NaN` vs 有限 / 两侧有限按 |diff| 分桶)、逐列 dtype、控制结果、以及**装置与门的 sha**。

### 3.5 红即停
任何一列不等 ⇒ 研究侧不重训、不出书层读数;实盘侧不发布新生产者。**不许放宽容差绕过**(lead §2)。
