## 1. 线 A:真值规则

### 1.1 费率
交易所归档 / P2 `ledger_full` 的 `rate`,**原值,不做任何舍入或重标定**。

### 1.2 间隔 —— 按**实际结算间距**,分层由 `common/funding_interval.py` 决定

lead 的裁定原话:"间隔按实际结算间距;非标准间距(如 3h)按你已有的 `common/funding_interval.py` 分层处理"。落地为:

```
iv_gap = (ft[k] - ft[k-1]) / 3600        # 实际间距,需要 k>=1
iv_gap ∈ ALLOWED_IV  ⇒ 用 iv_gap                    (EXACT_BY_SPACING)
iv_gap ∉ ALLOWED_IV  ⇒ UNRESOLVED_NONSTANDARD_SPACING:具名、计数、逐年报,不 raise 不猜
k == 0(无前驱)     ⇒ 间距不可算:具名为独立一类,不得当成 0 也不得当成默认 8h
```

**`ALLOWED_IV` 必须 import,不得重述。** 权威值是 `common/funding_interval.py` 的 `(1.0, 2.0, 4.0, 6.0, 8.0)` —— **含 6.0**。我今天在 `d10_legs_rn8_vs_archive.py` 里重写成 `(1,2,4,8)`,漏了 6.0,**4 个 as-of 行被错标**(标准 76→80 / 非标准 74→70;28 个已判 UNRESOLVED 全是 3.0h,所以**没有判词移动**)。修法是 `from funding_interval import ALLOWED_IV`,并在找不到模块时**抛错**,不回落到本地副本 —— 回落正是漂移的来源。收据 `03338fe83`。

### 1.3 为什么是间距而不是归档的 `funding_interval_hours` 列 —— 实测,不是偏好

**过渡行上这两者不一致**,而列是**前瞻的**:

| 名 | 锚 | 列 | 实际间距 | legs 用了 |
|---|---|---|---|---|
| DEXEUSDT | 2026-08-07T08:00Z | 4.0 | **2.0h** | 2.0 |
| ACEUSDT | 2026-08-10T04:00Z | 4.0 | **2.0h** | 2.0 |
| PROMUSDT | 2026-08-14T12:00Z | 4.0 | **2.0h** | 2.0 |
| COTIUSDT | 2026-08-31T20:00Z | 4.0 | **1.0h** | 1.0 |

四例全是**某币刚退出 1h 尖峰回到 4h 的那一刻**:列写新制度的 4.0,而这笔钱实际只累计了 2h(或 1h)。用列会在**恰好是尖峰退出**的地方把 RN8 **低估 2–4 倍** —— 而尖峰退出正是资金费腿做空的人口。**我第一版期望用的是列,判出 4 格"分歧",实际是我错、工件对**;`legs/expected` 恰好是 ×2/×2/×2/×4 的整数比是那个提示(差异全在间隔,不在费率)。

**跨 6 个月的分布**(`D10_LEGS_RN8_VS_ARCHIVE.json`):列≠间距的 as-of 行 **150** 个,其中间距为标准值 **80**(在役件全部跟间距)、非标准 **70**(可比的 28 个回退到列)。⇒ **规则不是"永远用间距",是"标准间距用间距,非标准具名未决"**,这正是 §1.2 的分层。

### 1.4 必须分开的两类(不得合并)
- **`ft` 不同** ⇒ as-of **卡住**(取数/推进问题);
- **`ft` 相同而值不同** ⇒ **口径/间隔**问题,不是卡住。

这条不是理论:实盘 44 锚里唯一的非 AGREE 两格正好各占一类 —— ONEUSDT 09-18T04:00Z 是前者(冻结,`−0.02 @ iv=8`),ONEUSDT 09-22T12:00Z 是后者(同秒同费率,`iv` 2.0 对 4.0)。**合并这两类会让后者消失在前者里。**

## 2. 线 B:训练/实盘逐位平价门

### 2.1 同一函数,不是同一描述
平价必须 **import 并调用**生产者的那一段,不得按描述重实现。已有可抄的形态:`nc_legs.py` 用 `H.set_tree(TREE)` 直接重放生产者树;`news_fund_replay.py` 用 `compile(lines[450:484])` 逐字编译生产者源码行并断言 `sha` 与边界行。**按描述重实现会错掉符号/恒等式/算子,且偏向录取**(已在案)。

### 2.2 同一数据表示 —— 这条比"同一函数"更容易漏
比较必须在**较粗那一侧的 dtype** 上做,**口径绑定文件**,不是挑一个容差:

- 归档发布的是**精确十进制**(`-0.00039508`);宽面板存 **float32**,加宽后是 `-0.00039507998735643923`;**float64 下差 1.264356e-11**。
- ⇒ 对面板做 `abs(a-b) < 1e-12` 的"逐位"测试,**在正确数据上必然失败**。fresh 今天先踩了这个坑,报 0/12,并打算把容差绑到**参照的打印精度**上 —— 那会**碰巧通过而一般是错的**(参照精度与存储精度是两件事)。正确做法:`np.float32(a) == np.float32(b)`。
- 反面:NC 的 `fn_v` 是 **float64** 且与归档同源十进制,它与真值**在 float64 上就逐位相等**,连容差都不需要(fresh 实测)。⇒ **dtype 是逐列事实,不是全局设定**,设计里要求**逐比较量声明它在哪个 dtype 上判**。

### 2.3 正控必须看得见 1 ULP —— 且 ULP 要用**目标数组自己的 dtype**
我今天 `CONTROL_FAIL` 一次:对 **float32** 数组注入 `math.nextafter(x, inf)`(float64 的 1 ULP),存回去**round 回原值**,控制空转。修法 `np.nextafter(np.float32(x), np.float32(inf))` + 断言"扰动没塌缩"。实测可见的 float32 ULP delta 为 **7.28e-12** 量级。

### 2.4 控制清单(每条各管一件,缺任一条都留一个"0 不可解释"的洞)
1. **基线绿先行**:同一输入喂两遍必须 100% 一致(实测 17,600/17,600 AGREE)—— 唯一能揭出"比较器自己造差异"的一步;
2. **每条变异红在自己那条具名类上**,不接受"有东西红了";
3. **注入物必须真的走到被测那一段代码**:我有一次注入落进了更早的覆盖桶,控制什么都没测到;判别法 = 看它**落进了哪个计数器**;
4. **控制之间必须隔离**:一个控制覆盖另一个控制的格 = 静默取消它(我因此让套件**以错误的理由**失败一次);
5. **零值只有在该类曾经响过时才算证据**:`legs_nan_BUT_MEMBER` 的 0 是在控制把它打红之后才认的;
6. **扰动不得搬动人口**:要造"A 有而 B 没有",必须从**被搜索**的那一侧删,而不是从**定义人口**的那一侧删(否则只是分母变小);
7. **控制跑的收据判词必须改写在判词计算之后**,否则会留下一句可被当成真实缺陷引用的话(我留下过 `P2_LEDGER_HAS_ABSENT_SETTLEMENTS`)。

### 2.5 平价的人口
**先断言复现一个已知数**再判任何东西(FX 侧是 5,613)。我漏过这条一次:分歧定义多算了"一侧 NaN",报出 **453,428** 个"FX 格",比真人口大 ~44.8 万。**复现已知数是让人口可核的东西。**

## 3. 线 C:实盘 T+1 对账与告警

### 3.1 对账量(逐锚 × 逐名,限当锚书成员)
`used`(生产者当锚实际用的 as-of)对 `correct`(T+1 已知账本的 as-of),按 §1.4 分两类,并报:落后秒数、书内权重与方向、该锚成员格数作分母。

### 3.2 参照口径的自陈弱点(必须写进每份产出)
T+1 的 `correct` 若取**同一生产者后来的账本**,它能抓"这个锚漏读了后来已知的结算",**抓不到**"这笔结算生产者从头到尾没收到"。⇒ 判词写"**相对事后已知账本**",不写"相对交易所真值"。要拿到后者,只能等月度归档(M+1 月初)。

### 3.3 硬依赖:逐锚留存(**这是 C 现在做不全的原因**)
- `~/wide_shadow/state/snap/<anchor>/` 实测 **49 个快照,首个 2026-09-17T12:00Z**;
- `aux.json` 在 49/49 里都有;**`members_hist.npz` 只有 9/49**(所以成员来源要用 `prev_rec`,或 dlarch 的 `NEWS_FEATURES` 构造);
- `ledger_tail` 每名只留**最后 400 行**(`shadow_loop_v3.py:421`)⇒ 1h 尖峰名约 17 天就被截断;
- ⇒ **09-11..09-17T12:00Z 无留存状态,不可恢复**(集成代理在 `ac0f2c115` 独立撞到同一边界)。

**设计后果**:T+1 对账只能对**有逐锚留存的锚**成立,且窗口随 400 行尾窗滚动。要让它长期可用,`DESIGN_live_funding_ledger_archive_2026-09-25.md` 那个归档作业**必须部署**(仍未部署,待 lead)。**本设计不假设它已存在。**

**原始格数与触及书的格数是两个量,必须同时报,且以后者为影响口径。** 今天三处独立实测同形:

| 线 | 原始 | 触及书 |
|---|---|---|
| FX 错格(news2) | 5,613 | **191(3.40%)**,39 锚,135 格集中在一个锚 |
| RN8 分歧(fresh) | 404 | 夹子人口只移动 **16** |

| 实盘 as-of 卡住(news2) | — | **1 / 17,600** |

**成员集必须用 dlarch 的构造**:`members[i] = m[off[i]:off[i+1]]`(`NEWS_FEATURES.npz`),**不是** `cand = mask & crypto`(那是可交易/候选掩码,是另一个量)。用前断言:轴同序、`count[i] == off[i+1]-off[i]`、最大索引 < 符号数。

**⚠ 一条今天被我自己推翻的、不要写进结论的话**:那个"135 格集中在一个锚"**尚未被解释**。我曾写"是大量结算同时落地的锚上的群体性漏取",实测后撤回 —— 逐 4h 锚恰好在该秒结算的符号数**中位 541 / p90 583 / 跨 1,092 锚**,即**同时结算是常态**,解释不了任何特定锚。**普遍存在的东西不能当特定现象的原因。**
