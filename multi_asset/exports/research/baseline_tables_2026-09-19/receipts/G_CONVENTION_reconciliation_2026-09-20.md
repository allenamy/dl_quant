# g(bps / 锚 / gross)的口径对账 · HIST 2023-06-30 → 2025-12-31

**装置** `devices/bt_g_convention.py`(只读 PATH 文件, 不做任何模拟), 收据 `receipts/pod2/receipts/BT_G_CONVENTION_*.json`。
**样本**: 在役配方主读数运行 `OBJB_A0_scaled_rule_raw_UAFE` 的 32 条成交路径, HIST 窗 5,495 个锚。

| 口径 | HIST g | 说明 |
|---|---|---|
| **本项目各表所用**: 逐锚 `g_k = 1e4 · (navm1_k/navm0_k − 1) / gross_mult`(gross_mult = 2.0 ⇒ 分母 = **目标 gross** = 2 × 窗初 NAV), 对**窗内每个锚**取算术平均(持有 / 停机 / 止损锚一个不丢) | **+0.0728** | = 归因代理的 **+0.073** |

| 去掉持有锚 / 去掉停机锚 / 只留有交易的锚 | +0.0728 / +0.0730 / +0.0730 | **人口不是差别来源** |

| 复利摊到锚 `1e4·(Π(1+r)−1)/n/2` | +0.0161 | 不是逐锚率的平均 |
| 不除 gross_mult(对 NAV 计的 bps) | +0.1456 | 量纲不同 |

**结论**: 差别 100% 来自分母 —— **固定的目标 gross(2 × 窗初 NAV)** 还是 **当窗实际 gross**。两者的 gross 水平本身一致(实际/目标 的逐锚均值 0.9995, 中位 1.0004), 差别来自「比值的平均 ≠ 用变动分母的平均」。

**为什么这不是分歧**: 两种口径在各窗上的绝对差 ≤ 0.03 bps/锚 ——
2023H2 −0.7378 vs −0.7659(差 0.028)、2024 +0.4252 vs +0.3980(0.027)、2025 +0.1299 vs +0.0977(0.032)、2026 +2.9876 vs +2.9995(0.012)。
**HIST 之所以看起来分歧大, 是因为 HIST 的 g 本身就在 0.05–0.07 这个量级**(同样的 0.03 绝对差, 在 2026 的 +3.0 上看不出来)。两个数都 ≈ 0, 任何结论不受影响。

**本项目为什么用目标 gross**: 各表的 g 与其分解是同一恒等式 `g = 价格 − 资金费付出 − 手续费 − UNKNOWN`, 每一项都除以同一个 `gross_mult · nav0`; 换成逐窗实际 gross 必须四项同时换, 否则恒等式(实测残差 ≤ 1.3e-10)不再成立。因此 A0 / A0ext 两份表继续用目标 gross 口径, 并在此具名。
