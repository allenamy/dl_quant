## 1. 项目定盘(不可违反)

- **标的**: Binance USDT-perp 多资产横截面, 市场中性多空账本。实盘约 2,150 USDT NAV,
  4h 锚点 00/04/08/12/16/20 UTC。
- **目标**: 账本 rank-IC ≥ 0.07, 净夏普 ≥ 5。
- **信号极弱 (R² < 1%)** —— 容量必须匹配信号。多资产的核心杠杆是 **parameter pooling**
  (params:sample 从 18:1 翻到 ~1:1000), 不是堆容量的借口。
- **机制 > 堆叠**: 每个 feature / module 必须有清晰作用机理 + 过定量门。禁止生硬堆叠。
- **预处理 > 架构**: 特征工程优先级永远高于模型创新。
- **双口径**: 所有实验同时报 Pearson + Spearman; 多资产 headline 是 **xsec rank-IC**。
- **★ IC 是 alpha, β 是量纲**: β = r·(σy/σŷ)。alpha 判定**唯一以 IC / rank-IC 为准**。
  禁止把 β 水平当质量门。真守卫是 **σŷ/σy ≥ 0.02**(塌缩), 不是 β。

### 2.3 bookDepth 的两条硬约束(实测)

**(a) 实盘只有 ±0.2% 那条带可复现。** REST `/fapi/v1/depth?limit=1000` 每侧最多 1000 档,
1000 档在价格上能铺多远取决于书有多密:

```
BTCUSDT ±0.19%   ETHUSDT ±0.55%   BNBUSDT ±1.72%   ...   小币 ±100%
```
±0.2% 带 **127/128 可复现**(唯一失败是 BTC, 只到 ±0.186%, 缺口占该带深度 3.9%);
±1%~±5% 带对 BTC/ETH **实盘算不出来**。而 BTC 归档实测 ±0.2% 深度只占其 ±5% 的 **6.6%**
—— **93% 的深度信息在服务不了的带里**。

⇒ **只训 ±0.2% 带**。宽带训了就是白训(train/serve 断裂, 见 §5 ch31 教训)。

**(b) 绝对深度跨币不可比, 形状才可比。** 同一条 ±0.2% 带, BTC 装其 ±5% 的 6.6%,
而某些小币的 25 档就已超过 ±0.2% 带的 1991%。直接拿绝对深度做横截面排序 =
**在排流动性, 不在排信号**。正确做法是**深度份额剖面**(每带 / 总量)或带间比值 —— 尺度无关。

**(c) 截断偏差是时变的。** REST 截断永远**少报**, 且截断点随书的密度移动、密度随波动率移动
⇒ 若用宽带, 偏差会以"披着流动性外衣的波动率因子"进入模型。横截面去均值**消不掉**
(它是逐币的, 不是逐时刻的)。

### 3.3 lead-lag —— 已自杀, 不要重建

**动机**: 现有 `MultiRelXAttn._corr` 是 `torch.bmm(rn, rn.T)` —— **对称** Pearson 相关矩阵,
`B[i,j] ≡ B[j,i]`, 在数学上**无法表达"i 领先 j"**。看起来是可指认的结构缺陷。

**预注册判据**: 有向结构跨年一致性 > 0.3 才建模块。**实测**:

```
[L1] 滞后 1/2/4/8/24h: 均值|C−Cᵀ| / 均值|C| = 1.06/0.86/1.33/1.20/1.34
     最强"有向对": XMRUSDT→MKRUSDT, ATOMUSDT→TRXUSDT, SNXUSDT→KAVAUSDT ...
[L3] 跨年一致性: 2023vs2024 = 0.028;  2025vs2026 = 0.281   ← 均未过 0.3
```

**判决: 不建。** 三条独立证据: 不对称分量与总相关同量级(纯噪声的签名);
最强"有向对"全是无经济故事的小币随机配对, **BTC/ETH 一个都没进榜**(真 lead-lag 必以它们为中心);
跨年一致性两次都没过线。⇒ **对称偏置没丢掉任何真东西, 那个"缺陷"在实践中不是缺陷。**

## 4. 反模式 —— 必须辩证读, 不可无脑遵循(用户明令)

单资产时代记下的"失败"里, 有相当一部分的**产生机制在多资产下不成立**。
实测过一次: 单资产出处的 regime 结论, 在多资产规模化下 C1 风格 regime **t=+3.31 过线**。

**机制仍成立 ⇒ 遵守**
- σŷ/σy 塌缩守卫(#24) —— 塌缩是任何设定下的真失效
- stride ≥ horizon(#2) —— 标签重叠是算术问题
- Ridge 先于 DL、泄漏纪律、只报 OOS —— 方法论层面

**机制被 pooling 反转 ⇒ 不该照搬**
- **#29「每加 channel −0.013 P」**: 产生于单资产 params:sample = 18:1。
  多资产权重共享后约 1:1000, **产生该惩罚的机制不在了**。
  ⇒ 不要用它预先砍通道数, 按实测增量门决定。
- **regime router 失败**: 单资产出处, 且是**硬**路由; 诊断出的病因是
  "波动率描述子无效, 真正的 regime 是**持仓状态**"。
  ⇒ 现在第一次有了持仓数据。**用持仓做的软门控是不同的东西, 必须重测**, 不能被旧结论拦住。
- **#22 MRP / #23 解耦头**: 单资产的具体模块判决, 非通用定律。

**"天花板"类结论一律重测** —— 那是最容易被经验主义污染的一类。

## 5. 因果性 —— 唯一不可协商的约束

用户原话: **"千万不能有任何形式的特征泄露和违反因果性"**。这条压倒一切其他目标。

### 5.1 已发生过的真实泄漏(必须知道形状)

  换装后的模型输给了它本该打败的两个对照。教训: **训练用的量若实盘算不出来/口径不同,
  训了就是白训, 而且会以"有效"的面目骗过回测。**
- **`panel_ref` 对 ch31 轴是盲的**: 脏面板与因果面板在 9 个键上 hash **完全相同**
  ⇒ 用 `panel_ref` 验证"无前视" = **假绿**。**因果性检查必须打在产物 SHA 上, 不是元数据块。**
- **vol-scaling 的 ΔNet 是泄漏**: +1.814 → **−0.083** 在 SERVE 口径下。

### 5.2 结构性保证(四条) + 经验检验(一条)

- **S1 构建期**: 每个族在构建时断言滞后。metrics 已做(小时 H−1 → ts=H, 整整一小时边距)。
  **不建 lag0 版本** —— 有了两个版本就一定会有人挑数字好看的那个, ch31 正是这么进来的。
- **S2 架构**: 因果卷积(左填充+裁剪)、注意力因果掩码、**任何地方都不用 BatchNorm**
  (跨全样本的 running stats = 泄漏)。用 LayerNorm(逐样本)。
- **S3 归一化**: 只允许两类 —— **逐时刻横截面统计**(只用 t 时刻, 天然因果)
  或**逐样本**统计。禁止任何跨全样本或跨训练/测试的 mu/sd。
- **S4 掩码**: MEMBER 必须是因果滚动(逐点时 top-N by trailing 30d 成交额, 月度刷新)。
- **E1 经验**: G1 未来相关扫描(|IC vs 未来 24h| < 0.15) + **G1b 时移不对称**
  (对未来的相关不得超过对过去的相关 + 0.05)。G1b 比绝对阈值更灵敏。

  现有设计把一切压平到 1h 标量后拼接。族专用编码器 + **门控融合**(非拼接)是候选。
  ⚠️ 这是**假说**, 不是结论。要先证明扁平拼接确实漏掉了东西(比如 DL 拿不到 Ridge 的 0.0321)。
- **书的深度剖面当函数处理**: 12 带沿带轴做卷积, 捕捉曲线形状(斜率、两侧不对称),
  而非拍成标量。单资产 `RawLOBEncoder` 的 level-conv + attn-pool 是可参考的先例。
- **regime 门控用持仓而非波动率**: 见 §4 —— 旧失败的病因诊断正好指向新数据。

## 7. 操作纪律(踩过的坑)

- **`pkill -f <pattern>` 会匹配到你自己的 ssh 命令串。** 今天我用
  `pkill -f "rp_fetch.py"` 杀掉了自己的会话, 并连带杀死 bookDepth 的父进程,
  子进程成孤儿、接力断链。**用轮询 PID (`kill -0`) 或精确 PID, 不要用模式匹配杀进程。**
- **heredoc 经 ssh 传递会被本地 shell 二次展开。** 复杂脚本**本地写好 + scp**, 不要内联。
- **拉取器必须幂等**(已有文件 skip) —— 今天中断重排零重复下载, 35 分钟进度一点没丢。
- **月度归档比日度少 21-30 倍请求。** klines 类一律用月度。
- **后台任务要 `setsid nohup ... < /dev/null &`**, 且脚本要 `chmod +x` 或用 `bash <script>`。
- **不要用 `du`/`ls` 的输出当完成判据** —— 用 PID 存活 + 日志尾行。
