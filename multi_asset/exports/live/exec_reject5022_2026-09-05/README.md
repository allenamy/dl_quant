# −5022(post-only 穿价)拒单率: 概念、根因、"升高"的真相、处置(2026-09-05)

## 1. 概念
- maker 单以 `round_px(mid_at_anchor, side)` 定价(向己方取整: 买单向下、卖单向上), timeInForce=GTX(post-only)。场所若发现该价会立即成交(买价 ≥ 当前最优卖价), 拒单并返回 −5022, 不入历史。
- 这是"我们自己的规则(不穿价)被场所执行"的结果, 不是订单构造错; 自 08-02 起按政策恢复: 先一次新鲜盘口重报价(attempt 2, post-only), 仍拒则在 k 窗末(N+24+15 分)按残差 IOC taker 补单(`topup_source=from_reject`)。

## 2. 根因(拒单本身为何发生)——受据
| 证据 | 读数 | 来源 |
|---|---|---|
| 一次 bookTicker 快照定价全宇宙, 逐单顺序提交 | 提交跨度 30–110 s/锚(计划→首单延迟仅 0.2–1.4 s) | out_v2 `span_s`/`lat_s` |
| 拒单率与提交跨度同向 | Spearman(真实率, 跨度) = +0.37; 与单数 +0.24 | out_v2 |
| 点差越窄越易被穿 | <2 bps 26.5% / 2–5 bps 24.0% / 5–10 bps 17.4% / 10–20 bps 15.8% | out_v1 spread 表 |
| 离触价远一档就少被穿 | join 25.7% ±1.0 vs behind 18.8% ±1.2(bandit 两臂, n=6937/4177) | out_v1/v2 arm 表 |

| 买卖平衡(非取整缺陷) | 逐锚 buy%/sell% 交替 | out_v1 |
结论: 拒单率 = 盘口陈旧(秒级)× tick 粒度 × 名的瞬时波动 的函数, 对 1-tick 点差的名, 逆向 1 tick 即穿。它是成本/质量表, 不是"书未达目标"信号。

## 3. "升高"的真相(E-0905-H)
- 告警行 `场所拒单 N/M` 的分母 M = 告警时刻已写的行 = **被跳过的计划(低于最小名义等)+ 被拒的 maker**; 已落单的 maker 直到终态才写行, 不在分母; 一名首拒+重报价再拒计两次。
- 复现: 09-04 12Z→09-05 08Z 六锚告警比 42.0/47.2/17.1/37.6/48.4/46.5%(与页报逐锚相同), 同六锚真实首次拒单率(行口径)26.2/21.2/13.8/19.5/21.7/32.7%, 名口径 26.8/31.7/25.0/15.8/22.7/26.2/42.4%(09-04 12Z 起 7 锚)。
- 09-03 入金 gross 翻倍后低于最小名义的跳过行从 213/锚降到 107/锚 ⇒ 分母缩小 ⇒ 告警比从 24% 升到 33%, 真实率 22.5→21.0→21.6%(行)/26.9→25.4→26.0%(名) 持平。Spearman(告警比, 跳过行数) = −0.96。
- ⇒ E-0903-D 的跟踪规则("持续 >40% ⇒ 升级为执行缺陷")建立在这个比值上, 差点把分母效应升级成执行缺陷。
