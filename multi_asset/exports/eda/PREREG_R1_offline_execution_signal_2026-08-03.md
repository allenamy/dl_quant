# PREREG — R1 离线执行信号研究(纯离线, 零实盘, 零 API 限额)

**本文不碰交易路径、不碰任何已冻结件、不消耗任何交易所限额。** 它把 RESEARCH §8 的研究计划变成一个**可证伪、可复算、且事先把失败长什么样写死**的方案, 并给出 R3(微观门接实盘)的 GO/NO-GO 判据。

**R1 本身不产生任何实盘动作。** 它的唯一产出是"这个信号存不存在、够不够格进 R3"这一判断。**R1 判 NO-GO 不阻塞 R2** —— 两者互不依赖(但见 §7-4 的一处反向依赖, 那是本文发现的)。

**⇒ 后果, 必须写在设计之前: 「此刻跨价差 vs 再等一个决策周期」这个标签, 在自有账本里【只有一条腿被观测过】。** 我们**从来没有等过** —— 900 秒到点就无条件扫。**那条"等一个周期会成交在什么价"的反事实腿, 账本里一个观测都没有。**
⇒ **它必须从市场数据重构, 不能从账本读。** RESEARCH §8.2 把自有账本列为"标签"来源, 那只对**已发生的那一腿**成立。

RESEARCH §8.5: 「110 名 × 6 锚 × 90 天 ≈ **59K** 个锚-名决策观测」。**实测:**

**⇒ 59K 这个数把两个不同的轴乘在了一起:**
> **aggTrades 有 90 天历史但没有我们的标签; 我们的标签有 110 名但只有 3 天。「110 名 × 90 天」在市场数据轴上成立, 在标签轴上不成立 —— 两者不能相乘。**

**这与上一份预注册里「~40 名」那条是同一族: 一个总体的计数, 被用在了另一个总体上。**

## 2. ★ 由 §1 被迫的设计: 两层标签, 且只有第二层能判 GO

**这不是一个选择, 是 §1-2 与 §1-3 的直接后果。**

### 2-1 L1 —— 市场重构标签(**开发层**, 不判 GO)

```
对任意 (名字 i, 时刻 t, 决策周期 Δ, 方向 s∈{buy,sell}):
  cross_now(t)   = 从 t 起、以 s 方向、按 aggTrades 逐笔吃掉名义 V 所得的成交均价
  cross_later(t) = 同样的算法, 但从 t+Δ 起
  L1 = s × ( cross_later − cross_now ) / mid_ref      [bps, 正 = 等待更好]
```

- **可对任意 (名字, 时刻) 计算 ⇒ 90 天 × 110 名, 百万量级样本。**
- **★ 它对我们自己的执行政策免疫** —— 不含任何 `policy_version` 依赖。这正好躲开了追价预注册里把成本侧钉死的那个问题(`PREREG_chase_opportunity_cost_2026-08-03.md` §6)。
- **但它是代理, 且代理误差不是随机的**: 它忽略**排队位置**与**我方冲击**, 而这两样恰恰是执行信号要预测的东西的一部分。
  ⇒ **在 L1 上调优会系统性偏向"忽略排队"的特征。** 这不是"精度差一点", 是**方向性偏倚**。

### 2-2 L2 —— 自有账本标签(**判据层**, 只有它判 GO)

真实决策的真实成交价: 已发生的那一腿取 `avg_fill_px`, 未发生的那一腿按 §2-1 的算法从 aggTrades 重构。**薄(≈94/天)且只能向前攒。**

### 2-3 冻结规则

| | |
|---|---|
| **L1 的唯一用途** | 特征筛选与模型定形(选哪些族、什么容量、什么窗口) |
| **L2 的唯一用途** | **GO/NO-GO。L1 上的任何优胜不构成 GO, 一次都不。** |
| **明禁** | 用 L2 做特征搜索或超参扫描(它太薄, 扫一遍就用完了) |

**⇒ 并预注册一条【迁移检验】, 因为"L1 上有效 ⇒ L2 上有效"是一个假设, 不是一个推论:**
```
迁移检验: 在 L1 上训好、参数完全冻结的模型, 在 L2 上的 rank-IC
          必须 ≥ 0.5 × 它在 L1 同期上的 rank-IC, 且符号相同。
不通过 ⇒ 代理失效 ⇒ R1 判 NO-GO, 不得以"L1 很好"为由放行。
```
**0.5 这个数是政策数, 现在定死以免事后调。裁定(team-lead, Q6): 0.5 采纳; L1 可用于特征筛选【与】超参选择(两者都在开发层); ★ 但【迁移检验必须在 L2 密封期结束后一次性跑, 不得反复试】。**
**★ 后一条是本检验能作数的前提, 不是一句补充: 一个可以反复跑的检验, 其"通过"只说明试了足够多次。** ⇒ 落地上须留痕 —— 迁移检验的运行必须写一行审计(时刻/模型哈希/L2 窗口), 使"跑过几次"事后可查, 与追价读数门的 override 审计同一形态。

## 3. 事件时钟(§8.4-1 的操作化)+ 一个它没有处理的角落

**特征窗按【最近 N 笔成交】或【最近 V 名义额】定义, 不按墙钟。** 理由(RESEARCH §8.3 实测): 「20 笔」在 RATS 与 SOL 上携带同等信息量, 「60 秒」相差 20 倍。

### 3-1 ★ 那个角落: 事件窗在薄币上会**静默地跨越 regime**

RESEARCH §8.3 实测 `1000RATSUSDT` **每天有 107 分钟一笔成交都没有**。⇒ 「最近 20 笔」在薄币上可能回溯**数小时**, 窗口跨过完全不同的市场状态, 而**特征值本身看不出这件事**。

**处置(先写死, 用的是本项目已有的纪律而不是新发明):**
```
特征窗 = 最近 N 笔, 且回溯不得超过墙钟上限 T_max
若回溯到 T_max 仍不足 N 笔 ⇒ 该 (名字, 时刻) 的特征【无定义】,
                              不入样本, 并计数上报
```
> **「量在边界上失去定义时, 宣布它无定义, 不给近似」** —— 近似会被下游引用, 而没人记得它是近似(journal 2026-08-03 §4-6, 同族第三次)。

**⇒ 明禁: 不得用"补零"、"用上一个值"、"放宽到 N' < N 笔"来填这个洞。** 前两者制造假特征, 第三者使不同名字的特征不可比 —— 而可比正是事件时钟存在的理由。

**裁定(team-lead, Q1): `T_max = 4Δ`, 采纳。** 理由: 它是一个**因别的原因已经存在的量**, 不是从数据里挑的; 与追价预注册里 regime 切点取自 `NEUTRAL_BAND`/告警带 是同一手法。

### 3-2 无定义率是必报项, 且它是分层表的输入

逐名报告无定义率。**若某名字的无定义率 > 50%, 该名字在当前 Δ 下【没有可用的短周期信号】** —— 这是一个结论, 不是一个待修的缺陷, 且它正好指认出"该用更被动策略"的那批名字(§8.4-3)。

## 7. R3 的 GO/NO-GO 判据

### 7-1 ★ 先解决一处上游冲突: 「30 秒」还是「180–300 秒」

- RESEARCH **§6** 写 R3 的前置是「R1 通过定量 gate: **30s** 方向 AUC/IC 显著且跨名稳定」。
- RESEARCH **§8.4-2** 写「决策点 **~180-300 秒**一次, 不是 30 秒」, 且 §8.3 的实测(薄币 60 秒窗中位 5–8 笔)**正是用来否定 30 秒的**。

**裁定(team-lead, Q3): 按 §8.4(180–300 秒), 采纳。** team-lead 附记: §6 的 "30s" 是其本人所写, 而 §8.3 的实测正是用来否定它的; **RESEARCH §6 由 team-lead 同步改, 不由本文改。**
**★ 并升为通则: 【一份文件内部两处数字冲突时, 以有实测支撑的那一侧为准】。** 本文另记一句配套的: 这类冲突若不在引用它之前对出来, 下游会各自引用其中一处, 然后谁都不知道分歧是从哪来的 —— **而那时两边都能举出"文档里写着"作为依据。**

### 7-2 GO 需要四条全部满足

| 门 | 内容 |
|---|---|
| **G1** | **L2 上** rank-IC 与预期方向一致, 且**经验零分布 z ≥ 2.5** |
| **G2** | **跨流动性层稳定** —— 按 F5 分层, **每层符号一致**, 无层反号 |
| **G3** | **净成本可行** —— 信号带来的成交价改善 **> 实施成本**(含 R0 归档与计算开销), 用 bps 计, 不用美元(阈值要跨规模存活) |
| **G4** | **迁移检验通过**(§2-3: L2 rank-IC ≥ 0.5 × L1 rank-IC, 同号) |

**四条缺一 ⇒ R3 NO-GO。**

### 7-2bis ★★★ L2 判 GO 的最短积累 —— 按【有效标签数 + regime 覆盖】, 不按天数(team-lead 裁定 Q4)

**裁定的形状先说清楚, 因为它和 N\* 是同构的:** **天数是可变的世界状态**(每天几个锚、每锚几个带价补单, 都会随宇宙、地板、行情变); **有效标签数与 regime 覆盖是结构性事实**。⇒ 门必须写在后者上。(与追价预注册里"读数门是状态不是计数"同一条道理。)

#### (a) 有效标签数 —— 功效算法与结果

估计量是 L2 上的 rank-IC。用 Fisher-z, `z = arctanh(ρ)·√(n−3)`; 要以 **80% 功效**达到 **G1 的 `z ≥ 2.5`**, 需 `E[z] = 2.5 + 0.8416 = 3.3416`:

```
n* = ceil( (3.3416 / arctanh(ρ_min))² + 3 )        ρ_min = 我们要求能分辨的最小 rank-IC
```

| ρ_min | **n\*(有效标签)** | @ ≈94/天 |
|---|---|---|
| 0.02 | 27,912 | 297 天 |
| 0.03 | 12,403 | 132 天 |
| 0.05 | 4,463 | 47.5 天 |
| 0.08 | 1,741 | 18.5 天 |
| 0.10 | 1,113 | 11.8 天 |
| **0.16** | **417** | **4.4 天** |
| **0.21** | **249** | **2.6 天** |

**ρ_min 的选法(锚到一个外部给定的常数, 不从数据里挑 —— 与 Δ=37bps 同一手法):**
```
sign-based 时序规则的每次改善 ≈ 0.798 × ρ × σ(label)        (0.798 = E|z|, 标准正态)
σ(label) 由 4h 横截面 sd 160 bps 按 √t 缩到决策尺度:
    Δ=180s → σ ≈ 17.9 bps        Δ=300s → σ ≈ 23.1 bps
materiality floor = 3 bps  ← maker/taker 手续费差(RESEARCH §1 的成本分解), 交易所给定, 非拟合
⇒ Δ=180s: ρ_min ≥ 0.210 ⇒ n* = 249        Δ=300s: ρ_min ≥ 0.163 ⇒ n* = 417
```
**⇒ 冻结: `n* = 417`(取两个 Δ 中较大者, 使门对 Δ 的选择不敏感)。**

**★ 这条链有三个环, 每个都标出来, 因为整条链的可信度等于最弱那环:**
1. **σ 由 4h sd 按 √t 外推** —— 假设近似随机游走。**未在 Δ 尺度上实测。** 若实测 σ 大一倍, ρ_min 减半, **n\* 变 4 倍**。
2. **0.798 假设标准正态与 sign-based 规则。** 真规则若带阈值(只在强信号时行动), 每次改善更大而次数更少, 净效应未定。
3. **3 bps 的 floor 是【类比】而非【推导】** —— 手续费差是 maker/taker 之别, 而时序信号不改变 maker/taker, 只改变何时 take。**我选它是因为它是手边唯一一个外部给定、与执行成本同量纲、且不从本数据拟合的常数。** 若 team-lead 认为该类比不成立, 换一个 floor 即可, n\* 按 1/ρ² 缩放(表已给)。

#### (b) ★ regime 覆盖 —— 而它才是真正卡住的那一条

**键: 复用追价预注册 §8-3 已冻结的三分**(`|net_over_gross_before|`, 切点 1.5% / 3.0%, 两个切点都取自因别的原因已存在的常数)。**复用而不新造, 理由与 Q7 同: 一个已经要为别的原因存在的键, 多带一个消费者的边际成本接近零; 多造一个就是"一个事实两处存放"。**

**可得性已核实**: `neutral_only.net_over_gross_before` 由 C 的决策产生, **与臂权重无关**(`plan_experiment` 里 `shadow` 独立于 `weights` 计算) ⇒ **即使实验被关掉, 该字段仍逐锚落盘。** 且 L2 本来就只能向前攒(§1-3), 而实验自 2026-08-02T20:00Z 起每锚都在跑 ⇒ **L2 的整个窗口内该键都可得。**

```
覆盖门: 三个 level 中至少 2 个各持有该版本有效标签的 ≥ 15%
```

**★ 实测(冻结时): 三个实验锚的 `|nog_before|` = 3.62% / 7.27% / 7.97%, 全部 > 3% ⇒ 三个锚全落 `running`, 覆盖 = 1/3 个 level。**

**⇒ 由此得到一个本文事先没料到、但值得写下来的结论: 卡住 L2 判 GO 的不是标签数, 是 regime 覆盖。** 标签数 417 只要 ≈4.4 天; 而 `calm`/`normal` 一个都还没出现过, **它们何时出现不由我们控制**。⇒ **裁定 Q4 要求"标签数 + regime 覆盖"两条而不是只写天数, 是对的 —— 因为这两条在完全不同的时刻才满足, 只写天数会让先到的那条冒充两条。**

#### (c) 两条门都是**版本内**的(Q7 的直接后果)

`n* = 417` 与覆盖门**在每个 `policy_version` 内分别计算**。**R2 落地 ⇒ L2 在 v2 内重新起算。** 如实记: 这使 L2 的功效随每次执行层迭代重置, 而这正是 Q7 选择"不阻塞 R2"所付的代价。

### 7-3 失败长什么样(先写死, 命中即 NO-GO)

1. **L1 强、L2 弱** ⇒ 代理失效(排队/冲击是主项), 而不是"样本不够"。
2. **只在流动名上有效** ⇒ 方向反了 —— 真正出问题的是薄币(RESEARCH §8.1-3)。
3. **无定义率 > 50% 的名字占多数** ⇒ 该 Δ 下短周期信号不存在, 不是模型问题。
4. **IC 显著但 G3 不过** ⇒ 与 y180 那次同形(xsec-IC 真实但换手吃掉), 已在册。

### 7-4 ★★ 本文发现的一处**反向依赖**: R2 会重置 R1 的判据层样本

RESEARCH §6 把 R1 与 R2 列为可并行(R1 无前置, R2 需 PREREG 冻结 + R0)。**但:**

> **L2 标签是【政策条件】的** —— 它记录的是"我们在当时的政策下跨价差得到了什么价"。**R2 一落地(re-peg / 升温阶梯 / 时点散开), L2 的分布就变了 ⇒ R2 之前攒的 L2 与之后的不可合并。**

**这与追价预注册里 `policy_version` 的问题是同一个, 只是换了一个量。** 后果是排期性的:
- **要么** R1 的 GO/NO-GO 在 R2 之前判完(但 L2 只有 3 天历史, 攒不够);
- **要么** L2 也必须带 `policy_version`, 分版本估计, 而它比成本侧更薄(≈94/天);
- **要么** 接受 R2 落地即 L2 归零重攒。

**★ 这条不在派工里, 也不在 RESEARCH 的风险清单里 —— 它是写 §2-2 时从"标签从哪来"推出来的。**

### 7-4bis ★★★ 裁定(team-lead, Q7): **L1 先行 + L2 版本化** —— 不归零重攒, 也不让 R1 阻塞 R2

```
L1(特征筛选与模型定形)  → 完全不受 R2 影响, 可立即开工、持续推进
L2(GO/NO-GO 判据)      → 用【与成本侧同一个】 policy_version 键分层
R2                      → 不被 R1 阻塞
代价                    → L2 的功效按【版本内】计算(§7-2bis-c), 每次执行层迭代重置
```

**裁定理由(原文要点, 抄录因为它同时解释了为什么不新造键):**
1. **L1 对我方政策免疫 —— 这正是它最大的价值**(本文 §2-1 已指出)⇒ **特征定形这一步可以完全不受 R2 影响。**
2. **L2 既然必然是政策条件的, 就用与成本侧【同一个】 `policy_version` 去分层** ——
   > **一个已经要为别的原因存在的字段, 多带一个消费者的边际成本接近零; 而多造一个版本键就是「一个事实两处存放」。**
3. ⇒ R2 不被阻塞, **代价如实记在 §7-2bis-c**。

**⇒ 由此, `policy_version`(追价预注册 §6-3bis 已裁为 R2 的硬前置门)现在有【两个】消费者: 追价实验的成本侧, 与 R1 的 L2 判据层。** 这**加强**了那个门的必要性 —— 它落地前上线 R2, 会同时静默作废两个量, 而不是一个。**本文不重复设门; 门在追价预注册 §6-3bis, 此处只登记第二个消费者。**
