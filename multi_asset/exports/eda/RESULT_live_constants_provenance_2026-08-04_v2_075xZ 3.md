# 在跑配置常数 —— 哪些是由一次 `wide_dl` 面板上的测量定下来的

**派工原话:** *"列出【全部】在跑的配置常数, 其数值是由一次 `wide_dl` 家族面板上的测量定下来的。"* —— 这是 `size` 腿那次**越界发现**的系统版。

---

## 0. 结论摘要

1. **在跑的配置常数里, 由 `wide_dl` 面板测量定下来的是【少数】** —— 绝大多数是**场地事实**(交易所文档)、**运行观测**(实盘日志)或**政策选择**(安全分数), 三类都不经过面板。
2. **★ 但"少数"里包含最脆的那一类。** 按派工要求优先标出的 **"符号检验作用在近零量上"**, 目前**确证 1 条**(`size` 腿), **高度疑似 1 条**(`funding_mode = rank`), **另有 1 条需要 C3 确认口径**(书级盈亏平衡 2.504 bps)。
3. **★ 一条结构性观察, 比清单本身更有用:** 面板污染要传导到一个配置常数, **必须经过"用面板算出一个 alpha 类的量"这一步**。⇒ **凡是常数的定义式里不含 IC / PnL / 边际贡献 / 净收益的, 结构上就免疫。** 这给出一个**不靠逐条追溯的筛子**, 见 §4。

**★ 为什么这一类最脆(把 size 的教训写成一般形式):**
> **符号检验没有幅度缓冲。** 一个幅度门(如"ΔIC ≥ +0.003")要被翻, 需要偏移量级接近门限; 而一个符号检验只要偏移**跨过零**就翻, **哪怕偏移只有 0.0003**。
> ⇒ **`|t| < 1` 的符号检验 = 一个由噪声与偏移共同决定的抛硬币, 而它在配置里长得像一个结论。**

## 4. ★★ 一个不靠逐条追溯的筛子(比清单更耐用)

**逐条追溯会漏, 而且下次新增常数时要重做一遍。结构上的判据是:**

> **面板污染要传导到一个配置常数, 必须经过"用面板算出一个 alpha 类的量"这一步。**
> ⇒ **看常数的【定义式】: 里面出现 `IC` / `rank-IC` / `PnL` / `净收益` / `边际贡献` / `Sharpe` 中的任何一个 ⇒ 有嫌疑, 必须追溯面板。**
> ⇒ **一个都不出现(场地上限 / 时序观测 / 容忍度 / 量纲)⇒ 结构上免疫, 不必追溯。**

**用这个筛子重扫上面三类: 一类与二类全部命中(都含 `MC̄` / `ΔIC` / 对比择一); 三类无一命中。⇒ 筛子与逐条追溯的结论一致**, 这是一次交叉验证, 不是重复劳动。

**★ 并由它得到一条【将来】的操作条款:**
```
新增任何配置常数时, 在它旁边写一行: 它的定义式里有没有 alpha 类的量?
有 ⇒ 记下所用面板与判据类型(符号 / 幅度 / 排序)。
这一行的成本是零, 而它免掉的是将来又一次"全量追溯"。
```
