## 2. 序 1 — §7.1-C: raw 训练 + 事后中性化

**机制:** 残差标签 = `YR` = 对 8 通道基线做过横截面残差化的目标, **信噪比更低且额外注入了横截面回归噪声**(文档 §5.2 / §3.2)。若把 **raw 训练**的模型的 OOF 预测**事后**做同一个横截面残差化, 能达到 residual 直训的水平, 则"必须直训高噪残差标签"这个前提不成立。

**最小可判实验:** **不需要新训练。** S1 已有两个干净 raw/resid 口径的产物(`per_fold` 同时记了 `raw_rank_ic` 与 `resid_rank_ic`), 只需对已有 OOF 预测做一次逐锚横截面 OLS 残差化再算 rank-IC。**成本 = 0 臂, CPU 分钟级。**

**击杀判据(重锚后):**
```
C 臂(raw 训练 + 事后中性化)的 resid rank-IC  <  B 臂(resid 直训)实测值 − SE_paired
⇒ 直训残差标签是必要的 ⇒ §7.1 的主张被杀
```
**★ 不用 0.048。** 用**同一次实验里的 B 臂**作对照(§0-2)。

**★ 一条限定, 必须随结论走:** 这与 A6 **不是同一件事**。A6 证的是在**书**上事后投影有效; §7.1-C 问的是在**模型预测**上事后投影够不够。**层级不同, 不可互相引用为支持。**

## 3. 序 2 / 4 / 5 — 三条我同意 team-lead 初判的

### 序 2 · §6.3 只做诊断, 不改 loss
**机制:** 七项加权总损失正是 `CLAUDE.md` 约束 4 禁止的堆叠, 且反模式册 #10/#12/#15/#20/#21 **五条全是 loss 改动翻车**。**但"记录各 loss 的梯度范数与任务间余弦"是纯观测**, 近乎免费, 且能回答一个我们从没问过的问题: **现有的几项损失是不是已经在互相打架。**

### 序 4 · §6.2 头四 Tail Event —— 只做空头侧
**机制:** A2 实测**空头尾召回 2.4–3.7×, 多头尾 ≤ 随机** ⇒ **多头侧没有可建模的结构**, 做双侧头是把一半容量花在噪声上。
**前置(硬):** A2 自带限定"书的 cap 会丢掉幅度"未解 ⇒ **依赖 A5(cap 外延)**。**A5 未出之前排它是浪费**: 若 cap 把尾部幅度削掉, 预测幅度就无处兑现。
**击杀:** 空头尾事件头的 `P(Y<Q0.1)` AUC 在干净面板上 ≤ 随机 ⇒ 杀。

### 序 5 · §7.3 风险标准化标签 —— 带一条具体对照
**机制:** 若仓位最终做 vol scaling, 标签与持仓目标对齐可减少高波币支配排序损失。
**★ 警告的具体形态(比"我们有个邻近否定"更精确):** vol-scaling 的表观收益 **99.8% 是泄漏经 beta 择时兑现**(+1.814 → SERVE −0.083)。**标签侧 `Y/σ^γ` 与仓位侧 vol-scaling 不是同一件事** —— 但 **`σ̂` 与 `beta_i` 在横截面上高度相关**, 而泄漏**恰恰只能经 `beta_i` 表达**。⇒ **σ 归一化有可能沿着同一条通道重新引入同一个偏。**
**⇒ 必须带的对照:** 同一实验里并跑 `γ=0`(即不做风险标准化)臂, 且**两臂都在干净面板上**; 只报 **Δ(γ=0.5 或 1.0) − Δ(γ=0)**。
**击杀:** 干净面板上 Δ ≤ 0 ⇒ 杀(不给"换个 γ 再试"的第二次机会 —— γ 只有两个候选, 一次跑完)。

## 4. ★ 序 3 — §7.4 多 Horizon: 我把它从"低"上调到"中"

**team-lead 的理由是单资产反模式 #10(multi-horizon UNIT 机制错配), 并明确要我独立判、别照抄。独立判的结果是上调, 依据有三条:**

1. **★ 标签【已经在盘上】, 数据前置成本为零。** S1 的逐位断言清单里就有 `Y1 / Y4 / Y24 / YR1 / YR4 / YR24`(见预注册 §3-1)—— **1h / 4h / 24h 三档目标已经在面板里建好了。** 文档提议的 `Y^1h,Y^2h,Y^4h,Y^8h` 我们有其中三档的近似。**这把"多 horizon"从一个数据工程项变成一个纯训练配置项。**
2. **反模式 #10 是【单资产】的, 且它的病因是 UNIT 机制错配** —— 那是"不同 horizon 的目标单位/量纲对不上"的具体故障, **不是"多 horizon 监督本身无效"的一般结论**。多资产横截面上目标已经是同一套横截面残差口径, 该具体故障不自动外推。**照抄它就是我今天反复在挡的那件事: 把一个正确的结论安在另一个量上。**
3. **反模式 #15/#25 给了安全形态:** rank-loss / mag-focal 作 **AUX 且 w ≤ 0.1 是安全的, REPLACE 才翻车**。⇒ **本项只以 AUX 形态排期, 权重上限写死 0.1**, 主目标仍是 `YR4`。

**最小可判实验:** 1 臂 —— S1 赢家架构 + `YR1`/`YR24` 作 AUX 头(w=0.1), 主目标 `YR4` 不变。
**击杀:** 主目标 `YR4` 的 resid rank-IC 相对 S1 赢家 **下降超过 `SE_paired`** ⇒ 杀; **不允许**"那就调小权重再试"(那是在看着数据挑超参)。

**★ 我对这条上调的信心限定:** 我把它从"低"抬到"中"的**唯一实质理由是成本塌了**(标签已在盘上), **不是机制变强了**。**便宜不等于有效** —— 它排在 §7.1-C 与诊断之后, 就是因为后两者的**信息量**更高而不只是更便宜。

## 5. ★ 序 6 — §8.2 三路径时序编码: 我推翻"架构里最高"

**team-lead 的理由:** 它是唯一有我们自己实测支撑的架构提议 —— 文档说 Shock branch 应保留单币局部信息避免噪声扩散, 而我们实测 H-ATT 成立(attention 当年的优势相当部分在收割共同标量)⇒ 限制 attention 只作用于 slow 分支是机制驱动。

**★ 我认为这条推理把 H-ATT 的结论用反了一半, 三条:**

1. **H-ATT 的干净面板结论不是"attention 有害", 是"attention 的边际 ≈ 0"**(−3.4%, t −0.83, 1/5 折)。**⇒ §8.2 是在【重新分配一个当前价值约等于零的模块】。** 把一个 0 搬到别的分支, 先验上仍然是 0 —— 除非有理由相信"位置"才是它失效的原因, **而 H-ATT 没有提供这个理由**(它测的是有/无, 不是放在哪)。
2. **它需要把 32 个通道做三分类(slow/fast/shock), 这是一个自由度很大的结构改动。** `CLAUDE.md` 约束 4(机制 > 堆叠)与反模式 #29(每加 channel −0.013 P, 除非 ≥ +0.003 alpha)都指向**先证明收益再动结构**。三分类的切法本身有很多种, **而没有任何实测告诉我们该怎么切** —— 那是"设计自由度"而不是"机制"。
3. **★ 现有证据指向【更少】结构而不是更多:** 干净面板上**赢的那一支是 plain(无 attention, 0.0464 > xattn 0.0449)**, 而且它 **3/5 折在 `best_epoch = 0`** 就取到最好。**一个在第 0 轮收敛、结构最简单的模型是当前最优** —— 这是要求架构精细化的最不利环境。

**⇒ 处置: 降到"低-中", 且若要做, 最小形态【不是】三分支, 而是一个 2 臂对照:**
```
臂 1: S1 赢家(plain, 无 attention)                    ← 已有, 0 臂
臂 2: 只对 slow 通道子集开 attention                    ← 1 臂
击杀: 臂 2 − 臂 1 ≤ SE_paired ⇒ 杀掉整个 §8.2 路线
```
**理由: 若"限制 attention 的作用域"这个机制是真的, 它在最小形态上就该显出来; 显不出来就不必去做三分支的通道分类工作。** 先用 1 臂买一个否决权, 而不是先付通道分类的工程成本。

## 6. ★ 序 8 — §8.3 稀疏 attention: 比"推迟"更强, 建议**不排期**

**team-lead 给"推迟, 等生产折"。我建议直接不排期, 理由是它的前提已经被答掉了:**

## 7. ★★ §10 条件增量筛选 —— team-lead 未读, 而它是这份文档里**唯一有治理后果**的一节

> 已实测到的两个受害现场: **track-2 的 OI 双门**(基线臂 = 完整 32 通道)与 **`size` 腿摘除**(`MC̄ = −0.00031`, `t_eff −0.17`, 对一个被抬高 ~2.7× 的书取边际)。

**⇒ 治理条款(建议现在就写死, 它不需要任何实验):**
