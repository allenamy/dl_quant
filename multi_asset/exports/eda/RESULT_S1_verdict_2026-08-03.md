## 1. H-ATT: **成立**

### 1-1 判据与读数

预注册 §4 写死的三分(**看结果之前**):

**实测(best-head resid IC, YR4, 5 年折):**

```

margin_clean  = −0.00156   ( = − 3.36%,  t = −0.830,  1/5 折为正 )
                                          ^^^^^^^^^^ 远在 +0.009475 之下 ⇒ 判入 <0.5× 区
```

**⇒ H-ATT 成立。**

### 1-2 ★ B4 的两句话纪律, 照录 —— 这两句不可合并

> **(1) "attention 的优势没了" —— 强证据。** margin 从 +0.01898 塌到 −0.00156, 幅度 −0.02054, 且脏面板一侧 5/5 折同号、t=+3.43。
> **(2) "无 attention 更好" —— 无证据。** −3.36% 的 t 只有 **−0.83**, 单种子, 5 折。**这是一个平局, 不是一次反超。**

**为什么必须分开说:** 这两句在数据上共享同一个 −0.00156, 但**证据强度完全不同** —— (1) 靠的是"从 +0.019 到 0"这个**变化量**, (2) 靠的是"−0.0016 是否真的小于 0"这个**水平**。**把它们合并成"无 attention 的架构更好"是把一个平局讲成了结论。**

### 1-3 ★ 主证读法: 差之差, 不依赖任何单支的绝对水平

```
                  脏面板        干净面板       变化
xattn            0.08380       0.04488
plain            0.06482       0.04644
                 -------       -------
margin           +0.01898      −0.00156      −0.02054   ← 主证
```

**这个读法的好处是它不依赖"0.0449 高不高"这个问题。** 两个面板的绝对水平差得很远(干净面板整体低约一半, 因为泄漏被拿走了), 若比较绝对水平, 结论会被"面板变了"污染。**差之差把面板效应对消掉, 留下的是"attention 这一个部件在两种面板上各值多少"。**

### 1-4 量尺条款(预注册 §4-2 条 2): **通过, 但只通过 3.26 倍**

预注册规定: **margin 的变化若落在 run-to-run 量尺的 2 倍以内 ⇒ 直接判"不决定性", 不进三分表。**

```
量尺 = |xattn_seed43 − seed44| 的 mean resid rank IC 差 = 0.00630
2× 量尺                                                = 0.01260
实测 margin 变化                                        = 0.02054   ⇒ 3.26× 量尺  ⇒ 清过
```

**★ 诚实限定, 必须随结论走:** 3.26× **清过了门, 但不是宽裕地清过**。而且量尺自带预注册里就写明的装置限定 —— **seed43/44 那对 run 在 13,176 网格、3 折上, 与 `_5yr` 的 5 年折不同装置, 只作数量级参照。** ⇒ **"H-ATT 成立"这句话的强度是"清过了预先写死的门", 不是"排除了 run 世代变异"。** 后者需要 §4-2 里已写死的升级路径(脏面板 2×2 重训), 该路径的触发条件是"判不决定性", 现在没有触发。

### 1-5 稳健性: 逐年切 + 换头选法, 两条都不翻案

### 3-2 ★ 对比口径的正当性 —— 为什么这不是"拿两个不同的东西比"

**这是本节最容易被质疑的地方, 所以写全。**

```

S1 两支新模型   →  评在 CAUSAL 面板   →  0.04488 / 0.04644
                     ^^^^^^ 面板不同
```

**面板确实不同, 而这正是【正确】的比法 —— 因为比的是"各自在自己实际的部署形态下, 到底能拿到多少":**

| | 训练时吃的面板 | 部署后实际收到的面板 | 有无训练-服务偏斜 |
|---|---|---|---|
| **现役 champion** | TRAIN(含 11h 未来) | **SERVE**(实盘末行截断, 拿不到未来) | **有** —— 这就是它只值 0.02942 而不是 0.08379 的原因 |
| **S1 新模型** | CAUSAL | **CAUSAL**(部署时同批换服务线, §10 五件套) | **无** |

**⇒ 每一侧都是"那个模型上线后实际能拿到的数"。** 这是决策相关的比较。

**★ 而"同面板对比"在这里是【错】的比法, 两个方向都错:**
- **把现役放到 CAUSAL 面板上比** = 旧模型配新服务线 = **实测 0.02942 → 0.02157**, 而预注册 §10 明文禁止这种部署组合 ⇒ 那个数不对应任何允许存在的系统。
- **把新模型放到 TRAIN 面板上比** = 给新模型喂它没被训练过的泄漏 ⇒ 无意义。

**同锚同折是成立的**(preflight 14/14 已证两个面板的 `te_rows` 逐位一致), **所以配对 t 合法** —— 配的是同一批 9,851 个锚。

### 3-3 一处必须自曝的乐观偏差(它不改判定, 但改绝对水平)

**`best_head` 是在【测试折上】用 argmax 选的**(`best = np.nanargmax(ic_r)`, 而 `ic_r` 算在 `te_rows` 上)。**这是在测试集上选模型, 两侧都乐观。**

- **对绝对水平有影响:** best-head 比 ensemble 高约 1.9%(0.02942 vs 0.02888)。**⇒ 任何"新模型能拿到 0.045"的一般性陈述, 应引 ensemble 的 0.0444 / 0.0459, 不引 best-head。**
