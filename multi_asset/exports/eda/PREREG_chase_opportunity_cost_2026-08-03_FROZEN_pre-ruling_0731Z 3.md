## 3. 机会成本侧 —— 估计量与它的基准价

### 3-1 记号(全部只用 ≤t 信息与已实现路径)

对锚 `a` 上的名字 `i`:

| 符号 | 定义 | 落盘来源(**已核实存在**) |
|---|---|---|
| `q_i` | **扣下时刻的带符号残差**(名义, USDT)。填上它使账本净额移动 `+q_i` | 补单行 `intended_notional`, `topup_source == "from_partial"` |
| `P_w` | **基准价 = 该锚的 `mid_at_anchor`** (见 §3-2, 这是本文的裁定) | 补单行 `mid_at_anchor`, 14/14 非空 |
| `P_next` | **下一锚的 mid**(已冻结口径: 用 mid 不用成交价) | 下一锚 `anchors.jsonl` 的 `mid_at_anchor_vector`[symbol] |
| `F_i` | chase 臂的实际成交均价 | 补单行 `avg_fill_px`, 在**成交的**行上 15/15 非空 |

```
持有价值   H_i = q_i × (P_next − P_w) / P_w            [USDT]  → 报告用 H_i / |q_i| × 1e4  [bps]
执行成本   X_i = q_i × (F_i    − P_w) / P_w + fee_i    [USDT]  → 同上转 bps
```

`H_i` **两臂都可算**(只需 `q_i` 与两个 mid, 都与臂分配无关); `X_i` **只在 chase 臂可观测**。

**⇒ 主估计量:**
```
ATE = E[H]                        −        E[X | chase 臂]
      ↑ 用【两臂全部越地板名字】估计          ↑ 只能用 chase 臂估计
```
这是相对朴素做法(chase 臂算 `Y=H−X`, no_chase 臂算 `Y=0`, 作差)的方差改进: `H` 与臂无关 ⇒ 可用**两倍样本**估计, 稀薄只落在 `X` 上。**该改进依赖一条假设, 见 §3-4 的内建证伪。**

### 3-2 ★★★ 裁定: `P_w = mid_at_anchor`, 两臂同一个价, 且这条不需要 0B 新增任何字段

**前身草稿把 `P_w` 定义为"扣下时刻 `t_w` 的 mid", 并把"`t_w` 是否落盘"列为未核实项 #1, 说"若未带需 0B 补一个字段, 否则 `H` 不可算"。核实结果是: 时刻有, 价格没有, 而且补上它是错的。**

**核实(2026-08-03 07:2xZ, 14 个 `skipped_no_chase_arm` 行):**

| 字段 | no_chase(扣下) | chase(实发) |
|---|---|---|
| `cancel_ts`(即 `t_w`) | **14/14 非空** | 102/102 非空 |
| `submit_ts` | 0/14(按构造: 没发单) | 15/102 非空 |
| **`mid_at_submit`** | **0/14** | **15/102**(恰是成交的那 15 行) |

**⇒ 三条后果, 第三条是决定性的:**

1. **时刻 `t_w` 是有的**(`cancel_ts`), 落在锚后 **930.9–988.7 s**(中位 ≈ 956.8 s)。所以草稿担心的"没有时间戳"不成立。
2. **但 `t_w` 那一刻的价格没有落盘**, 且**按构造不可能有** —— 没有提交就没有 `mid_at_submit`。要它就得新增一次行情读取。
3. **★ 即使新增了, 也不能用。** chase 臂的 `mid_at_submit` 与 no_chase 臂的(假想)`mid_at_t_w` **不是同一时刻的量**: 实测 chase 的提交偏移是 **985.8–1011.1 s(中位 1009.0 s)**, 扣下偏移中位 **956.8 s** —— **两臂的"决策时刻"系统性相差 ≈ 52 秒**(扣下的名字瞬间退出循环, 发单的名字要走完提交与成交)。在跑的行情里 52 秒是真实价差。**用一个"同名不同时刻"的价当两臂的共同基准, 正是本项目已登记三次的「列名不是口径」族 —— 而这一次它会直接落在主判据的分母上。**

**裁定: `P_w ≡ mid_at_anchor`, 两臂逐字相同。理由三条, 第三条说明这个选择不可能偏袒任何一方:**

- **(i) 它是唯一在两臂中以同一定义、同一时刻落盘的价**(14/14 与 102/102 全非空)。
- **(ii) 它已经是已冻结文件 §4 给成本侧定的基准**("支付成本 = fee + 带符号 adverse, **对 `mid_at_anchor`**")。决策规则要比较 `X < H`; 两侧若用不同参照价, 这个不等式**在量纲上就不成立**。
- **(iii) ★ 这个选择证明上不能改变估计量。** 展开:
  ```
  ATE = E[q(P_next − P_w)/P_w] − E[q(F − P_w)/P_w]
  ```
  逐名字看, chase 名字的实际臂间差是 `q × (P_next − F)/P_w` —— **`P_w` 完全抵消**。`P_w` 只是一个分解点。在锚内随机化下 `q` 与 `P_w` 在两臂间可交换, 故 **`P_w` 的选择影响有限样本方差, 不影响估计量**。⇒ 这是一个**方差/一致性选择, 不是一个关于答案的判断** —— 正因如此它适合在冻结前定死。

**⇒ 对 0B 的净要求: 零。** 草稿列的"本文对落地的唯一新要求"不存在。**`mid_at_submit` 明令禁止进入 `H` 或 `X` 的定义**(它只可用于事后的执行质量描述, 且须标注"仅 chase 臂可得")。

### 3-3 `t_w` 仍要记录, 但它的用途变了

`cancel_ts − anchor_ts` **不进主判据**, 只进 §6-2 的版本可合并性检验(政策改动若挪动了补单腿的决策时点, 该分布会移)。**实测基线(供日后比对): 扣下中位 956.8 s, chase 提交中位 1009.0 s。**

### 3-4 内建证伪(先写死, 结果两向都照报)

`E[H]` 用两臂合并估计, 依赖 **"我方在 `t_w` 的冲击不残留到下一锚"** —— 否则 chase 名字的 `P_next` 发生在我们自己那笔成交之后, `H` 在两臂间不可交换。

**检验: 锚内配对比较两臂的 `H` 分布。** 零假设(冲击不残留)下二者可交换。**系统性不同 ⇒ 合并估计量作废, 退回朴素估计量(只用 no_chase 臂估 `H`), 且 N\* 须按更大的方差重算。** 该检验的存在与退路**现在写死**, 不等看到结果再决定。

## 4. ★★★ 持有窗口的终点 —— 派工要求的"两种情形都写死"

### 4-1 终点固定为下一锚, 两种情形都是, 且理由是结构性的

**结论先说: 终点在两种情形下都是「下一锚」。变的不是终点, 是终点上谁付那一笔。**

**为什么终点必须与情形无关:** chase 名字持有仓位、no_chase 名字没有, 所以"这个仓位什么时候被平掉"**本身就是处理的后果**。用一个后果去定义估计量的窗口, 等于让处理改变自己的度量尺。**固定窗口是唯一与臂无关的选择。**

**为什么"下一锚"是那个固定点(不是随便挑的):** 在 T+1, 两臂被**重新定到同一个目标**。因此两臂的敞口差 `q_i` **恰好存活于 `[t_w, T+1]`**, 到 T+1 由该锚的再平衡收敛。⇒ 窗口不是约定, 是系统的再平衡节律定的。

### 4-2 两种情形的几何差异 = 一个精确表达式的两个符号区间

记 `d` = **下一锚该名字的计划成交名义**(= `target_w − prev_w` 折算, 直接读下一锚 maker 行的 `intended_notional`), `q` = 被扣下的残差。在 T+1:

```
no_chase 世界要交易   |d|
chase    世界要交易   |d − q|          (它已经持有 q)
二阶差   S = ( |d| − |d − q| ) × c_{a+1}          c_{a+1} = 下一锚实测混合成本率
```

| 派工点名的情形 | 判别式 | `S` 的符号 | 谁多付 |
|---|---|---|---|
| **(i) 下一锚信号让该残差消失** (`d ≈ 0`, 或 `d` 与 `q` **反号**) | `|d − q| > |d|` | **负** | **追价方** —— 它建了一笔马上要平掉的仓, 付了一次往返的第二腿 |
| **(ii) 下一锚重新要求建同向仓位** (`d` 与 `q` 同号且 `|d| ≥ |q|`) | `|d − q| < |d|` | **正** | **不追方** —— 它并没省下成本, 只是**推迟**到下一锚的价格上付 |
| (中间态: 同号但 `|d| < |q|`) | 连续插值 | 可正可负 | 视幅度 |

**★ 这是本节的实质: 派工要求的"两种几何"不是两个公式, 是同一个精确表达式 `S = (|d| − |d − q|)·c` 的两个符号区间。** 无需分支, 无需 clip —— 与 journal §3 的通则同形("任何 `A−C` 都可写成 `(A−B)+(B−C)` 且精确; 伸手去 clip 就说明还没找到那个中间量")。**上表的作用是证明它覆盖了这两种情形, 而不是引入新公式。**

**单位纪律:** `d` 与 `q` 分别以 T+1 与 T 的价格计名义 ⇒ **必须先折成合约数量再相减**(`q/mid_T` 对 `d/mid_{T+1}`), 结果按 `mid_{T+1}` 折回名义。数量对重估免疫 —— 与 journal §7.1 "缓存存数量" 同一课。

**实测(仅计数, 无价格):** 10 个已闭合窗口中 **9 个是情形 (ii)**(同向重新要求), **1 个是情形 (i)**(符号翻转)。⇒ **情形 (ii) 是常态**, 因此 `S` 的期望符号很可能为正, 即"不追"主要是**推迟付费而非省下付费**。这条现在写下, 供事后核对。

### 4-3 主判据排除 `S`, 而排除**不是中性的** —— 所以 `S` 是必报项

**主判据 = `E[H] − E[X]`, 不含 `S`。** 理由是机制性的, 不是省事:
> `S` 以**执行成本率** `c_{a+1}` 计价 ⇒ 它随 policy_version 变 ⇒ **把它并进机会成本侧, 就毁掉了"机会成本是政策不变量"这条性质** —— 而那条性质正是两侧分解(RESEARCH §4)存在的全部理由。

**但排除它有方向性后果, 必须与判词并排写:**
- 情形 (i) 多时, 排除 `S` **高估**追价的价值(漏掉往返第二腿);
- 情形 (ii) 多时, 排除 `S` **低估**追价的价值(不追只是推迟)。

**⇒ 冻结两条: (1) 两种情形的实测占比是必报项; (2) 次级判据 `E[H] − E[X] + E[S]` 与主判据必须并排出现。若两者符号相反, 结论以"主判据 + 情形占比"共同表述, 不得只报其一。**

### 4-4 越窗持有(carry) —— 并改正草稿只覆盖一半世界的定义

这些残差按构造贴着地板。在 T+1, 两个世界所需的调整**都可能仍低于地板 ⇒ 都不交易 ⇒ 敞口差 `q` 存活过 T+1**。

**★ 草稿把 `carry` 定义为"下一锚该名字的计划成交被地板挡下" —— 那只看了已实现的(no_chase)世界。** 敞口差是否存活取决于**两个世界都不交易**:
```
carry_i = 1  iff  |d| < floor_i   AND   |d − q_i| < floor_i
```
只看一侧会把"no_chase 不动但 chase 要平掉"误判为 carry —— 那种情形下差额其实被关闭了。**这是「守卫只覆盖了一个实例而非整个类」族。**

**处置(先写死):**
1. 主判据窗口**仍固定为一个锚**(理由同 §4-1)。
2. `carry` 比例逐锚报告, 它衡量"一个锚的窗口低估了多少真实持有期"。
3. **`carry_i = 1` 的单元不剔除** —— 按结果剔除样本就是选择偏倚。它们进主判据, 同时进 carry 统计。
4. **`carry` 比例 > 50% ⇒ 读数报告首行声明, 并把次级判据(含 `S`)提为并列主判据。** 该阈值现在定死, 不等看到数再定。

**实测: 10 个已闭合窗口中 1 个已实现世界被地板挡下(10%)。** 未核实: 我**没有**逐个算 `|d − q|` 对地板(那需要重建 `floor_i`), 因此 10% 是 carry 的**上界的一半的观测**, 不是 carry 率本身。**首次读数时须按上式重算。**

## 6. 政策版本化(派工 (b))

### 6-1 分解与各侧的作废规则

```
机会成本侧  E[H]                        ← 与【补单执行政策】无关 ⇒ 样本跨版本累积
追价成本侧  E[X | policy_version]        ← 随版本变 ⇒ 换版本只作废这一侧
决策规则    追 iff E[X | 当前版本] < E[H]
```

### 6-2 ★ 但"政策不变"是有条件的, 条件现在写死

`H_i = q_i × (P_next − P_w)/P_w`。**函数形式**与执行政策无关, **但两个输入不是**:

| 输入 | 对**补单腿内部**的改动(re-peg / 升温阶梯 / 时点散开 / 微观门) | 对 **maker 阶梯**的改动 |
|---|---|---|
| `q_i` (残差) | **不变** —— 残差在补单腿之前就已确定 | **会变** —— maker 成交率变 ⇒ 残差分布变 |
| `P_w` (= `mid_at_anchor`) | **不变**(§3-2 的选择使它对补单腿时点免疫 —— 这是该选择的第四个好处, 草稿的 `t_w` 取法没有这个性质) | **不变**, 但 `q` 的分布变仍使合并失效 |

**⇒ 不变性成立于「改动只发生在补单腿内部」。任一版同时动了 maker 阶梯 ⇒ `E[H]` 的跨版本合并失效。**

**版本可合并性检验(三条政策数, 先写死):**
```
per policy_version:  mean(|q|),  sd(|q|),  越地板比例,  median(cancel_ts − anchor_ts)
合并条件(三条全满足才允许把该版本的 H 并入池):
  |Δ mean|q||          ≤ 25%  (相对合并池)
  |Δ 越地板比例|        ≤ 10 个百分点
  |Δ median t_w 偏移|   ≤ 120 秒
基线(v1, 三锚实测): 越地板比例 no_chase 18.7% / chase 14.7%; median t_w 偏移 956.8 s
```
**任一条越界 ⇒ 该版本的 `H` 单独成层, 且读数报告首行声明"跨版本合并已作废"。**

### 6-3 相位边界

- **`policy_version` 逐锚落盘**; 版本切换 = 相位边界。
- **锚点跨越切换**(同一锚内前后不同版本)⇒ 该锚不入样本并计数。
- **`N*` 与 `sd` 只对机会成本侧定义**(它是政策不变量) —— 见 §7。
- **但成本侧也要有下限**, 否则新版本第一个锚就能翻转决策: `MIN_ANCHORS_PER_VERSION_FOR_X = 3`(与 `ops/chase_readout.py::MIN_ANCHORS_FOR_SD` 取同值), 且**必须同时报 `SE(E[X|version])`**。版本内锚数 < 3 ⇒ 决策规则不出结论, 沿用上一版判词并声明。**★ 按 §5-1 的实测密度, 3 个锚只有 ~15 个 `X` 观测 —— 这个下限偏松, 但把它调紧需要 team-lead 裁(§11-Q1)。**
- **⚠ `policy_version` 目前不存在**(§9-1)。落地前, 版本由锚时刻 `live/binance_executor.py` + `live/chase_policy.py` 的 git commit 定义, 且**必须补记进产物**。

## 7. 推断、sd 产物与 N\* 定案(派工 (c) 与 (f))

### 7-1 配对与推断层级

- **配对层级: 名字级 within-anchor; 锚 = 聚类单位。**
- **点估计**: 先算每锚的 `Ĥ_a − X̂_a`, 再对锚**等权平均**。锚等权而非名字等权 —— 名字数在锚间差 2–3 倍, 名字等权会让最宽的锚主导。
- **主推断 = 锚内随机化检验(permutation)**: 锚内置换臂标签, 重算统计量, 取经验分布。锚数少时这是唯一诚实的推断; 正态近似与 cluster-robust t 作**次级**并报(df = n_anchors − 1)。
- **★ 锚内的名字不是独立单元。** 残差集按机制是同向的(已冻结文件实测三锚净额/名义 +80% / −100% / −100%), 因此一个锚上的 `H` 基本是**一次方向性下注**, 而不是 4–6 个独立观测。⇒ **有效独立单元数 ≈ 锚数**, 不是名字-锚数。**禁止计算名字级标准误并据以定 N\*。**
- **同名字跨锚携带**(本锚扣下 ⇒ 下锚 delta 更大)使有效独立单元数进一步 < 锚数; 置换在锚内做故不依赖跨锚独立, 但**功效计算未扣除这一项 ⇒ N\* 是下界**。报告须给同名字重复出现的频次表。

### 7-2 MDE 的单位: bps, 不是 USDT

前身草稿建议 `MDE = $0.75/锚`。**本文改为 bps, 理由是机制性的:** RESEARCH §5 已裁定敞口会持续扩大(10–50×)。**一个以美元定义的 MDE 会随敞口变大而静默收紧** —— 同一个政策问题, 明天需要的 N\* 会因为账本变大而变小, 而我们并没有获得更多信息。**bps 对规模免疫, 且决策规则两侧本来就同单位。**(当前敞口下 $0.75/锚 ≈ 每锚扣下名义 $40–120 的 60–190 bps, 跨度 3 倍 —— 这就是美元单位的问题本身。)

### 7-3 N\* 公式(先定死)与量级演示(★ 不迁就, 算出来大就写)

```
Var(Δ_a) = sd_within² × (1/n_chase,a + 1/n_nochase,a) + sd_between²
N*       = ceil( (z_{1−α/2} + z_{1−β})² × Var(Δ) / MDE² )        α = 0.05 双侧, β = 0.20
```

**★ 结构性预判(先写下, 可被 sd 产物证伪): `sd_between` 主导。** 理由见 §7-1(锚内是一次方向性下注)+ 实测 chase 成本随锚从 17 单调升到 52 bps。⇒ **N\* 由锚数决定, 几乎不随每锚名字数变化 —— 稀薄的处理组不是瓶颈, 锚点数才是。**

**量级演示 —— 以下不是 sd 估计, 是把已知的市场尺度代进公式看数量级。真 sd 必须由 §7-4 的产物在机会成本口径上给出。**

- 已核实的市场尺度: **4h 横截面收益 sd 中位 160 bps**(110 名 × 10 个 4h 区间, 范围 125–292)。复算: 读 `anchors.jsonl` 的 `mid_at_anchor_vector`, 对相邻锚取逐名收益, 取横截面 `pstdev`。
- 每锚的 `H`(bps) ≈ 4–6 个**同向**名字的名义加权收益。同向 + 高相关 ⇒ 有效独立 ≈ 1.5–2.5 ⇒ **`sd_between` 量级 110–200 bps**(设 150)。
- MDE 若锚定到已实测的追价成本水平(+17.21/+41.59/+52.50, 均值 **37.1 bps**), 取 **Δ = 37 bps**:

```
N* ≈ 7.849 × (150 / 37)²  ≈  129 个锚  ≈  21.5 天 (6 锚/天)
```

| 敏感性 (N\* = ceil, 天数 = N\*/6 四舍五入) | sd 110 | sd 150 | sd 200 |
|---|---|---|---|
| **Δ = 25 bps** | 152 锚 (25 天) | 283 锚 (47 天) | 503 锚 (84 天) |

| **Δ = 50 bps** | 38 锚 (6 天) | 71 锚 (12 天) | 126 锚 (21 天)  |

复算: `N* = ceil(7.8489 × (sd/Δ)²)`, `7.8489 = (Φ⁻¹(0.975) + Φ⁻¹(0.80))²`。

**⇒ 如实写: 数量级是"数十天", 不是"几个锚"。** 且这是**下界**(§7-1 的跨锚携带未扣除; §5-3 的缺失未扣除)。**若 team-lead 需要更快的读数, 唯一诚实的杠杆是提高每锚被扣下的名义(即放宽地板或做大敞口), 不是降低 N\*。**

### 8-3 混合键的定义与切点(现在冻结, 切点不从数据里挑)

