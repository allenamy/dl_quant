⇒ **在修好这把尺子之前挖到的任何新腿, 都会拿到一个约 +0.19 的假信用。** 先修尺子不是流程洁癖, 是轨道 2 的前置。

## 1. ★ 机制假说(推自已发表的数字, 未看任何新数据)

`engine/netting.py` 第 57-62 行, 每个锚点:
```
base   = active - active.mean()      # 未整形的书
gref   = |base|.sum()                # ← 参考 gross
shaped = chain.shape_position(active)
shaped = shaped * (gref / gsh)       # ← 整形后重新缩放回 gref
```
**`gref` 随组合信号的离散度增长。往书里加任何一条腿(哪怕纯噪声)都会抬高 combo 的离散度 ⇒ 抬高 gref ⇒ 整本书的实际敞口被放大。**

`ΔNet` 是**累计收益差**, 对敞口标度**不是**不变量 ⇒ 它把"书变大了"记成"腿有 alpha"。

**用已发表数字做的自洽核验(全部来自 RESULT_alt_weights §1 与 RESULT_leg_marginal §0, 未跑新东西):**
- SQ 三腿: 累计净 +9.87732, 换手 9,410.4 @1.9bps ⇒ 累计毛 = 9.877 + 9410.4×1.9e-4 = **11.665**
- 安慰剂: ΔGross **+0.261**, ΔTurn **+399**
- ΔGross/Gross = **2.24%**, ΔTurn/Turn = **4.24%** ⇒ **不是均匀加杠杆**: 噪声腿要被交易, 换手涨得比毛额快一倍
- 复核: ΔNet = 0.261 − 399×1.9e-4 = **+0.185** ✅ 与实测 +0.18535 逐位一致

**⇒ 坏因 = 敞口标度混入 + 成本档取得太低(1.9bps)。** 安慰剂的盈亏平衡成本 = 0.261/399 = **6.54 bps**
—— 而部署读数是 **3.63(点估计) / 5.80(CI 上界)**, 换手前沿 crossover 6.93/8.49。
**⇒ 那个 +0.185 是在一个比部署成本低 1.9 倍的成本档上取得的。**

## 2. ★★ 可证伪预言(写死于跑任何东西之前)

**净夏普对敞口标度是严格不变量**: 敞口 ×c ⇒ pnl ×c 且 turn ×c ⇒ net ×c ⇒ 夏普不变。
(逐锚缩放因子 gref/gsh 随时间变化, 所以不变性不是精确的; 但**系统性的水平位移完全抵消**。)

| # | 预言 | 会红的方向 |
|---|---|---|
| **P1** | 安慰剂在**净夏普**口径下, 5 个种子的 ΔSharpe 均值 **\|·\| < 0.10**, 且至多 1 个种子 \|ΔSharpe\| > 0.20 | 若净夏普口径下安慰剂仍稳定为正 ⇒ **坏因不是敞口标度, 本门的修复方案整体作废** |
| **P2** | 同一批安慰剂在 **ΔNet@1.9bps** 口径下**复现** +0.15~+0.25 | 若复现不出来 ⇒ 我的装置与 0C 的不是同一个, 一切比较无效, 停止 |
| **P3** | 安慰剂 ΔNet 随成本单调下降, 在 **c ≈ 6.5 bps** 附近变号 | 若变号点远离 6.5 ⇒ §1 的算术分解错, 机制存疑 |

**P2 是装置对等断言**: 它必须先过, 否则 P1 的"变干净了"可能只是我换了个不同的装置。**顺序不可颠倒。**

## 3. 修好之后的录取门(供轨道 2 的每一条新腿使用)

**估计量 = 净夏普(不是 ΔNet)**, 并且**仍然**报告同配置安慰剂, 因为不变性只是近似:

- **G0 尺子关**: 该候选槽位的安慰剂(种子 0-4 固定), ΔSharpe 均值 \|·\| < 0.10 ⇒ 尺子可用。**不过则不出具录取判定。**
- **G1 录取**: `ΔSharpe(真腿) − mean ΔSharpe(安慰剂)` > 0, 且 **day-block bootstrap CI 下界 > 0**
- **G2 样本外**: 逐年 walk-forward(权重与录取决定都只用严格更早的年份), OOS 均值 > 0
- **G3 成本**: 3.63 与 5.80 **两档都要过**; 只在 1.9bps 过的一律不受理
- **G4 换手归因(必报, 不可省)**: 若增益来自**降换手**而非**升毛额**, 必须分开陈述 —— 那是 cadence 轨的胜利, 不是新腿的

**三条继承自 RESULT_alt_weights §3 的硬要求, 一字不改:**
1. 任何"加/减腿"比较必须同时跑同配置安慰剂, 单报 real 一律不受理
2. 安慰剂种子 ≥5 且事先固定, **报告全部 seed 而非均值**
3. 安慰剂必须与被测对象**同形**: 占据同一槽位、同样的权重(§2.2 的"全打乱"是给权重移动类比较用的, 两类不可混用)
