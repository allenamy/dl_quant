## 2. ★★★ 主判装置被重建过 —— 原装置有口径混杂, 三处确证

**原装置** `scratchpad/paired_gen_backfill.py` 用**当前** `panel_build` 建**一个**面板给两代打分。
但 `deff3bb` **在同一个提交里**改了 checkpoints **和** `signal/panel_build.py` 两处通道构建:

1. 新增 `PANEL_CALIBER = "normfix"`(此前 `as_trained`)。**代码自注: "A mismatch is silent — ch0 moves ~45% in sd."**
2. ch31: `np.convolve(...,"same")` → `np.convolve(...,"full")[:len]`, 即 centered(含 11h 未来)→ trailing-24。
   **代码自注: "Serving the centered form to a trailing-trained model is a train/serve mismatch on 155 of the model's 168 window rows."**

⇒ 新代匹配、**旧代在两个轴上都失配**, 而旧代实盘看的是它自己的老面板。
**那句代码自注的镜像, 正是原装置对旧臂做的事。**

**三处确证:**
- **代码层**: 上述 diff。
- **实测层**: 原装置旧臂与实盘书的逐锚 `corr = +0.195`(新臂 +0.631)。书里 DL 占 79.8% 权重, 忠实的仪器不该只有 0.19。
- **修法层(预先声明的可证伪检验)**: 我事前写"修好之后旧臂 corr 应向 0.6 靠"。实测 **+0.195 → +0.506**,
  且旧臂均值 **+0.09752** 对上实盘书 **+0.09768**(三位小数)。**检验通过。**

**修正装置** `scratchpad/paired_gen_homepanel.py`: 用 `sys.modules` 注入两份 `panel_build`
(`normfix`+full / `as_trained`+same), 每代在**自己的家面板**打分, 掩码统一取臂A,
并**断言两个面板确实不同**(`max|Δch31|>0` 且 `max|Δch0|>0`, 防缓存把"各自家面板"变成空话)。

**内部一致性**: 修正后新臂三个数字与原装置**逐位相同**(+0.09532/+0.09515/+0.08053)

## 4. ★ 0.09 这个数该怎么读(用户质疑"太高了吧")

- 0.0953 是**未整形 DL 合成的秩空间** rank-IC —— 不是整书。整书实盘 +0.0438(新)/+0.0977(旧),
  离线整书 +0.0548。整形(cap99 + sqrt 幂 + risk_budget 除波动)+ funding 腿**会改秩**。
- **更要紧**: 换装后实盘**值空间 Pearson 只有 +0.0015**, 而 `corr(Pearson, 毛额) = +0.978`
  (rank-IC 与毛额只有 +0.90 / 全期 +0.69)。**钱几乎就是值空间 IC。**
- ⇒ **秩空间的漂亮数字与一本亏钱的书可以同时为真。0.09 既不"太高", 也不重要 —— 它量的不是决定盈亏的量。**
  详见 memory `rank-ic-positive-value-ic-zero` 与任务 #75(尺子换轨)。
