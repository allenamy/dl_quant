## 1. 先把"现有 1.9 bps"翻译成人话 (关键校准)

出货表扣的那个 **flat 1.9 bps/side, 其实等价于 "maker 手续费 = 0, taker 手续费 = 1.5 bps, tick-normal 逆选择, 成交率 ≈ 0.51"** —— 我用本文的参数化成本模型跑这一格得到 **有效成本 1.842 bps → 145.0%/yr, Sharpe 12.31**, 对上出货表的 **144.2% / 12.24**。✅ 模型与出货口径同源。

**⇒ 现有表隐含了一个机构假设: 交易所 maker 费为零、taker 1.5 bps。个人 VIP 0 不是这个世界。** 这正是本文要量化的差距。

**换算尺度 (最有用的一个数):**
- 书的年换手 = **1457 单位-gross/yr** (每个 4h anchor 约翻 0.67 倍 gross)
- ⇒ **有效成本每贵 1 bps, 年化收益率掉 14.57 pp/gross**
- 无成本毛收益 = **171.8%/yr (Sharpe 14.55)**
- ⇒ **盈亏平衡有效成本 = 171.8 / 14.57 = 11.79 bps/side** (计入 funding carry 后 **12.15 bps/side**)

## 2. 成本模型 (逐币, 每单位成交名义)

```
c_j = φ · (maker_fee + max(0, ADV − hs_j · credit_j))  +  (1−φ) · (taker_fee + hs_j)
```
| 项 | 取值 | 出处 |
|---|---|---|
| `hs_j` 半价差 | 逐币 log10(小时名义) 插值; BTC 0.018 / 中位 0.502 / 最大 1.051 bps | 14 币 makerfill 校准 |
| `ADV` 逆选择 markout | **normal 2.0** / **stress 3.2** bps | tick 实测 (deepdive: BTC −1.71 normal / −3.24 stress / −5.30 崩盘) |
| `credit_j` 价差捕获信用 | ≥$4M/h 币 1.0; 以下 0.5 (外推保守) | makerfill 系列惯例 |
| `max(0, ·)` | **不把做市利润记成负成本**; 交易所手续费再叠在这个下限之上 (费是真实流出) | 保守 floor |

111/140 币在 $4M/h 校准底之下 → 走 0.5 信用的保守外推。

## 3. 两种成交率口径 (都出, 回答不同问题)

| 口径 | 定义 | 何时适用 |
|---|---|---|
| **`topup` (头条)** | pilot 规格: 被动挂 k=300-900s, **残余用 taker 扫平**。持仓永远在目标上 ⇒ **alpha 不变**, 成本 = 上式混合。**这就是 makerfill 系列实际模拟的东西。** | 你打算按 pilot 规格执行 |
| `partial` | 不补单: `w_t = w_{t-1} + φ(w*_t − w_{t-1})`。只做成 φ, **书滞后于信号**。换手随 φ 下降, 但 alpha 也下降。P&L 与成本按当期实际 L1 gross 归一 → 仍是 "return on deployed gross"。 | 你不补单 / 想看信号衰减的代价 |

**注: 团队给的"alpha 与成本同比例缩放"我没有采用** —— 那个近似会漏掉最重要的一项 (**滞后持仓的 alpha 衰减**)。`partial` 是对它的精确模拟, 结论显著不同 (见 §5)。

## 5. 曲面的三个结构性读数

**① 净负区 = 空集。** 240 格 (2 口径 × 3 taker × 2 逆选择 × 5 maker × 4 fill) **没有一格净负**。最差一格 (`partial` / stress / maker 5 / taker 5 / fill 0.4) 仍是 **+57.9%/yr, Sharpe 5.13**; 把全部 240 格 × 5 个年份摊开看, **最差的单格单年是 +34.0%/yr, Sharpe 3.14**。曲面上最高有效成本 7.87 bps, 距离 11.8 bps 的盈亏平衡门还有距离。**⇒ 在这本书上, 费率与成交率是"折损多少"的问题, 不是"能不能做"的问题。**

**② maker 费超过 ~3.5 bps 时, 被动执行反而变差 (曲面翻转)。** 看 maker=5.0 那一行: 成交率**越高收益越低**。机理: maker 一侧付 `费 + 逆选择(2.0) − 价差捕获(~0.5)`, taker 一侧付 `费 + 半价差(~0.5)`。当 maker 费 ≈ taker 费时, 挂单方多吃一份逆选择却少赚一份价差 ⇒ **不如直接吃单**。**⇒ 只有当 maker 费比 taker 费低 ≥1.5 bps 时, 做被动执行才有意义 (VIP 0: 1.8 vs 4.5, 差 2.7 bps, 有意义 ✅)。**

**③ ★ 补单 (residual taker) 值 ≈ +27 pp/yr (中枢; 悲观下界 +12) —— 这是本文最可操作的结论。** 同在 fill=0.51 / maker 1.8 / taker 4.5:
- `topup` (补单): **115%/yr, Sharpe 9.8** (表内值, 见下方更正)
- `partial` (不补单): **83%/yr, Sharpe 7.4** (gross 利用率仅 0.89, 换手 763 vs 1457)
**⇒ 用 taker 补掉没成交的那一半, 多付的手续费远小于持仓滞后损失的 alpha。4h 信号衰减很快, 别让持仓落后。**

> **★ 更正 (0C 2026-07-25, `topup_delay_check.json`): 表内 +32 pp 的差值是高估的, 真值中枢 ≈ +27 pp。** 本文的 `topup` 口径把补单**按锚点价成交**计价 (`w = target` 对 `Y4[anchor]` 计分), 而真实补单在 **+900s** 成交。**延迟在这里不是对称噪声而是系统性逆向 —— 我们买的是预测会涨的币, 等待 = alpha 漏进执行。** 实测本书 4h alpha 累积**接近线性** (第 1 小时 `f1 = 0.29` vs 线性 0.25), 故中枢修正 **−5 pp**; 若 900s 内极端前载则最多 −20 pp (下界 +12)。**`partial` 一侧同样按锚点价计价, 但该偏差在两个口径间大部分对消, 故只对补单腿计费。** **方向结论不变: 补单仍是强制规格。** 幅度由 pilot 用 `mid_at_anchor` 直接实测 (schema v2)。

## 6. 诚实 caveats (量化, 会影响真金决策)

1. **★ 链上 DEX 那一行 (maker 0-1 bps) 不能直接当结论用。** 整个成本律 (半价差插值、tick 逆选择 markout、fill 曲线) 是在 **Binance 永续微观结构上校准的**, 不外推到链上订单簿: 链上的价差/深度/延迟/撮合机制完全不同, 还有 **gas、MEV/抢跑、预言机与清算机制、跨场所基差** 等本文一律未建模的成本。更根本的是 **110 币的宇宙在任何链上场所都不完整存在** —— 币种缺失会直接砍掉 breadth (书的收益来自 ~100 币的横截面)。**⇒ 那一行只应读作"如果 maker 费降到 0-1 bps 且其余条件不变, 上限在哪", 不是链上可行性判词。链上要单独立项校准。**
2. **逆选择只在 BTC 上做过 tick 实测** (deepdive 残余不确定 #1)。alt 腿大概率更差, 我把 BTC 的 markout 统一套用 ⇒ **对 alt 腿可能低估成本**。压力档 (4d) 部分覆盖了这个风险。
3. **成交率是外生输入, 不是本文测的。** φ={0.4, 0.51, 0.7, 1.0} 是查表轴。**但对个人账户规模有一个强先验: 单量/小时名义比 f 极小 (f ≪ 0.5%), 而 tick 实测的 fill 曲线在小 f 端最高 ⇒ 真实 φ 应落在 0.7-1.0, k=900 工作窗下尤其如此。个人账户读右边两列, 不是左边两列。** 这与机构规模的 0.4-0.51 是不同 regime —— **规模小在这里是优势。**
4. **市场冲击/排队/容量未建模** —— 在个人账户规模 (≲$2M gross, 软容量 $40-80M) 下确实可忽略, 这是本文相对 engine README 唯一放宽的项; **一旦规模上到千万美元级, 这三项重新变成承重项, 本表失效。**
5. **funding 现金流已按 `funding_pnl_backfill.md` 的基准口径 (prev-position, +5.17%/yr) 叠加**, 该文的对齐区间 [+5.17%, +6.49%] 里我取下界。
6. **仍是回测。** live shadow 只有 17 天 (7 月 paper +3.57%)。本表是"如果历史重演且执行如模型"的曲面, 不是实盘业绩。

## 7. ★ 判词: 对个人实盘决策而言, 真正的约束不是费率

费率把结构口径从 **153%/12.9 (零 maker 费) 折到 120%/10.2 (VIP0+BNB, fill 0.7)** —— **折损约 22%, 且余量厚 (盈亏平衡门 11.8 bps vs 实际 ~3.9 bps)。费率与成交率通过了。**

**⇒ 因此 GO/NO-GO 的重心应该移到本文没测、也测不了的地方:**

| 待验 | 为什么承重 | 谁来答 |
|---|---|---|
| VIP 0 单账户能否真的持有 ~100 个 symbol 的双边仓位 (逐 symbol 持仓限额、保证金模式、杠杆档) | 限额若绑死, breadth 塌 ⇒ 书的收益来源直接受损 | 场所调研 (venue-research) / 用户账户实测 |
| 24/7 全自动执行 (6 次/日 × ~100 symbol × 被动挂单+补单), API 限频与故障恢复 | 手工不可能; 断单 = 持仓漂移 = §5③ 的 −32 pp | 工程 |
| 新加坡个人账户的准入/合规/税 | 前置条件 | 用户 |
| 结构口径 → 实盘的最后一跳 (频率×breadth×参与模型 caveat) | 这是唯一还没被任何数字关掉的缺口 | **只能靠小额 pilot 实测** |

**建议下一步: 不要再算了, 开最小额 pilot (核心 mega+mid 书), 目标是实测三个数替换先验 —— 实测成交率 φ、实测逆选择 markout (尤其 alt 腿)、实测有效成本 bps。** 拿到这三个数, 直接回到本表查格子, 就是预期净值; 若实测有效成本 ≤ 4 bps 且 φ ≥ 0.7, 本表 4a 的 **120%/10.2** 那一格就是可信的结构预期。**止损线沿用 makerfill_deepdive: 有效成本持续 >4 bps / φ ≪ 0.5 / 崩盘日 markout 尾差于 −25 bps。**
