# PREREG — `-5022` 拒绝单以【新鲜触价】重挂一次 maker, 而非直接落 taker 补单

## 0. 现状与机制(全部由实盘成交记录测出, 非推断)

`binance_executor.py:482` 读 bookTicker 后**只保留 mid, 丢弃 bid/ask**; 报价 = `floor(mid)`(买)/`ceil(mid)`(卖)。
mid 报价在任何 ≥1 tick 的价差下都是被动的 ⇒ **`-5022`(post-only 会穿价)只可能来自【陈旧】**: bookTicker 是全宇宙一次读取, 随后 ~110 笔订单顺序提交, 最后几笔用的 mid 已旧十几秒。
实测佐证: 买 262 / 卖 220 **基本平衡** ⇒ **不是**当年那个侧盲取整缺陷(那次是 16:1 卖偏)。

**5 天实盘成交的执行 edge(相对 `mid_at_anchor`, 正 = 对我们有利, 名义加权):**
```
maker 成交            42,321 USDT   +1.96 bps   (中位 +1.48, 连 p10 都是 +0.15)
topup_taker/from_reject 13,343 USDT   −1.53 bps   (中位 +3.12 —— 几乎免费)
topup_taker/from_partial 3,637 USDT  −40.04 bps   (中位 −28.59)
topup_taker/未标源       2,290 USDT  −28.21 bps
```
**⇒ 两族补单的经济性差 26 倍, 混在一起看会得出错误结论**(整体 −11.97 是两族混出来的, 不可用)。
**from_reject 便宜的原因是它【不含逆向选择】**: 订单在提交时就被拒, 与"市场是否跑开"无关;
**from_partial 贵的原因正是逆向选择**: 挂单没成交, 恰恰因为价格跑开了, 然后我们穿价去追。

## 1. 改什么(唯一一处)

主提交循环结束后, 若 `benign_rejected` 非空:
1. **重取一次 bookTicker**(公开、无鉴权、全宇宙一请求、weight 5)
2. 对被拒名字按**新鲜触价**重新定价, **仍为 post-only(GTX)**, 重挂一次
3. 仍失败 ⇒ **落回现有 taker 补单路径, 行为与今天逐字相同**

**风险边界(为什么这是低风险)**: post-only 订单**只能挂上或被拒, 永远不会吃单** ⇒ 本改动不可能制造计划外的 taker 成交。重试恰好一次, 由 `attempt_idx` 记录。

## 2. ★ 明确【不做】的两件, 及其数据理由

- **不把报价挂得更被动。** 直觉上"退一档就不会穿价", 但那会把成交量从 `from_reject`(−1.53)推向
  `from_partial`(−40.04) —— **更被动 = 更多不成交 = 更多逆向选择。方向是反的。**
- **不碰 `from_partial` 的补单政策。** 它是更大的杠杆(约 2.5 bps 混合成本), 但**它正在 chase 随机实验中**。
  用观测数据抢一个随机化实验的结论, 是本项目反复登记过的错误。**等实验说话。**

## 3. 判据(预写死)

**主判 —— 拒绝率**: 部署后 20 个锚点内, `venue_reject` **最终**未成交的名义占比, 相对部署前 5 天基线
(17,115 / 85,577 = **20.0%**)必须**下降**, 且下降的那部分**以 maker 成交**(不是变成 partial)。

| 条件 | 结论 |
|---|---|
| 最终 reject 名义占比 < 10% **且** maker 成交额占比上升 | **保留** |
| reject 占比下降但 **`from_partial` 名义上升 > 30%** | **回滚** —— 我们只是把便宜的一族换成了贵的一族 |
| 出现任何非 post-only 的计划外 taker 成交 | **立即回滚** —— 风险边界被破 |
| 20 锚内 `benign_rejected` 样本 < 50 | **判据不可执行**, 延长观察, 不得提前宣布成功 |

**对侧参照**: 重挂**失败**的那些(二次 −5022), 其后续 taker 补单的 edge 应仍 ≈ `from_reject` 基线
(−1.53)。若它显著更差, 说明二次拒绝是在选择"正在快速移动"的名字, **那是一个新的、我没有预期的现象**, 须单独登记。

## 4. 本文不建立什么

- 不建立 chase 实验的任何结论。
- 不建立 maker 的 +1.96 是"技能" —— 它有 4h 锚点后视的成分, 本文只用它做**同口径对比**, 不当作 alpha。
- 不建立成本口径变更。费用侧的收益(约 **0.47 bps** = 15.6% 成交额 × 3 bps 费差)是**算出来的, 不是测出来的**,
  部署后须以实测费率复核。
