## 1. 数学核心

### 1.1 目标函数与解 (离散时间, 我自己推的, 可逐步复核)

单资产标量情形足以给出全部结构; 多资产是同一式子的矩阵版。

$$\max_{\{x_t\}}\ \sum_t \rho^t\Big[\,x_t\mu_t \;-\;\tfrac{\gamma}{2}x_t^2\sigma^2\;-\;\tfrac{\lambda}{2}(x_t-x_{t-1})^2\,\Big],\qquad \mu_t=\beta f_t,\quad f_{t+1}=\varphi f_t+\varepsilon$$

`ρ` 每锚贴现, `γ` 风险厌恶, `σ²` 收益方差, `λ` **二次**交易成本系数, `φ` 信号每锚持久度。

猜线性策略并匹配二次值函数 `V=-\tfrac{A}{2}x^2+Bxf-\tfrac{C}{2}f^2+D`, 一阶条件给

$$x_t=\frac{\lambda}{\gamma\sigma^2+\lambda+\rho A}x_{t-1}+\frac{\beta+\rho B\varphi}{\gamma\sigma^2+\lambda+\rho A}f_t$$

包络条件 `V_{x_{t-1}}=\lambda(x_t-x_{t-1})` 给 `A=\lambda a`, `B=\lambda a b`, 代回得 **a 的二次方程**

$$\boxed{\ \rho\lambda a^{2}+\big(\gamma\sigma^{2}+\lambda(1-\rho)\big)a-\gamma\sigma^{2}=0\ }\quad\Rightarrow\quad a=\frac{-\big(\gamma\sigma^{2}+\lambda(1-\rho)\big)+\sqrt{\big(\gamma\sigma^{2}+\lambda(1-\rho)\big)^{2}+4\rho\lambda\gamma\sigma^{2}}}{2\rho\lambda}$$

以及 aim 相对无摩擦 Markowitz 组合 `M=\beta f/(\gamma\sigma^2)` 的倍数

$$\boxed{\ \frac{\text{aim}}{M}=\frac{\gamma\sigma^{2}}{a\big(\gamma\sigma^{2}+\lambda+\rho\lambda a(1-\varphi)\big)}\ }$$

**策略形式: `x_t = (1-a)·x_{t-1} + a·aim_t`。** 多因子时按线性叠加, **每条腿用自己的 φ_i 算自己的 aim 倍数**:

$$\text{aim}_t=\sum_i \underbrace{\frac{\gamma\sigma^{2}}{a\big(\gamma\sigma^{2}+\lambda+\rho\lambda a(1-\varphi_i)\big)}}_{\text{持久度权重 }z_i}\cdot M_t^{(i)}$$

**★ 这就是 GP 的全部内容: `z_i` 随 `φ_i` 单调递增 ⇒ 慢腿在 aim 里被放大, 快腿被压缩。** 直觉: 你要为建仓付成本, 只有能持有足够久的信号才还得起。

**关于 GP 原文:** 上式我从头推导, 未引用记忆中的公式。矩阵版(`Λ=λΣ` 使问题对角化)与 Gârleanu–Pedersen (2013, JF, *Dynamic Trading with Predictable Returns and Transaction Costs*) 的结构一致, **但我没有原文可核, 因此规格里的矩阵推广标为"待与原文对照"**, 落地前须有人核一次。标量版无此依赖。

### 1.3 退化检验 (你点名要的两个极限)

**(a) λ→0 ⇒ a→1 ⇒ 当前系统.** 由二次式: λ→0 时 `a = [-γσ² + sqrt(γ²σ⁴+4ρλγσ²)]/(2ρλ) → (2ρλ)/(2ρλ) = 1`。a=1 时策略退化为 `x_t = aim_t = M_t` = **每锚全额交易到 Markowitz 目标 = 当前 rank+cap 直接建书**。✅ **当前管线是本框架的 λ=0 特例, 这是采纳它最强的论据。**

**(b) λ→∞ ⇒ a→0 ⇒ 冻结账本**(不交易)。中间任意 a∈(0,1) 连续。

**(c) ★ 但"a=0.51 复现影子的 51%-fill"这个等价关系是错的, 必须写死, 否则校准检验会假通过.**
影子 `challenger.py` 里 `FILL=0.51` 出现在
```
row[f"{name}_net"] = FILL * (gross - turn * cost * 1e-4)
```
—— 它是**对整条净 P&L 的统一折价**, 不是对**持仓**的部分调整。两者只在 gross 项上等价(gross 对持仓线性), **在换手项上不等价**: 影子按**全额目标变动**收成本再整体乘 0.51; 真正的 a=0.51 策略只走 51% 的距离、只为这 51% 付钱。
⇒ **影子模型相对一个真实的 a=0.51 策略是系统性高估成本的**(方向已知)。
⇒ **校准检验的正确写法(替换你原来的表述):**
- **CAL-1:** 令 a=1、成本取影子的 (1.9bps, FILL=1.0), 新实现必须**逐锚点复现**当前管线的持仓与换手(容差: 每锚 L1 权重差 < 1e-6)。
- **CAL-2:** 令 a=1、成本与 FILL 取影子设置(1.9/2.9bps, FILL=0.51), 新实现必须复现 `compare.json` 的 `champion_net` / `challenger_net` 逐锚序列(容差 1e-9)。
- **CAL-3(不是复现, 是记录差值):** 令 a=0.51 跑同一窗口, 报告它与 CAL-2 的净收益差, 并**明写这个差不是误差而是两个不同模型**。若有人把 CAL-3 的差当 bug 修, 那就是把一个真实的建模改进抹掉。

## 2. 成本模型

### 2.1 结构: 三项, 处理方式各不相同

$$c_{\text{total}} = \underbrace{c_{\text{fee}}}_{\text{每笔必付, 已知常数}} + \underbrace{c_{\text{exec}}}_{\text{每笔必付, 与规模有关}} + \underbrace{c_{\text{adv}}(\tau)}_{\text{随补单延迟 }\tau\text{ 增长}}$$

| 项 | maker 腿 | taker 腿 | 在优化器里 |
|---|---|---|---|
| `c_fee` | 2.000 bps (实测, VIP0) | 5.000 bps (实测, VIP0) | 常数, 进 λ 的线性部分 |
| `c_exec` | 首锚净 **+0.55 bps** 含费 ⇒ **点差捕获 ≈ −1.45 bps**, 即 maker 腿净赚回大部分手续费 | 含在 +29.44 内, 未与 `c_adv` 分离 | 二次项 λ 的主体 |
| **`c_adv(τ)`** | markout 均值 −0.61 bps (仅 62/159 有值) | **~24 bps(你的拆分), 但 21 笔 taker 的 markout 字段 0/21 有值 ⇒ 现在测不出来** | **不是 λ 的一部分 —— 它是决策变量 τ 的函数, 必须单独进目标** |

**★ 为什么两项在优化器里必须分开(这是本节的核心):** `c_fee + c_exec` 是"你交易就付", 进二次成本 `λ/2·(Δx)²`, 只影响 **a**。而 `c_adv(τ)` 是"你等得越久, 你要买的东西越贵", 它**不惩罚交易, 惩罚拖延** —— 数学上它进的是**信号的有效衰减率**而不是成本项: 延迟 τ 后成交, 实际拿到的 alpha 是 `μ·φ^{τ/4h}` 而付的价是 `p·(1+c_adv(τ))`。**把它塞进 λ 会得出"成本高所以慢慢来"的完全相反的结论。**

### 2.2 需要多少样本才能标定 (你要的 N 及推导)

|---|---|---|
| ≤1.00 bps | 2 笔 → **<1 锚(已达成)** | 325 笔 → **≈16 锚 ≈ 2.6 天** |
| ≤0.50 bps | 6 笔 → **<1 锚(已达成)** | 1,300 笔 → **≈62 锚 ≈ 10.3 天** |
| ≤0.25 bps | 24 笔 → **<1 锚(已达成)** | 5,201 笔 → **≈248 锚 ≈ 41 天** |

(按首锚 159 maker / 21 taker 成交每锚换算。)

**⇒ 结论的不对称性是本节最有用的一句: maker 成本在**一个锚点后就已经标定到 ±0.1 bps**; taker 成本要 ~16 锚才到 ±1 bps。而 taker 正是那个占 94% 成本的腿。**

**三条必须写明的限制:**
1. **上表是下界。** 同一锚的 21 笔 taker 共享一个"该锚的市场漂移"公共分量, 逐笔不独立 ⇒ 有效样本 < 名义样本, 真实需求**更大**。公共分量只有 ≥2 锚才能拆, 现在 n=1, **未量化**。
2. **只覆盖 calm。** 首锚 `regime_at_anchor=calm`; stress 下的成本没有任何观测, 而 `c_adv` 恰恰在 stress 下最大。
3. **★ 最关键: 现有管线不识别我们真正要的那个量.** 优化器要的是 `dc_adv/dτ`(斜率), 但当前是**固定 15 分钟阶梯** ⇒ τ 是常数 ⇒ **斜率在数学上不可识别, 再多锚点也标不出来**。
 ⇒ **必须做设计实验: 在影子轨/试点里对阶梯时长做随机化**(例如每锚从 {5, 10, 15, 25} 分钟中随机取一个, 或按名字分层随机), 否则 §1 的整个 τ 优化没有输入。**这条是进影子轨的前置条件, 不是优化项。**
4. M2 markout 落地前, taker 的 `c_exec` / `c_adv` 拆分**只能来自阶梯期内的 mid 轨迹**, 而 taker 成交的 `mid_at_fill_plus_60s` 当前 **0/21 有值** ⇒ 该产出目前是空的, 需先修(已属 0B 范围, 本规格只登记依赖)。

## 3. 组合层 —— 天花板算给你, 结论是**收益有限**

### 3.1 方法

信号组合的单位风险 IC: `IC(w) = w'r / sqrt(w'Ωw)`, `r` = 逐腿 IC 向量, `Ω` = 腿间信号相关矩阵(§0.2)。无约束最优 `w* ∝ Ω⁻¹r`, 最优值 `IC* = sqrt(r'Ω⁻¹r)`(Grinold 的信号合成形式)。

### 3.2 结果 (部署 fundfix 口径, n=174 锚)

| 方案 | 组合 IC | 相对当前 | 若当前净 Sharpe = 4.61 |
|---|---|---|---|
| **当前固定权重** (.50/.17/.17/.16) | **0.1090** | 1.000× | 4.61 |
| Σ⁻¹ 无约束最优 | 0.1188 | **1.090×** | 5.02 (**Δ +0.41**) |
| Σ⁻¹ 最优, 但**约束 w≥0** | 0.1174 | 1.077× | 4.97 (Δ +0.36) |
| 直接去掉 size (.60/.20/.20/0) | 0.1165 | 1.069× | 4.93 (Δ +0.32) |
| **king 单腿** | **0.1124** | **1.031×** | 4.75 (Δ +0.14) |

无约束最优权重: **king 0.612 · s2 0.193 · funding 0.077 · size −0.118**。

### 3.3 判词 (照你的要求, 不虚报)

1. **天花板 = +9.0% IC ⇒ 在净 Sharpe 4.61 的基线上是 +0.41。低于你设的 0.5 线。⇒ 组合层收益有限, 重点在交易层。**
2. **而且这 +9.0% 里的绝大部分来自把 size 腿的符号翻过来**(最优权重 −0.118)。约束 w≥0 后天花板降到 +7.7%, 且最优解直接把 size 置零。**符号翻转是"这个因子还成不成立"的问题, 不是"权重怎么配"的问题 —— 把它算作组合层的收益是虚报。剔除符号自由度后, 组合层真正值的是 +7.7% 里减去"删掉一条已失效的腿"那部分。**
3. **★ 一个更尴尬也更重要的读数: king 单腿(0.1124)在这个窗口里就已经打败当前四腿混合(0.1090)。** 当前混合相对其最好的单腿是**负贡献**的。这不构成"改成 king 单腿"的建议(单腿的风险集中度、regime 稳健性、容量都没评估), 但它把组合层的定位讲清楚了: **当前的问题不是"怎么更聪明地混", 而是"混进来的东西里有一条在拖后腿"。**
4. **size 腿在本窗口 IC = −0.0315 (t −2.83), 且在 0–44h 每一个 horizon 上都是负的, 剖面平坦。** 这不是噪声形状 —— 一个持续、稳定、跨期一致的反号。**处置建议(需你裁定, 不由本规格决定): 在 aim-portfolio 进影子轨之前, size 腿必须单独出一个 GO/NO-GO, 因为 §1 的 GP 机制会放大它 —— 见 §6-E5。**

**收缩估计(仍然要做, 但目的变了):** 既然天花板本身不高, 收缩的作用不是抢那 9%, 而是**防止组合层因为估计噪声而变成负贡献**。逐锚腿间相关的 sd 是 0.11–0.26(§0.2), 逐腿 IC 的 se 是 0.008–0.011。建议 `Ω_shrunk = δI + (1-δ)Ω̂`, `δ` 由 174 锚的 bootstrap 定; **权重变动幅度设硬上限(例如相对上一次 ≤0.05/腿/月)**, 否则组合层自己会制造换手, 而换手正是我们要削减的东西。

## 4. sizing 层

### 4.1 双地板是实测的, 且第二个地板更狠

首锚实测(`state/live/exchange_info_cache.json` + 首锚订单行): 有效地板 = **max(min_notional, step × price)**。

- `min_notional` 分布: **5.0 (647 币) / 20.0 (5 币) / 50.0 (BTC)**。
- **`step × price` 才是 BTC 的真实地板**: BTCUSDT `step = 0.001` ⇒ 单张 ≈ **$100+**, 是其 `min_notional=50` 的**两倍以上**。
- **实证: 首锚 BTC 被挡, `|delta| = $53.65 > min_notional 50` —— 它不是被名义地板挡的, 是 `round_qty(53.65/price)=0` 被 lot 步长挡的**(`binance_executor.py::RebalanceExecutor.plan` 里 `qty==0` 分支同样打 `skipped_min_notional` 标签)。**⇒ 标签把两个不同的地板写成同一个原因, 从行里分不出是哪个地板咬的。这是 sizing 层的第一个必须修的可观测性缺口。**

首锚 11 个被挡名字(按 |delta| 降序): BTC 53.65 · LTC 18.03 · BCH 5.96 · TNSR 3.65 · AVAX 3.30 · MEME 3.05 · CELO 2.31 · AAVE 2.26 · LINK 0.98 · DYDX 0.73 · STX 0.42。目标权重: max 0.02685 · 中位 0.00774 ⇒ 在 gross 4,194 下 **max $112.6 / 中位 $32.5**。

### 4.2 进优化器的方式

地板是**非凸**约束(`x_i = 0` 或 `|x_i| ≥ F_i`)。规格给出的处理, 按代价从低到高:

1. **(推荐, 与 GP 相容) 把地板变成"死区 + 再分配"**: 优化在连续松弛上求解, 事后对 `|x_i| < F_i` 的名字置零, 并把释放的 gross **按 aim 的相对权重**重新分配给同侧未被挡的名字, 再做一次市场中性 demean。**它必须写进 aim 的定义而不是事后打补丁**, 否则 `x_{t-1}` 携带的状态与 aim 不在同一个空间, §6-E3 的状态携带会漂。
2. **(次选) 对被挡名字加一个惩罚项** `κ·Σ_i max(0, F_i − |x_i|)`, 把非凸约束软化成凸的。κ 由被挡名字数校准。
3. **(不推荐) 混合整数** —— 每锚 110 个二元变量, 4h 一次, 收益不抵工程与故障面。

**地板 × λ 的交互见 §6-E4, 那是本节最危险的一条。**

### 4.3 rank+cap 在这个框架里的位置

**rank+cap 是先验收缩, 不是风险模型。** `rank_centered` 把幅度信息整个丢掉换取稳健性; `pos_cap_pct=99` 再裁掉两侧各约 1 个名字(110 个名字上 99 分位必然咬)。在 aim-portfolio 里它的正确位置是 **`M_t` 的构造环节**(先验), 而 `Σ`(风险)与 `λ`(成本)是**另外两个独立的层** —— 现在这三件事被压在一条 `rank → cap → demean → l1` 的链里, 分不开。

**幅度信息何时值得引入 —— 用既有证据定, 不新造理由:**
- 既有证伪: **isotonic 校准变体净 −1.3 Sharpe**(`engine_v1_finalized` 记录), 即在当时的 AUM 与校准稳定性下, 引入幅度是**净负**的。
- ⇒ **门槛(建议, 需你确认): 只有当 (a) 有 ≥3 个月的 out-of-sample 校准稳定性证据(月度 isotonic 映射的逐月 rank 相关 ≥0.8), 且 (b) AUM 使得中位单名敞口 ≥ 5×有效地板(当前中位 $32.5 vs 地板 $5 = 6.5×, 但 BTC 是 $112.6 vs ~$100 = 1.1×)时, 才重新评估幅度信息。**
- **当前 AUM 下明确不引入**: gross 4,194 距 `min_gross_usdt=4000` 只有 269.58 USDT(权益 −6.3% 即停机), 在这个位置上讨论幅度加权是在错误的问题上花预算。

## 6. Edge case 清单

**E1 — 名字进出宇宙时 aim 的处理.**
`x_{t-1}` 里有一个本月被踢出成员集的名字: 它的 aim 是 0, 但部分调整会让它**以 (1-a) 的速率慢慢退出**, 即在一个已不被信号覆盖的名字上留仓 `ln(0.5)/ln(1-a)` 个锚点。
**裁定要求: 宇宙退出必须走 a=1 的快速通道(立即清零), 不受 λ 保护。** 理由: 成本模型只对"我们想持有但要付钱建仓"的名字有效; 对一个不再被评分的名字, 继续持有的收益项是 0 而不是 μ, GP 的权衡不成立。新进名字反向: 用正常 a 建仓即可, 无特殊处理。

**E2 — 停机 / 封禁期间 λ 的累积效应.**
停机 k 个锚后恢复, `x_{t-1}` 与 `aim_t` 的距离已经很大, 单锚 `a·(aim − x)` 会产生一个**远大于常态的换手尖峰** —— 恰好落在系统刚从故障恢复、限流预算最紧张的时刻(见 `cancel_burst_measurability` 附录: 四次 -1003 全落在撤单 burst)。
**要求: 恢复后的第一锚必须有独立的换手上限**(例如 ≤ 常态换手中位数 × 1.5), 多出的距离在后续锚点摊完。**且该上限必须与 §4-5e 的守卫矩阵共用一个常数, 不得各写一份。**

**E3 — 部分成交后的状态携带.**
`x_{t-1}` 必须是**实际持仓**(`position_readback`), 不是**上一次的目标**。当前 `loop_state.json::positions` 是实际持仓 ✅, 但 `challenger.py` 影子里的 `prev` 是**上一次的目标** ❌。
**⇒ 影子轨若照搬 `challenger.py` 的写法, 会模拟一个"每次都完全成交"的世界, 而 partial fill 正是本升级要处理的东西。第四轨必须用实际持仓做状态, 这使它与前三轨的实现不同 —— 这个差异要在轨的 README 里写死, 否则会被当成 bug 修回去。**

**E4 — ★ 地板量化 × λ 的交互: 名字饿死 (最危险的一条).**
小 a × 小目标权重 ⇒ 每锚的 `a·(aim_i − x_i)` 永远小于该名字的有效地板 `F_i` ⇒ 该名字**永远交易不到, 永远停在 0**, 而优化器每锚都认为自己"正在向 aim 靠近"。
**实测这不是理论风险**: 首锚中位单名 $32.5, 地板 $5 ⇒ a < 0.15 时中位名字的单锚增量就跌破地板; **BTC 更糟 —— 目标 $112.6 vs 有效地板 ~$100 ⇒ 任何 a < 0.89 都让 BTC 永远建不了仓。**
**要求: (i) 必须有"饥饿检测"—— 连续 k 锚 `|aim_i − x_i| > F_i` 但从未下单的名字要报警; (ii) 对这些名字触发一次性的 a=1 脉冲(攒够一笔一次做完), 这是标准解法, 但它会制造集中的换手, 因此脉冲必须排队、限速, 并计入 E2 的同一个上限。**

**E5 — regime 切换时衰减率错配.**
φ_i 是在 174 个 **calm** 锚上估的(`n_stress_anchors = 0` —— 影子窗口内一个压力锚都没出现过)。stress 下 king 的快分量可能衰减更快而 funding 更慢, 两个方向相反。
**要求: (i) φ 必须带 regime 下标, 且在 stress 样本 n≥[待填] 之前, stress 下**冻结使用 calm 的 φ 并显式登记该状态**(不得外推); (ii) 由于 §1 的 `z_i` 对 φ 单调, φ 估错会直接改变腿间相对配置 —— 因此 φ 的每一次更新都必须像换权重一样过一道门, 不能作为"参数刷新"静默生效。**
**★ E5 的第二半已于 2026-08-01 15:5x UTC 重写 —— 旧版前提被去混淆检验推翻, 见 §6-E5b。**

**E5b — ★ 持久度加权 × 零 alpha 腿 (旧 E5 后半的替代, 2026-08-01 重写).**

**旧版说的是:** size 是 φ≈1 的永久腿且 IC 为负(−0.0315)⇒ GP 会放大一条反号的腿 ⇒ 阻塞第四轨。
**旧版的前提已被 `RESULT_leg_marginal_audit_2026-08-01.md` 推翻:** 那个负 IC 读数来自单月影子窗口, 而"边际贡献为负"来自一把混淆的尺子。去混淆后 size 的边际贡献是 **+0.478 (t_eff +4.20)**, 全历史单腿 IC **+0.00913**(2023-11 后 +0.00111 ≈ 0)。
**⇒ size 的真实身份是「标量 alpha ≈ 0, 但因与其它腿负相关而分散有益」(size×funding −0.278, ×s2 −0.089, ×king −0.066)。旧的阻塞理由消失。**

**但它换来了一个更隐蔽的问题, 而且这个问题是 GP 框架特有的:**

**(a) 分散价值根本不是信号层的东西, 它是协方差层的东西。**
§1 的多因子形式里, 每条腿进 aim 的是它的 **Markowitz 分量** `M^(i) = (γΣ)⁻¹B_i f_i`, 再乘持久度权重 `z_i`。**分散价值住在 `Σ⁻¹` 里, 不住在 `B_i` 里。** 一条 alpha≈0 的腿, 其 `B_i f_i ≈ 0` ⇒ `z_i × 0 = 0`, **无论 `z_i` 多大, GP 都不会放大它** —— 前提是**真的有一个 Σ**。
**而我们当前的书没有 Σ。** `compose_book` 是 `Σ w_k·L1(leg_k) → cap → demean → l1`, 一个**没有风险模型的线性混合**。我们实测到的 +0.478 分散收益, 是这个等权混合**隐式**做了 Σ⁻¹ 该做的事。
**⇒ 当前构造把信号层与风险层压在了一起。这是 E5b 的根。**

**(b) 于是在无 Σ 的实现里, GP 的持久度加权会系统性高估 size 这类腿 —— 而且是静悄悄的.**
`z_i` 只有在乘一个**真实的预期收益分量**时才合法。若它乘的是一个原始信号混合, 那么**持久度本身就被当成了价值**。一条 φ≈1、alpha≈0 的腿会拿到最大的 `z_i`, 贡献接近零的收益, 却挤占 king 快分量的份额。
**旧风险是"放大一条反号腿"—— 响亮, 符号就能抓到。新风险是"放大一条零 alpha 的慢腿"—— 它自己不亏钱, 只是稀释, 而且表现得非常*稳定*, 恰恰是最难被察觉的形态。**

**(c) ★★ 而且成本感知的目标函数给了它第二个、独立的偏爱理由 —— 这条最危险.**
实测: **size 腿使换手降低 3.1%**。GP 的目标函数里有 `−(λ/2)(Δx)²` 这一项。**一条零 alpha、高持久、还降换手的腿, 对一个成本感知优化器来说是免费午餐: 它降低成本项而不降低收益项, 因此提高目标函数值。**
**⇒ 这不是 bug, 是规格失败: 优化器会忠实地优化我们写下的目标, 而我们写下的目标奖励"别交易", 而 size 是"别交易"的最便宜实现方式。** 任何 alpha≈0 且换手低的东西都会被这个目标吸进来。

**(d) 由此产生的设计要求 (取代旧的阻塞条款):**
1. **`z_i` 只允许乘一个已证明为正的预期收益分量, 绝不允许乘原始信号混合。** ⇒ 要么真的实现 Σ, 要么**不用持久度加权**(退化成单一 a, 见 §1.3)。
2. **进入 aim 的准入规则: 一条腿必须有**去混淆后为正的标量预期收益贡献**。凡价值仅来自分散的, 归 `Σ`, 不归 aim。**(size 现在正是这一类。)
3. **诊断量(必须逐锚记录): 每条腿的 aim 份额 ÷ 该腿的已实现 gross P&L 份额。** 若某腿的 aim 份额持续远高于其 P&L 份额, 它就是被持久度而不是被 alpha 抬着的。
4. **★ 安慰剂腿在这里从审计工具升级为对优化器的活体守卫。** 打乱信号的安慰剂腿 = alpha 恰为零, 且(若打乱保持自相关)持久度高、换手低 —— **它正是 (b)+(c) 这个失败模式会吸进来的那个对象。⇒ 预注册要求: 在 aim 构造里放一条持久安慰剂腿, 它必须拿到 ≈0 的 aim 权重; 若它拿到了可观权重, aim 构造当场判为坏。** 这比事后看诊断量强, 因为它是一个会**变红**的测试。

**(e) 阻塞状态更新:**
- **旧阻塞(等 size 定案)解除。** 它的前提已被推翻, 且 size 当前已不在部署书内。
- **代之以一条更窄、更便宜的阻塞: 第四轨在满足 (d)-1 与 (d)-4 之前, 不得启用持久度加权。** 这是**设计与测试**前置条件, 不是数据前置条件 —— 不需要再等几个月的数据, 写完测试即可解除。
- 若第四轨先以**单一 a、不做持久度加权**的形态上线(§1.3 的中间形态), 则本条完全不阻塞。**建议就这么上**: 先证明部分调整本身有效, 再引入按腿持久度。

**E10 — ★ 第四轨必须在**冻结的权重配置**上跑, 否则重演今天这个混淆, 只是高一层.**
今天的教训: 「摘腿 + 归一」把"腿的贡献"与"king 的权重"混在一起, 三个数看起来干净, 归因整个是错的。
**第四轨测的是*交易机制*(部分调整 vs 全额调整), 它必须与*权重配置*正交。** 若 aim-portfolio 在 A 权重上跑而冠军在 B 权重上跑, 则 ΔIC/Δnet 同时包含机制差与权重差, **而我们已经确认权重差是这本书里最大的单一效应(king .50→.595 值 +0.729, t_eff +5.71)—— 它会淹没机制差。**
**要求: 第四轨与其对照臂必须共用当时部署的权重, 逐字一致; 权重若在轨运行期间变更, 两臂同时变更并在轨的产物里记录变更锚点。** 与 §5(e) 的"证据只取 SHADOW 切片"同级, 是硬要求。
gross = nav × target_leverage 每锚重算, 且有 `leverage_deadzone_frac=0.1` 死区。入金使 gross 跳升 ⇒ 所有 `aim_i` 按比例放大 ⇒ 部分调整会把这个跳变当成"信号变强"而去追。
**要求: aim 与 x 都在**相对权重空间**(unit-gross)里做部分调整, 只在最后一步乘 gross。这样 NAV 跳变只改幅度不改方向, 不产生任何被 λ 惩罚的"调整"。** 出金同理。**这条同时解释了为什么 §4.2 的地板再分配必须在权重空间里做。**

**E7 — ★ 与守卫矩阵的接口: §4-5e 的"意图"是 aim 还是 target?**
**本规格的裁定(明确写死, 请你确认或改): 守卫看到的"意图" = `x_t`(本锚实际下单后的目标持仓), 不是 `aim_t`。**
理由三条: (i) 守卫的职责是防止**我们真的持有**的东西造成损失, aim 是一个我们**不打算这一锚达到**的点; (ii) 若守卫读 aim, 则在 a 很小时它会对一个永远不会实现的敞口报警, 训练操作员忽略告警; (iii) 现有 `position_break` / `weight fidelity`(§4-6 权重相关 0.85)全部按"目标 vs 实际"比对, 若目标改成 aim, **权重保真度会永久性地不达标, 而那不是故障** —— 这正好是"一个门两个意图"的典型形态。
**⇒ 附带要求: aim 必须**另外**记录在锚点产物里(新字段, 不复用 `target_vector_hash`), 因为诊断"为什么没交易"需要它; 但它不进任何门。**

**E8 — 产物必须盖章 + append-only 账本必须折叠 supersede 链.**
(a) 现 `exports/live/positions/*.json` **不记录自己用的权重**(challenger 产物记), 已登记为 S5 缺陷。第四轨的产物必须自带 `{a, λ, φ_i, 成本口径, 代码版本}`, 否则三个月后没人能回答"这一锚是哪套参数产的"。
(b) **★ 本规格自己在 §0.3 初稿上犯过的错, 升级为设计要求:** aim-portfolio 的成本标定**每一次**都要读 `fills.jsonl`, 而该日志是 append-only + supersede 语义。**任何读它的代码必须先按 `trade_id` 折叠、再三方对账(fills 折叠后 ↔ orders ↔ realized_gross), 且不得用首行推断 schema(字段是异构的)。** 详见 §0.3 的读者契约。
 **危害在这个升级里比在报告里大得多**: λ 是从这份账本标定的, 而错误的方向是**选择性重复**(只有被回填过的成交被重复)⇒ λ 会被系统性拉向"已回填子集"的成本水平, 而回填与否本身和 markout 可得性相关 ⇒ **这是一个会把选择偏差直接写进优化器参数的路径。**
(c) 因此 §5(d) 的测试清单里, 关于本条的测试必须是: 构造一份含 supersede 行的 fixture, **先验证未折叠的实现会给出错误的名义**(红), 再验证折叠后三方对账通过(绿)。

**E9(补, 不在你的清单里但同族)— a 与 λ 的时间一致性.**
λ 会随 §2 的成本标定逐周更新 ⇒ a 随之变 ⇒ **同一个 aim 在不同周被以不同速度追逐**。若不加约束, a 的抖动本身就是换手源。
**要求: a 每次更新的相对变动 ≤ 20%, 且更新频率 ≤ 每月一次; 更新须记录触发它的成本样本区间。**
